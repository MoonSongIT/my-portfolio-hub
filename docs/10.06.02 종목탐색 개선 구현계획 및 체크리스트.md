## Sprint 10.6.1 — Discovery Panel + 최근 본 종목 + 시장 필터 탭

### A. Discovery Panel (탐색 홈 화면)

#### 설계 결정

`Research.jsx`에서 `query === ''` 일 때 검색 결과 그리드 대신 Discovery Panel 표시.  
세 섹션: **최근 본 종목** / **인기 검색어** / **시장 요약**.

```
Research.jsx
 ├─ query === '' → Discovery Panel
 │       ├─ RecentlyViewedSection  (localStorage 'recentlyViewedStocks' 읽기)
 │       ├─ PopularTickersSection  (하드코딩 상수)
 │       └─ MarketSummarySection   (useStockPrice × 3)
 └─ query !== '' → 기존 SearchResultCard 그리드
```

**시장 요약 지수 티커**

| 카드 | 티커 | market | 비고 |
|------|------|--------|------|
| KOSPI | `^KS11` | `NYSE` | Naver API는 `^` 지수 미지원 → Yahoo 라우팅 |
| KOSDAQ | `^KQ11` | `NYSE` | 동일 |
| NASDAQ | `^IXIC` | `NASDAQ` | |
| S&P 500 | `^GSPC` | `NYSE` | |

> **구현 확정**: `^` 지수 티커는 market을 `'NYSE'`/`'NASDAQ'`으로 설정해 모두 Yahoo Finance로 라우팅.  
> KOSDAQ 카드 추가 완료(2026-05-14).

  function saveRecentlyViewed(ticker, name, market) {
    const KEY = 'recentlyViewedStocks'
    const prev = JSON.parse(localStorage.getItem(KEY) || '[]')
    const filtered = prev.filter(item => item.ticker !== ticker)
    const next = [{ ticker, name, market, visitedAt: new Date().toISOString() }, ...filtered].slice(0, 10)

  }

### D. 종목 비교 패널

#### 설계 결정

`StockDetail.jsx` 내에 비교 패널. 별도 라우트 불필요.  
수익률 비교: 첫 번째 close 기준 % 변화율 정규화.

```
StockDetail.jsx
 ├─ 헤더: "비교" 버튼 (compareMode 토글)
 └─ compareMode === true → <StockComparePanel> 렌더링 (차트 아래)
      ├─ 비교 종목 검색 (useStockSearch 재사용)
      ├─ 수익률 비교 차트 (Recharts LineChart, % 정규화)
      │   └─ 기간: 1mo / 3mo / 6mo / 1y
      └─ 지표 비교 테이블 (PER/PBR/ROE/시총/52주 고저)
```

**% 정규화 함수**
```js
const normalize = (history) => {
  if (!history?.length) return []
  const base = history[0].close
  return history.map(h => ({
    date: h.date,
    pct: +((h.close - base) / base * 100).toFixed(2)
  }))
}
```

### BUG-1. 한글 쿼리 → Yahoo Finance 400 오류 (2026-05-14 수정)

**증상**: 한글 종목명 입력 시 간헐적 400 오류 (`/v1/finance/search?q=삼성...`)  
**원인**: `searchStocks()` 3순위 Yahoo 보완 호출에 `isKo` 가드 누락 — 로컬 결과가 8개 미만이면 한글 쿼리도 Yahoo로 전송  
**수정**: `if (merged.length >= 8 || isKo) return …` — 한글일 때 Yahoo 원격 호출 스킵

```js
// 수정 전
if (merged.length >= 8) return merged.slice(0, 15)

// 수정 후
if (merged.length >= 8 || isKo) return merged.slice(0, 15)
```

### BUG-3. AI 스크리너 에러 메시지 단일 메시지 문제 (2026-05-15 수정)

**증상**: API 호출 실패 시 원인 무관하게 "API 키 설정을 확인해 주세요" 단일 메시지만 표시  
**원인**: 에러 처리 코드가 HTTP 상태코드를 구분하지 않고 동일 메시지 반환  
**수정**: HTTP 상태코드별 분기 처리

```js
// 수정 후 — 상태코드별 메시지 분기
if (status === 529 || status === 503) {
  return '⚠️ AI 서버가 일시적으로 과부하 상태입니다. 잠시 후 다시 시도해 주세요.'
} else if (status === 401 || status === 403) {
  return '🔑 API 키가 유효하지 않습니다. 설정에서 API 키를 확인해 주세요.'
} else if (status === 429) {
  return '⏱️ 요청 한도를 초과했습니다. 잠시 후 다시 시도해 주세요.'
} else {
  return `HTTP ${status}` 또는 에러 메시지 원문
}
```

### BUG-2. 워런트·비표준 접미사 티커 → Yahoo 차트 404 오류 (2026-05-14 수정)

**증상**: `SKYH.W` 등 비표준 티커가 검색 결과에 포함되어 `SearchResultCard`의 `useStockPrice`가 404 반환  
**원인**: Yahoo Finance는 `.W`(워런트), `.WS`, `.RT`, `.U`, `.R` 접미사 티커의 차트 API를 미지원  
**수정 1**: `fetchQuote()`에 사전 검증 추가 — 비표준 접미사 즉시 throw  
**수정 2**: `searchStocks()` 반환 전 `filterStandard()` 적용 — 검색 결과 자체에서 제거

```js
// fetchQuote — 비표준 접미사 사전 차단
if (/\.(W|WS|RT|U|R)$/i.test(ticker)) throw new Error(`미지원 티커 형식: ${ticker}`)

// searchStocks — 반환 전 필터
function filterStandard(stocks) {
  return stocks.filter(s => !/\.(W|WS|RT|U|R)$/i.test(s.ticker))
}
```
