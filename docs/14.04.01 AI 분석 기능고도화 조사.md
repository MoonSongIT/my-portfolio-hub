# 14.04.01 AI 분석 기능 고도화 조사

## 작성일
2026-06-15

## 사용 모델
이 문서는 Claude Opus 4.8(`claude-opus-4-8`) — 현재 최고 사양 모델로 작성되었다.

## 문서 성격
구현 문서가 아닌 **조사(Research) 문서**이다. 현재 구현된 AI 분석 기능의 구조를 파악하고, 고도화 방법론과 "AI를 활용한 투자·주식 최근 뉴스 탐색" 방법을 조사하여 적용 방향을 정리한다.
실제 구현은 별도의 계획·체크리스트 문서(추후 14.04.02 등)로 분리한다.

## Part 1. 현재 구현 분석

### 1-1. 전체 구조

```
사용자 입력
   │
   ▼
orchestrator.routeToAgent()  ← 키워드 규칙 기반 라우팅 (정적)
   │  detectCompoundIntent()  ← 복합 의도 → 파이프라인
   ▼
claudeApi.sendToAgent()      ← 에이전트별 컨텍스트 빌드 + 시스템 프롬프트 선택
   │  (뉴스/공시/시세 프리패치)
   ▼
callClaudeWithRetry() → fetch(/api/claude)
   ▼
api/claude.js (Vercel Serverless 프록시) → api.anthropic.com/v1/messages
```

### 1-2. 6개 에이전트

| 에이전트 | 파일 | max_tokens | 역할 |
|---------|------|-----------|------|
| analysis | `src/agents/analysisAgent.js` | 1024 | 급등락 원인 분석 / 시장 브리핑 / 포트폴리오 영향 |
| journal | `src/agents/journalCoachAgent.js` | 2048 | 매매 심리 코칭 |
| research | `src/agents/researchAgent.js` | 2048 | 종목 리서치 (재무·기술·뉴스·공시) |
| portfolio | `src/agents/portfolioAgent.js` | 1024 | 보유 자산 분석 |
| alert | `src/agents/alertAgent.js` | 1024 | 관심종목 시장 모니터링 |
| report | `src/agents/reportAgent.js` | 2048 | 성과 리포트 (주간/월간) |

### 1-3. 데이터 그라운딩(근거 수집) 방식

- **뉴스**: `src/api/newsApi.js` — Yahoo Finance Search + 네이버 금융 통합. 종목당 최대 5~8건, 3분 캐시.
- **공시**: `src/api/disclosureApi.js` — DART(한국) / SEC EDGAR(미국). DART 일일 40,000건 한도 추적.
- **시세**: `src/api/stockApi.js` — `fetchQuote`로 실시간 시세, 60초 캐시.
- 수집한 데이터를 `buildXXXContext()` 함수로 **텍스트 문자열로 직렬화**하여 사용자 메시지 앞에 주입하는 방식이다. 즉 "프리패치 후 컨텍스트 주입형 RAG"에 가깝다.

### 1-4. 강점

1. 6개 에이전트 + 오케스트레이터로 도메인이 잘 분리되어 있다.
2. 뉴스·공시·시세·기술적 지표를 프리패치하여 환각을 억제한다.
3. 자동 재시도(지수 백오프), max_tokens 절단 감지·이어쓰기, 10턴 초과 대화 요약 압축 등 안정성 장치가 갖춰져 있다.
4. 사용자 본인 API 키(`X-User-Api-Key`) 경유로 종량제 비용을 사용자가 부담하는 구조가 이미 완성되어 있다.
5. researchAgent는 응답 하단에 `[참고 출처]` URL과 매력도 JSON 블록을 강제하여 후속 파싱이 가능하다.

### 1-5. 한계 (고도화 대상)

| # | 한계 | 근거 위치 |
|---|------|----------|
| L1 | **프록시가 모델을 `claude-sonnet-4-6`으로 하드코딩**. 호출부에서 `model`을 넘겨도 메인 경로에서 무시됨 | `api/claude.js:38` |
| L2 | **라우팅이 정적 키워드 매칭**. 오타·동의어·복잡한 의도에 취약 (예: "왜 빠졌어?"는 잡지만 "무슨 일 있었길래"는 못 잡음) | `src/agents/orchestrator.js:7~60` |
| L3 | **뉴스 소스가 종목 티커 검색에 한정**. 거시·테마·정책 뉴스(금리, 환율, 업종 규제)는 수집 경로가 없음 | `src/api/newsApi.js` |
| L4 | **뉴스 감성(sentiment) 정량화 없음**. 제목 텍스트만 전달, 긍/부정·강도 점수 미산출 | `analysisAgent.buildMovementContext` |
| L5 | **실시간 웹 탐색 불가**. 모델은 프리패치된 5~8건만 봄. 누락된 최신 이슈를 스스로 찾지 못함 | 전체 |
| L6 | **출처 인용이 비강제·수기 의존**. 모델이 텍스트로 URL을 붙이는 방식이라 신뢰도·클릭 추적이 약함 | `researchAgent.RESEARCH_PROMPT:20` |
| L7 | **max_tokens가 작음(analysis 1024)**. 다단계 추론·근거 비교에 부족 | `src/api/claudeApi.js:64~71` |
| L8 | **확장적 사고(extended thinking) 미사용**. 복합 원인 분석에서 추론 깊이 한계 | `api/claude.js` |

## Part 2. 고도화 방법론 조사

### 2-1. Anthropic 네이티브 웹 검색 도구 (핵심 권장)

2026년 4월 GA된 Claude API의 `web_search` 서버 도구가 가장 직접적인 고도화 수단이다. 모델이 **필요할 때 스스로 검색 → 본문 읽기 → 출처 인용**까지 한 번의 요청 안에서 처리한다.

- **최신 버전**: `web_search_20260209` — 동적 필터링(dynamic filtering) 지원. 모델이 코드를 작성·실행하여 검색 결과를 컨텍스트 진입 전 선별 → 정확도↑, 토큰↓. (단 code execution 도구 동시 활성 필요.)
- **이전 버전**: `web_search_20250305` — 동적 필터링 없는 기본형.
- **지원 모델**: Fable 5, Opus 4.8, Mythos 5, Opus 4.7/4.6, Sonnet 4.6 등.
- **출처 인용**: 항상 자동 활성. 각 인용에 `url`, `title`, `cited_text`(최대 150자) 포함. 인용 필드는 토큰 과금 제외.
- **비용**: 검색 1,000건당 **$10** + 검색 결과 토큰 비용. `max_uses`로 요청당 검색 횟수 상한.
- **지역화**: `user_location`으로 한국(country=KR, timezone=Asia/Seoul) 결과 우선 노출 가능 → 국내 종목 뉴스 정확도 향상.
- **도메인 필터링**: `allowed_domains` / `blocked_domains`로 신뢰 출처만 한정 가능 (예: 금융감독원, 한국거래소, 주요 경제지).

최소 요청 예시.

```json
{
  "model": "claude-opus-4-8",
  "max_tokens": 4096,
  "messages": [{ "role": "user", "content": "삼성전자 오늘 주가가 왜 움직였는지 최근 뉴스로 분석해줘" }],
  "tools": [{
    "type": "web_search_20260209",
    "name": "web_search",
    "max_uses": 5,
    "user_location": { "type": "approximate", "country": "KR", "timezone": "Asia/Seoul" },
    "allowed_domains": ["dart.fss.or.kr", "finance.naver.com", "hankyung.com", "mk.co.kr"]
  }]
}
```

> 본 프로젝트 적합성: 이미 `api/claude.js` 프록시를 거치므로 `tools` 배열만 전달·중계하면 된다. **현재의 Yahoo/Naver 프리패치를 보강하거나 일부 대체**할 수 있다.

### 2-2. Agentic RAG / 멀티 에이전트 방법론

2026년 업계는 단순 RAG에서 **Agentic RAG**(에이전트가 검색 전략·도구·반복 횟수를 동적으로 결정)로 이동 중이다.

- **ReAct 프롬프팅 + 동적 에이전트** 결합으로 SEC 공시·주가 시계열·뉴스 감성을 단계적으로 추론하는 워크플로가 표준화되고 있다.
- 학술적으로는 다중 에이전트 RAG-LLM(MARAG-Fin) 구조가 뉴스·재무·시세를 분리 수집 후 종합하는 패턴을 제시한다.
- 본 프로젝트는 이미 6개 에이전트 + 파이프라인(`runAgentPipeline`)을 보유 → **라우팅을 LLM 기반(소형 모델 분류)으로 전환**하고, **에이전트가 web_search를 직접 호출**하게 하면 Agentic RAG에 자연스럽게 도달한다.

### 2-3. 뉴스 감성 분석 정량화

- 국내 연구(KCI)에서 판별형(KcBERT, KRFinBERT) vs 생성형(Llama 3.1, Mistral, Gemma 2) 비교 결과, **KRFinBERT 부정 감성 기반 Short 전략이 누적 76.20%·샤프 0.9998**을 기록 → 한국어 금융 뉴스 감성의 예측력이 검증됨.
- 적용안: 수집한 뉴스 제목·요약을 LLM으로 **종목별 감성 점수(-1~+1)·강도·근거 1줄**로 구조화하여 컨텍스트에 주입 → analysisAgent의 원인 분석 정밀도 향상.

### 2-4. 확장적 사고(Extended Thinking) + 출처 인용 API

- Opus 4.8/4.7/4.6는 확장적 사고 시 최대 128k 출력 토큰 지원. 복합 원인 분석·다종목 비교에 추론 깊이를 부여할 수 있다.
- `thinking.display: "omitted"`로 사고 과정을 응답에서 숨겨 스트리밍 속도 확보 가능.
- Anthropic Citations API와 web_search 인용을 결합하면 "근거 문장 → 출처 URL" 매핑이 구조화되어 L6(출처 비강제) 한계를 해소한다.

## Part 3. AI 활용 투자·주식 뉴스 탐색 방법 조사

요구의 핵심인 "AI로 최근 뉴스를 탐색하는 방법"을 3개 경로로 정리한다.

### 경로 A — Anthropic web_search 도구 (1순위 권장)

- 별도 뉴스 API 계약·키 관리 없이, **모델이 직접 최신 뉴스를 검색·요약·인용**.
- 장점: 통합 단순(프록시에 `tools`만 추가), 출처 자동 인용, 한국 지역화/도메인 화이트리스트 지원.
- 단점: 검색당 $10/1,000건 추가 비용 → `max_uses` 상한 + 캐시로 통제 필요.
- 본 프로젝트 적용: analysis/research/alert 에이전트에 한해 web_search 활성, journal/portfolio/report는 비활성(불필요).

### 경로 B — 금융 데이터 API / MCP 서버 (구조화 데이터 보강)

2026년 트렌드는 **MCP(Model Context Protocol) 서버**로 AI 에이전트가 실시간 금융 데이터를 직접 질의하는 방식이다.

| 서비스 | 특징 | 비고 |
|--------|------|------|
| Alpha Vantage | 거래소 라이선스 실시간+장기 과거 데이터, 공식 MCP 서버 | AI 워크플로 1순위로 평가됨 |
| EODHD | MCP 서버 + AI Skills + OpenAPI, 단일 구독 광범위 | 올라운더 |
| FMP (Financial Modeling Prep) | MCP 서버로 70,000+ 데이터포인트, Claude 연결 | 재무 데이터 강함 |
| Massive (구 Polygon.io) | WebSocket 실시간 틱, 기관급 저지연 | 대규모·고빈도용 |

- 본 프로젝트 적합성: 이미 Yahoo/Naver/DART/EDGAR를 자체 프록시로 쓰고 있어 **즉시 도입 필요성은 낮음**. 향후 미국 종목 재무·뉴스 품질을 높이려면 FMP/Alpha Vantage를 보조 소스로 검토.

### 경로 C — 거시·테마 뉴스 탐색 (현재 사각지대 보완)

- 현재는 종목 티커 단위 뉴스만 수집(L3). 금리·환율·업종 정책·지정학 같은 **거시 뉴스**는 web_search 도구로 "오늘 한국 증시 영향 뉴스", "반도체 업종 규제 동향" 등을 질의해 보완하는 것이 가장 비용 효율적이다.
- alert 에이전트의 일일 시장 브리핑에 거시 뉴스 탐색을 결합하면 CLAUDE.md의 AlertAgent 사양(가격 이상·뉴스·공시 스캔)에 더 부합한다.

### 국내 시장 적용 시 유의점

- 한국투자증권 'AI 시황(지금 시장은?)' 등 국내 증권사도 LLM 대화형·AI 종목분석을 상용화 → 사용자 기대 수준이 높아짐.
- web_search의 `user_location`을 KR로 두고 `allowed_domains`에 국내 신뢰 출처(네이버 금융, 한경, 매경, DART)를 넣으면 영어권 결과 편향을 줄일 수 있다.
- 금지사항 준수: 어떤 경로든 "매수/매도 권유" 문구 금지, 면책 문구 필수(기존 프롬프트 규칙 유지).

## Part 4. 본 프로젝트 적용 제안 (우선순위)

| 순위 | 항목 | 대상 파일 | 기대 효과 | 비용/리스크 |
|------|------|----------|----------|------------|
| P1 | 프록시 모델 파라미터화 (하드코딩 제거, 호출부 `model` 존중, 기본값 Opus 4.8 옵션) | `api/claude.js` | 최고 사양 모델 활용 가능, 에이전트별 모델 차등 | 낮음 (Opus는 토큰 단가↑) |
| P2 | analysis/research/alert에 `web_search` 도구 결합 (`max_uses` 상한 + 캐시) | `api/claude.js`, `src/api/claudeApi.js` | 실시간 뉴스 탐색·자동 출처 인용 (L3·L5·L6 해소) | 검색 $10/1,000건 |
| P3 | 뉴스 감성 점수 구조화 (LLM 1콜로 종목별 감성/강도/근거) | `src/agents/analysisAgent.js` | 원인 분석 정밀도↑ (L4 해소) | 추가 토큰 소량 |
| P4 | LLM 기반 라우팅 (Haiku 분류) 또는 정적 규칙 보강 | `src/agents/orchestrator.js` | 의도 인식 정확도↑ (L2 해소) | Haiku 저비용 |
| P5 | analysis max_tokens 상향 + 확장적 사고 옵션 | `src/api/claudeApi.js`, `api/claude.js` | 다단계 추론 품질↑ (L7·L8 해소) | 토큰 비용↑ |
| P6 | 거시·테마 뉴스 탐색을 alert 일일 브리핑에 결합 | `src/agents/alertAgent.js` | 시장 브리핑 완성도↑ (L3 보완) | P2에 종속 |

### 권장 1차 범위
P1 + P2를 묶어 "**최고 사양 모델 + 실시간 뉴스 웹 검색**"을 1차 고도화로 진행하면, 요구사항("AI로 최근 뉴스 탐색")과 "최고 사양 모델 사용"을 동시에 충족한다.

### 비용 통제 가이드
- `web_search`는 analysis/research/alert에만, `max_uses: 3~5`로 제한.
- 동일 종목·동일 일자 검색은 기존 `apiCache`로 재사용.
- 사용자 본인 키 구조이므로 비용은 사용자 부담 → 설정에서 "웹 검색 사용" 토글 제공 검토.
