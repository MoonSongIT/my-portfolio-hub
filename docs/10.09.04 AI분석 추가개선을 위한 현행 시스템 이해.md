# AI분석 추가개선을 위한 현행 시스템 이해

_작성일: 2026-05-20_

---

## 전체 흐름

```
사용자 메시지 (AIChat.jsx)
     ↓
sendToAgent() — claudeApi.js
     ↓
routeToAgent() — orchestrator.js  ← 키워드 기반 라우팅
     ↓
[에이전트 선택]
     ↓                                  ↓
buildXxxContext()               fetchNews / fetchQuote / fetchDisclosures
(앱 로컬 데이터 → 텍스트 직렬화)      (외부 API 실시간 조회)
     ↓                                  ↓
         systemPrompt + contextText 결합
               ↓
         POST /api/claude  (프록시 서버)
               ↓
         Claude API 단일 호출 (싱글턴)
               ↓
         응답 텍스트 → UI 렌더링
```

## 에이전트 목록 (6개)

| 에이전트 | 라우팅 방식 | 데이터 소스 | 특이사항 |
|---------|-----------|------------|---------|
| **analysis** | 키워드(왜/이유) or compound(보유+뉴스) | 뉴스API + 공시API + Quote API | 3가지 경로 분기 (종목/포트폴리오/시장) |
| **journal** | 키워드(패턴/심리/일지) | journalStore (로컬) | 200건 초과 시 압축 컨텍스트 |
| **research** | 키워드(분석/어때/살까) | stockData bundle or Tool Use 전환 | 번들 없으면 Tool Use 경로로 자동 전환 |
| **portfolio** | 키워드(포트폴리오/수익률) | portfolioStore (로컬) | 기본 fallback 에이전트 |
| **alert** | 키워드(관심종목/뉴스) | watchlistStore (로컬) | quotesMap 선택적 주입 |
| **report** | 키워드(리포트/성과) | portfolioStore (로컬) | 기간(monthly 등) 파라미터 |

## 핵심 설계 특성

### 1. 키워드 기반 라우팅 (단순, 취약)

- 딥러닝 없이 순수 `includes()` 매칭
- 모호한 문장이나 복합 질문에서 오라우팅 발생
- compound 조건(보유+뉴스 키워드 동시 포함)은 예외적으로 최우선 처리

**라우팅 우선순위 (orchestrator.js)**

```
1순위: compound 조건 — 포트폴리오 키워드 AND 뉴스/시장 키워드 → analysis
2순위: ROUTING_RULES 순서대로 첫 매칭 에이전트
       analysis → journal → portfolio → research → alert → report
기본값: portfolio (fallback)
```

### 2. 컨텍스트 = 로컬 데이터 직렬화 + 실시간 API

- 로컬 데이터(보유종목·일지·관심종목)는 Zustand store에서 직접 읽어 텍스트로 직렬화
- 실시간 데이터(뉴스·공시·지수)는 분석 시점에 별도 fetch
- contextText와 userMessage를 합쳐 단일 user 메시지로 Claude에 전달

### 3. 단일 Claude 호출 (멀티에이전트 없음)

- 에이전트 간 협력 없음 — 항상 단 1회 API 호출
- "오케스트레이터"는 선택 로직만 담당하고 실제 오케스트레이션은 없음
- 복합 분석(예: 종목분석 + 포트폴리오 영향)은 단일 프롬프트로 처리

### 4. analysis 에이전트의 3-경로 분기

```
analysis 선택 시
  ├─ context에 종목(ticker) 있음  → 종목 급등락 원인 분석 (ANALYSIS_PROMPT)
  │    └─ fetchNews + fetchDisclosures 병렬 호출
  ├─ context에 holdings 있음      → 포트폴리오 + 시장뉴스 연관 분석 (PORTFOLIO_ANALYSIS_PROMPT)
  │    └─ 각 종목 fetchQuote 병렬 + fetchNews(S&P500)
  └─ 둘 다 없음                   → 전체 시장 브리핑 (MARKET_BRIEF_PROMPT)
       └─ 4개 지수 fetchQuote 병렬 + fetchNews(S&P500)
```

### 5. 대화 히스토리 관리

- 10턴(메시지 20개) 초과 시 이전 대화를 Claude에게 요약시켜 압축 (`summarizeAndCompressHistory`)
- 세션별로 IndexedDB에 저장, 사용자별 세션 목록 관리
- 멀티턴은 `sendWithHistory()`로 전체 messages 배열을 Claude에 전달

### 6. max_tokens 에이전트별 차등

| 에이전트 | max_tokens |
|---------|-----------|
| journal, report | 4096 |
| research | 3072 |
| analysis, portfolio, alert | 2048 |

## 구조적 한계 (개선 아이디어 도출 포인트)

| 항목 | 현재 | 한계 |
|------|------|------|
| **라우팅** | 키워드 `includes()` 매칭 | 복합 질문·오타·문맥 인식 불가 |
| **컨텍스트** | 전체 데이터 직렬화 후 주입 | 토큰 낭비, 비관련 데이터 포함 가능성 |
| **데이터 신선도** | 요청 시점 단발 fetch | 지수/뉴스 지연, 에이전트마다 중복 호출 |
| **에이전트 협력** | 없음 (단일 호출) | 복합 분석 불가 (예: 종목분석 + 포트폴리오 영향) |
| **피드백 루프** | 없음 | AI 답변 품질을 학습·개선하는 기제 없음 |
| **응답 형식** | 프롬프트로만 제어 | 구조화된 JSON 출력 없음, 파싱 취약 |
| **오류 복구** | 500/529에서만 재시도 | 불완전 응답·환각 감지 없음 |
