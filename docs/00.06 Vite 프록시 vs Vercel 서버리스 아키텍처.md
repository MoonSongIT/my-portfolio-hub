# 00.06 Vite 프록시 vs Vercel 서버리스 아키텍처

> 작성일: 2026-06-02
> 목적: 로컬 개발 환경과 Vercel 배포 환경의 구조적 차이를 기록
> 핵심 교훈: `vite.config.js`의 `server.proxy`는 **빌드 결과물에 포함되지 않는다**

## 1. 한눈에 보는 차이

```
┌─────────────────────────────────────────────────────────────────┐
│                    로컬 개발 환경 (npm run dev)                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  브라우저                                                         │
│    │                                                            │
│    │  GET /api/naver/api/stock/069500/basic                     │
│    ▼                                                            │
│  Vite 개발 서버 (Node.js 프로세스, localhost:5173)                 │
│    │                                                            │
│    │  server.proxy 설정이 요청을 가로채서 전달                      │
│    │  /api/naver/* → https://m.stock.naver.com/*               │
│    │  /api/yahoo/* → https://query1.finance.yahoo.com/*        │
│    │                                                            │
│    ▼                                                            │
│  외부 API 서버 (Naver, Yahoo Finance 등)                          │
│                                                                 │
│  ✅ 작동 이유: Vite 서버가 Node.js로 실행 중이라 프록시 가능          │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│              Vercel 배포 환경 (npm run build 후)                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  브라우저                                                         │
│    │                                                            │
│    │  GET /api/naver/api/stock/069500/basic                     │
│    ▼                                                            │
│  Vercel CDN (정적 파일만 서빙: HTML, JS, CSS)                      │
│    │                                                            │
│    │  ← /api/* 경로에 대응하는 함수가 없으면                        │
│    ▼                                                            │
│  404 Not Found ❌                                               │
│                                                                 │
│  ❌ 실패 이유: 빌드 결과물에 Vite 프록시가 포함되지 않음              │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│         Vercel 배포 환경 (서버리스 함수 추가 후) ← 현재 상태          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  브라우저                                                         │
│    │                                                            │
│    │  GET /api/naver/api/stock/069500/basic                     │
│    ▼                                                            │
│  Vercel                                                         │
│    ├── 정적 파일 (CDN): HTML, JS, CSS                             │
│    └── 서버리스 함수 (api/*.js): /api/* 경로 처리                   │
│          │                                                      │
│          │  api/naver/[...path].js 가 요청 수신                   │
│          │  fetch('https://m.stock.naver.com/...') 직접 호출      │
│          ▼                                                      │
│  외부 API 서버 (Naver, Yahoo Finance 등)                          │
│                                                                 │
│  ✅ 작동 이유: 서버리스 함수가 Vite 프록시 역할을 대체                 │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 빌드 전후 무엇이 사라지는가

| 항목 | 로컬 dev | 빌드 후 (Vercel) |
|------|---------|-----------------|
| `vite.config.js` `server.proxy` | ✅ 작동 | ❌ 사라짐 |
| Vite 미들웨어 (`configureServer`) | ✅ 작동 | ❌ 사라짐 |
| `src/` 컴포넌트·스토어·훅 | ✅ 포함 | ✅ 번들에 포함 |
| `api/*.js` Vercel 함수 | ✅ 로컬 서버 처리 | ✅ 서버리스로 배포 |
| `.env` 변수 (`VITE_` 접두사) | ✅ 번들에 포함 | ✅ Vercel 환경변수로 주입 |
| `.env` 변수 (접두사 없음) | ✅ 서버 전용 | ✅ Vercel 서버 함수에서만 접근 |

## 3. 현재 프로젝트의 API 프록시 매핑

### 로컬 → `vite.config.js` `server.proxy`

```js
'/api/naver'     → 'https://m.stock.naver.com'         (한국 주가 모바일 API)
'/api/naver-pc'  → 'https://finance.naver.com'          (한국 주가 PC 페이지)
'/api/yahoo'     → 'https://query1.finance.yahoo.com'   (미국 주가 v1/v8)
'/api/yahoo-v10' → 'https://query2.finance.yahoo.com'   (미국 주가 v10)
'/api/krx-data'  → 'http://data.krx.co.kr'             (KRX 데이터)
```

### Vercel → `api/` 서버리스 함수 현황

| 경로 | 파일 | 대상 | 상태 |
|------|------|------|------|
| `/api/naver/*` | `api/naver/[...path].js` | `m.stock.naver.com` | ✅ 완료 |
| `/api/yahoo/*` | `api/yahoo/[...path].js` | `query1.finance.yahoo.com` | ✅ 완료 |
| `/api/yahoo-v10/*` | `api/yahoo-v10/[...path].js` | `query2.finance.yahoo.com` | ✅ 완료 |

## 4. 새 외부 API를 추가할 때 체크리스트

새 외부 API 연동이 필요할 때 **반드시 두 곳 모두** 작업해야 한다.

```
□ 1. vite.config.js → server.proxy 에 로컬 프록시 추가
      (로컬 개발용 — npm run dev 에서만 동작)

□ 2. api/<이름>/[...path].js → Vercel 서버리스 함수 생성
      (배포용 — Vercel에서만 동작)
```

> 둘 중 하나만 하면 로컬/배포 중 한쪽에서 반드시 404 발생.

---

## 5. 왜 프록시가 필요한가 (CORS)

브라우저에서 `fetch('https://m.stock.naver.com/...')` 를 직접 호출하면 **CORS 정책**에 의해 차단된다.

```
브라우저 직접 호출 (❌ CORS 차단):
  브라우저 → https://m.stock.naver.com/...  ← Origin 다름 → 차단

프록시 경유 (✅ 정상):
  브라우저 → /api/naver/...     ← 같은 origin, CORS 없음
               ↓
           서버(Node.js)  →  https://m.stock.naver.com/...
                                ← 서버끼리 통신 = CORS 제한 없음
```

## 6. Vercel 서버리스 함수 작성 패턴

```js
// api/<이름>/[...path].js
import { setCors, handlePreflight } from '../_cors.js'

export default async function handler(req, res) {
  if (handlePreflight(req, res)) return
  setCors(req, res)

  // catch-all 경로 파라미터 추출
  // /api/naver/api/stock/069500/basic
  // → req.query.path = ['api', 'stock', '069500', 'basic']
  const segments = Array.isArray(req.query.path)
    ? req.query.path
    : [req.query.path].filter(Boolean)

  // 쿼리 파라미터에서 path 제거 후 재조립
  const { path: _p, ...queryRest } = req.query
  const qs = new URLSearchParams(queryRest).toString()

  const targetUrl = `https://외부API.com/${segments.join('/')}${qs ? '?' + qs : ''}`

  const response = await fetch(targetUrl, {
    headers: { 'User-Agent': '...', 'Referer': '...' },
  })

  const text = await response.text()
  res.setHeader('Content-Type', response.headers.get('content-type'))
  res.status(response.status).send(text)
}
```
