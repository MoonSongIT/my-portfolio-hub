# AI분석 응답 형식 개선 계획

_작성일: 2026-05-20_

---

## 1. 현행 응답 형식의 구체적 문제

### 1-1. 프롬프트로만 형식 제어 — 구조화 보장 없음

모든 에이전트 응답 형식은 시스템 프롬프트의 자연어 지시로만 제어된다. Claude가 지시를 무시하거나 다른 형식으로 응답해도 감지하거나 교정하는 기제가 없다.

```js
// reportAgent.js — 프롬프트 지시 예시
`출력 형식 규칙:
- 금액: 천 단위 구분자 포함 (1,234,567원)
- 수익률: 소수점 2자리 (12.34%)
- 표: 마크다운 테이블 형식
- 전문 용어: 괄호 안에 간단한 설명 추가`
```

- Claude가 "1234567원"(쉼표 없음)으로 응답해도 시스템은 탐지하지 못한다.
- "마크다운 테이블 대신 목록으로" 응답해도 그대로 사용자에게 전달된다.

### 1-2. 구조화된 JSON 출력 없음 — 파싱 취약

AI 응답은 항상 자연어 텍스트 문자열이다. 응답에서 특정 값을 추출해야 할 때 정규식이나 텍스트 파싱에 의존해야 한다.

```js
// claudeApi.js — 응답 처리
const text = response.data?.content?.[0]?.text || '응답을 받지 못했습니다.'
return { text, agentType, agentInfo }
// text는 순수 문자열 — 종목명, 수익률, 추천 종목 등을 추출할 방법 없음
```

ResearchAgent가 "투자 매력도: 상" 또는 "투자 매력도 — 상" 중 어느 형식으로 응답할지 알 수 없어, 이 값을 UI에서 색상으로 표시하려면 불안정한 텍스트 매칭이 필요하다.

### 1-3. 에이전트별 출력 구조가 코드에서 명시적이지 않음

각 에이전트가 어떤 구조의 데이터를 돌려줄 것인지 타입 정의나 스키마가 없다.

```js
// 현재: 모든 에이전트 동일한 반환 구조
return { text: '...', agentType: 'research', agentInfo: '...' }
// research가 종목 목록을 반환해도, report가 수익률 테이블을 반환해도 text 하나뿐
```

- UI 컴포넌트가 응답 내용에 따라 다르게 렌더링하려면 문자열을 파싱해야 한다.
- 향후 응답 일부를 차트 데이터로 재활용하거나 알림 트리거에 사용하기 어렵다.

### 1-4. 마크다운 렌더링 일관성 없음

ChatPanel에서 AI 응답을 마크다운으로 렌더링하지만, alert 에이전트는 이모지와 텍스트를 혼합해 렌더링 시 깨지는 경우가 있다.

```js
// alertAgent.js — 이모지 혼합 출력
`알림 우선순위:
- 🔴 긴급: ±10% 이상, 주요 공시 — 즉시 확인
- 🟡 주의: ±5%, 거래량 급증 — 오늘 중 확인`
// 이모지가 마크다운 파서에 따라 다르게 처리될 수 있음
```

## 2. 문제 요약

| 문제 | 영향 에이전트 | 심각도 |
|------|--------------|--------|
| 형식 제어가 프롬프트 자연어에만 의존 | 전체 | 중간 |
| 구조화된 JSON 출력 없음 | research, report, analysis | 높음 |
| 에이전트 출력 스키마 미정의 | 전체 | 중간 |
| 마크다운 렌더링 일관성 없음 | alert | 낮음 |

## 3. 개선 방향

### 옵션 A — 응답 후 파싱 레이어 추가

AI 응답(텍스트)을 받은 후, 정규식·키워드 파싱으로 구조화된 객체를 추출한다.

- 장점: AI 프롬프트 변경 없음, 점진적 적용 가능
- 단점: 파싱 취약성 그대로 존재, 응답 형식이 조금만 바뀌어도 파싱 실패

### 옵션 B — Claude JSON Mode 활용

Anthropic API의 `tool_use` 기능을 활용해 에이전트별 스키마를 정의하고, Claude가 항상 구조화된 JSON으로 응답하게 한다.

- 장점: 파싱 안정성, 타입 안전, UI 재활용 용이
- 단점: API 사용 방식 변경 폭이 크고, 에이전트별 스키마 설계 비용 높음

### 옵션 C — 하이브리드 텍스트 + JSON 블록 (추천)

AI 응답 내에 마크다운 코드 블록(` ```json `)으로 구조화 데이터를 포함시키고, 파서가 해당 블록만 추출한다.

```
AI 응답:
"삼성전자는 현재 기술적 지지선 근처에 있습니다...

\`\`\`json
{ "attractiveness": "상", "targetPrice": 90000, "risk": "중" }
\`\`\`"
```

- 장점: 사람이 읽기도 좋고 구조 추출도 가능, 기존 텍스트 흐름 유지
- 단점: Claude가 코드 블록을 빠뜨리면 파싱 실패 (graceful fallback으로 처리)

**추천: 옵션 C (하이브리드) → 에이전트별 점진적 적용**

옵션 B(tool_use)는 API 사용 방식 변경이 크다. 옵션 C는 기존 텍스트 응답 구조를 유지하면서 구조화 데이터만 코드 블록으로 추출해 UI에서 활용할 수 있다. 안정성이 검증되면 옵션 B로 마이그레이션한다.

## 4. 항목별 개선 상세

### 4-1. 에이전트별 출력 스키마 정의

```js
// src/agents/schemas.js 신규
export const AGENT_SCHEMAS = {
  research: {
    attractiveness: 'string',  // '상' | '중' | '하'
    targetPrice: 'number | null',
    risk: 'string',            // '상' | '중' | '하'
    similarTickers: 'string[]',
  },
  portfolio: {
    totalReturnPct: 'number',
    topGainer: '{ ticker: string, pct: number } | null',
    topLoser:  '{ ticker: string, pct: number } | null',
    rebalanceNeeded: 'boolean',
  },
  report: {
    periodReturnPct: 'number',
    benchmarkReturnPct: 'number',
    bestTicker: 'string | null',
    worstTicker: 'string | null',
  },
  alert: {
    urgentCount: 'number',
    cautionCount: 'number',
    infoCount: 'number',
    signals: '{ ticker: string, level: string, reason: string }[]',
  },
}
```

### 4-2. 프롬프트에 JSON 블록 지시 추가

각 에이전트 시스템 프롬프트 끝에 JSON 블록 지시를 추가한다.

```js
// researchAgent.js — 프롬프트 끝에 추가
`응답 마지막에 반드시 아래 JSON 블록을 포함하세요:
\`\`\`json
{
  "attractiveness": "상|중|하 중 하나",
  "targetPrice": 숫자 또는 null,
  "risk": "상|중|하 중 하나",
  "similarTickers": ["티커1", "티커2"]
}
\`\`\``
```

### 4-3. JSON 블록 파서 — extractStructuredData

```js
// src/utils/responseParser.js 신규
export function extractStructuredData(text) {
  const match = text.match(/```json\s*([\s\S]*?)\s*```/)
  if (!match) return null
  try {
    return JSON.parse(match[1])
  } catch {
    return null  // 파싱 실패 시 null, UI는 텍스트만 표시
  }
}

export function stripJsonBlock(text) {
  return text.replace(/```json[\s\S]*?```/g, '').trim()
}
```

### 4-4. UI에서 구조화 데이터 활용 — MessageBubble

```jsx
// src/components/chat/MessageBubble.jsx 수정
import { extractStructuredData, stripJsonBlock } from '../../utils/responseParser'

function MessageBubble({ message }) {
  const structured = extractStructuredData(message.content)
  const displayText = structured ? stripJsonBlock(message.content) : message.content

  return (
    <div>
      <MarkdownRenderer content={displayText} />
      {structured?.attractiveness && (
        <AttractivnessBadge level={structured.attractiveness} />
      )}
      {structured?.signals?.length > 0 && (
        <AlertSummaryChips signals={structured.signals} />
      )}
    </div>
  )
}
```

## 6. 개선 전후 동작 비교

| 항목 | 현재 | 개선 후 |
|------|------|---------|
| 응답 형식 보장 | 없음, 프롬프트 의존 | JSON 블록 파서로 구조 추출 가능 |
| 투자 매력도 표시 | 텍스트에서 직접 읽어야 함 | `structured.attractiveness` 배지로 표시 |

| 파싱 실패 처리 | 없음 | null 반환, 텍스트 그대로 표시 (graceful fallback) |
| 에이전트 출력 스키마 | 코드에 없음 | `schemas.js`에서 명시적 관리 |

## 8. 고려 사항

- **Claude 응답 일관성**: Claude가 JSON 블록을 빠뜨릴 수 있다. `extractStructuredData`가 null을 반환하면 UI는 텍스트만 표시하고 배지를 숨긴다. 오류를 발생시키지 않는다.
- **프롬프트 길이 증가**: JSON 지시 추가로 시스템 프롬프트가 약 200토큰 증가한다. Anthropic prompt caching(`cache_control: ephemeral`) 덕분에 추가 비용은 캐시 미스 시에만 발생한다.
- **스키마 버전 관리**: 스키마 변경 시 기존 응답 파싱이 깨질 수 있다. `schemas.js`에 버전 필드를 추가하고, 파서에서 버전별 처리를 분기할 준비를 한다.
- **tool_use 마이그레이션**: 옵션 C(하이브리드)가 안정화되면, Anthropic API의 `tool_use`로 전환해 파싱 안정성을 높이는 것을 장기 로드맵에 포함한다.
- **journal 에이전트 제외**: journalCoachAgent는 서술형 코칭 응답이 핵심이므로 JSON 블록 지시에서 제외한다.
