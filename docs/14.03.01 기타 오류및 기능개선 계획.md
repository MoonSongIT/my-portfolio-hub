### [FEAT-01] 대시보드 수익률 추이 차트 — 투자원금+손익 누적 막대 오버레이

**관련 파일**
- `src/components/charts/ProfitLineChart.jsx`

**배경**

대시보드 수익률 추이(AreaChart)는 누적 수익률 %만 보여준다.
실제 자산 규모(투자원금 + 누적 손익)가 어떻게 쌓여 왔는지는 한눈에 안 들어온다.

> 참고: 1차 구현에서 "일간 증감치(%p) 막대"로 오버레이했으나, 의도는 금액 기준 누적 막대였음. 본 항목은 누적 스택 막대로 재구현한 결과를 반영한다. 포트폴리오 꺾은선(HoldingPnlTimeline)은 적용 범위에서 제외(원복).

**목표**

대시보드 차트 한 화면에서 "수익률 흐름(누적 %) + 자산 규모(투자원금+손익 누적 금액)"를 함께 읽을 수 있게 한다.

**선택 차트 조합 — ComposedChart : Area + 스택 Bar + 이중 Y축**

| 레이어 | 데이터 | Y축 | 색상 |
|--------|--------|-----|------|
| Area (기존 유지) | `returnRate` 누적 수익률 % | 좌측 | 그린/레드 그라디언트 |
| Bar 하단 (신규) | `principalBase` = min(투자원금, 평가액) | 우측(금액) | 회색 (#cbd5e1) |
| Bar 상단 (신규) | `pnlSegment` = \|평가액−투자원금\| | 우측(금액) | 이익=#EF4444(빨강), 손실=#3B82F6(파랑) |
| ReferenceLine y=0 | 기준선 | 좌측 | 회색 점선 |

막대 해석:
- 손익 양수 → 베이스=투자원금(회색) + 위에 이익(빨강), 막대 전체 = 총 평가액
- 손익 음수 → 베이스=평가액(회색) + 위에 손실(파랑), 막대 전체 = 투자원금

선택 이유:
- `investedValue`(투자원금), `totalValue`(평가액) 필드가 데이터에 이미 존재 → 컴포넌트 내 파생만으로 계산
- 스택 막대가 "원금 위에 손익이 쌓이는" 누적 구조를 직관적으로 표현
- 이중 Y축으로 수익률(%)과 금액(원) 스케일 충돌 방지
- 한국 색상 컨벤션(이익=빨강, 손실=파랑) 적용

**구현 범위**

1. `ProfitLineChart.jsx`
   - 우측 `YAxis`를 금액 축(`formatCurrencyShort`, domain=[0, max])으로 변경
   - `dailyReturn` 단일 막대 → `principalBase` + `pnlSegment` 스택 막대(stackId)로 교체
   - 손익 부호로 상단 세그먼트 Cell 색상 분기
   - Tooltip: 누적 수익률 / 투자원금 / 손익합계 / 총 평가액 표시

2. `HoldingPnlTimeline.jsx`
   - 1차 구현분(일간 증감 Bar) 원복 — 적용 범위에서 제외

### [FIX-01] 자금 입출금 수정 모달 — 선택 정보 미표시·수정 불가

**관련 파일**
- `src/components/portfolio/CashFlowModal.jsx`

**증상**

자금관리에서 입출금 항목의 "수정" 버튼을 눌러도 팝업에 선택한 정보(금액·카테고리·날짜·메모)가 채워지지 않고 빈 폼이 뜬다.

**원인**

- 호출부(`CashFlowHistory.jsx`)는 `editTarget`(선택 항목)을 모달에 전달하지만, `CashFlowModal`이 `editTarget` prop을 받지 않아 무시됨.
- 모달의 init `useEffect`가 열릴 때 전 필드를 빈값으로 초기화.
- 저장 시 `addCashFlow`만 호출 → 수정이 아니라 새 항목으로 중복 추가됨.
- 스토어에는 `updateCashFlow(id, updates)`가 이미 존재했으나 모달이 호출하지 않음.

**수정**

1. `CashFlowModal`에 `editTarget` prop 추가 → 있으면 해당 값으로 폼 초기화(type·계좌·카테고리·금액·통화·날짜·메모)
2. 제출 시 `editTarget`이면 `updateCashFlow(id, payload)`, 아니면 기존 `addCashFlow(payload)`
3. 입금↔출금 탭 전환 시 카테고리 초기화를 `useEffect([type])` → 탭 클릭 핸들러(`handleTypeChange`)로 이동 (수정 모드 첫 로드에서 카테고리가 지워지는 문제 방지)
4. 헤더 제목/저장 버튼 라벨을 수정 모드일 때 "입출금 수정 / 수정 저장"으로 표시

> 참고: 자산 7,985만 vs 투자원금+손익 차액 145만은 본 항목과 무관(매도차익 정상 계상). 별도 진단 중 — 자동매매 매입원가(현금흐름 기준) vs 보유종목 avgPrice 원가의 계산 차이(USD 환율 시점차 유력).

### [FEAT-03] 수익률 추이 차트를 종합수익률 기준으로 재설계 (FEAT-01 개정)

**관련 파일**
- `src/utils/portfolioAggregator.js` (핵심)
- `src/pages/Dashboard.jsx`
- `src/components/charts/ProfitLineChart.jsx`
- `src/tests/portfolioAggregator.test.js`

**배경 / 검증 결과**

FEAT-01 차트 막대가 종합수익률 카드와 불일치. 원인은 데이터 출처 차이:
- 차트 = dailyPnl 스냅샷(보유주식만) → investedValue=보유주식 매입원가, 손익=미실현만, totalValue=주식평가액
- 카드 = cashFlow 투자원금(netCapital) + (미실현+실현+배당)

→ 차트 막대 전체(주식평가액 7,115만) ≠ 카드 자산(7,985만), 손익(미실현 1,909만) ≠ 손익합계(3,185만)

**해결 (옵션1: 종합수익률 기준 재설계)**

cashFlow·일지에 date가 있으므로 **과거 소급 계산 가능**. 스냅샷 구조 변경 불필요.
각 날짜 d마다:
- 미실현(d) = Σ (closePrice − avgBuyPrice)×qty×rate  (스냅샷)
- netCapital(d) = Σ cashFlow(date≤d, !isAuto, isCapital)(dep−wd)×rate
- realized(d) = Σ 일지 sell.pnl(date≤d)×rate + Σ cashFlow(date≤d, realized_gain)×rate
- dividend(d) = Σ cashFlow(date≤d, dividend)×rate
- 손익합계(d) = 미실현 + 실현 + 배당
- investedValue=netCapital(d), totalValue=netCapital+손익합계(=자산), returnRate=손익합계/netCapital×100

**구현 범위**

1. `portfolioAggregator.js` — 시그니처에 cashFlows, entries 추가 + 위 누계 로직
2. `Dashboard.jsx` — aggregatePortfolioHistory 호출에 cashFlows, entries 전달
3. `ProfitLineChart.jsx` — 툴팁 라벨(투자원금/손익합계/자산), 좌측 Area=종합수익률
4. `portfolioAggregator.test.js` — 테스트 갱신

**검증**: 최근 막대 전체=자산(7,985만), 손익부=손익합계(3,185만), 좌측 선=종합수익률(66.35%)이 카드와 일치

### [FIX-03] 매매일지 빠른입력/일괄입력 계좌 선택 일관성 유지

**관련 파일**

**증상**

빠른입력·일괄입력 폼을 열 때마다 계좌 선택이 항상 첫 번째 계좌(`accounts[0]`)로 초기화되어, 직전 오퍼레이션에서 선택한 계좌가 유지되지 않았다.

**수정**

1. `JournalEntryForm` — 신규 입력 기본 계좌를 `selectedAccountId !== 'all' ? selectedAccountId : accounts[0]`로 변경

### [FEAT-04] 매매일지 텍스트 입력 필드 한국어 IME 힌트 적용

**관련 파일**
- `src/components/journal/JournalEntryForm.jsx`
- `src/components/journal/JournalBatchForm.jsx`
- `src/index.css`

**배경**

숫자 필드를 제외한 텍스트 입력(종목 검색, 메모)에 포커스할 때 한글 입력 모드가 기본이 되도록 힌트를 제공한다.

**제약**

브라우저 보안 정책상 JavaScript/HTML로 OS IME를 강제 전환하는 표준 방법은 없다. 가능한 수준에서 최선의 힌트를 적용한다.

**적용 레이어**

| 레이어 | 내용 |
|---|---|
| `index.html` | `<html lang="ko">` — 기존에 이미 적용되어 있었음 |
| `index.css` | `input[lang="ko"], textarea[lang="ko"] { ime-mode: active }` 추가 — deprecated이나 Chrome/Edge 일부 버전에서 동작 |
| `JournalEntryForm` | 메모 `<textarea>`: `lang="ko"` 추가 |
| `JournalBatchForm` | 종목 검색 `<Input>`, 메모 `<Input>`: `lang="ko"` 추가 |
| 숫자 필드 | `inputMode="numeric/decimal"` 유지 — 변경 없음 |

**기대 효과**

- 모바일(Android/iOS): `lang="ko"` 속성이 한국어 키보드 우선 표시를 유도함 — 효과 가장 확실
- 데스크톱 Chrome/Edge: `ime-mode: active` 및 `lang="ko"` 힌트가 일부 환경에서 IME 활성 상태를 유도
