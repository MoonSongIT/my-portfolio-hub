# AI분석 데이터 신선도 개선 계획

_작성일: 2026-05-20_

---

## 1. 현행 데이터 신선도의 구체적 문제

### 1-1. 요청 시점 단발 fetch — 캐시 없음

모든 실시간 데이터(뉴스, 시세, 공시)는 사용자가 메시지를 보낼 때마다 새로 fetch한다.

```
사용자 메시지 ①  →  fetchNews()  →  Claude 호출
사용자 메시지 ②  →  fetchNews()  →  Claude 호출  (동일 데이터 재호출)
사용자 메시지 ③  →  fetchNews()  →  Claude 호출  (또 재호출)
```

같은 세션에서 포트폴리오 분석을 3번 요청하면 동일한 뉴스 API를 3번 호출한다. 뉴스는 몇 분 사이에 바뀌지 않으므로 중복 호출이 낭비다.

### 1-2. 지수 데이터는 analysis 에이전트에서만 fetch

```js
// claudeApi.js — analysis 경로 3에서만 지수 조회
const BRIEF_INDICES = ['^KS11', '^KQ11', '^IXIC', '^GSPC']
const [quotes, news] = await Promise.all([...])
```

- alert 에이전트는 지수 데이터 없이 관심종목 이름만 나열한다.
- portfolio 에이전트는 시장 전체 흐름과 무관하게 보유 종목 손익만 계산한다.
- "오늘 시장 어때?" 질문이 alert로 라우팅되면 지수 정보 없이 응답한다.

### 1-3. 뉴스 시간 순서가 보장되지 않음

```js
// newsApi.js — Naver와 Yahoo를 단순 병합
const merged = [...naverNews]
if (needed > 0) merged.push(...yahooNews.slice(0, needed))
return merged.slice(0, 5)
```

Naver와 Yahoo에서 가져온 뉴스를 시간 순서 없이 이어 붙인다. 가장 최신 뉴스가 앞에 오지 않을 수 있다. 두 소스에 동일 뉴스가 중복 포함될 수도 있다.

### 1-4. fetchQuote timeout 10초 — 다수 종목 시 지연 누적

```js
// stockApi.js
const yahooApi = axios.create({ baseURL: '/api/yahoo', timeout: 10000 })
```

analysis 경로 2에서 10개 보유 종목을 병렬 fetchQuote하면 최대 10초 대기가 발생한다. 개별 호출이 병렬이라도 가장 느린 응답에 맞춰야 한다.

### 1-5. DART 호출 횟수 모니터링이 경고만 하고 차단 없음

```js
// disclosureApi.js
if (dartCallCount >= 35_000) {
  console.warn(`[DisclosureAPI] DART 일일 호출 ${dartCallCount}건 — 40,000건 한도 근접`)
} else {
  console.debug(...)
}
```

35,000건 이상이 되어도 경고만 출력하고 계속 호출한다. 40,000건 한도 도달 시 DART API가 차단되면 모든 한국 주식 공시 조회가 실패한다.

### 1-6. 공시 조회 기간(days=30)이 고정

```js
// claudeApi.js
fetchDisclosures(ticker, market)  // days 미전달 → 항상 30일 기본값 사용
```

최근 7일 공시만 필요한 상황에도 30일치를 조회한다. "지난 3달 공시 알려줘" 같은 요청에는 대응 불가다.

## 2. 현행 데이터 신선도 문제 요약

| 문제 | 영향 | 심각도 |
|---|---|---|
| 세션 내 동일 API 반복 호출 | 불필요한 비용·지연 | 중간 |
| 지수 데이터가 analysis에만 있음 | alert 에이전트 응답 품질 저하 | 중간 |
| 뉴스 정렬·중복 미처리 | 오래된 뉴스가 최신보다 앞에 올 수 있음 | 낮음 |
| fetchQuote timeout 10초 | 다종목 분석 시 UX 저하 | 중간 |
| DART 한도 도달 시 차단 없음 | 공시 조회 전면 실패 가능 | **높음** |
| 공시 days 항상 30일 고정 | 불필요한 데이터 과다 조회 | 낮음 |

## 3. 개선 방향

### 방향 A — 세션 내 인메모리 캐시

요청 시점에 fetch한 데이터를 메모리에 TTL과 함께 저장한다. 같은 세션에서 동일 키 요청 시 캐시 반환.

**장점.** 구현 단순, 반복 API 호출 제거.  
**단점.** 탭 새로고침 시 캐시 소멸, 탭 간 공유 불가.

### 방향 B — 앱 시작 시 백그라운드 사전 로드

앱 마운트 시 지수 4개와 보유 종목 quote를 백그라운드에서 fetch하여 전역 상태에 저장한다.

**장점.** AI 채팅 요청 시 대기 없이 즉시 컨텍스트 빌드 가능.  
**단점.** 사용자가 AI를 쓰지 않는 경우에도 API를 호출한다.

### 방향 C — 하이브리드 캐시 (권장)

- 세션 내 인메모리 캐시를 두고 TTL 내 중복 호출을 차단한다.
- 지수 데이터만 공용 캐시 키로 관리하여 에이전트 간 공유한다.
- 뉴스 TTL 3분, 공시 TTL 15분, 시세 TTL 1분으로 차등 설정한다.

## 4. 항목별 개선 상세

### 4-1. 세션 내 인메모리 캐시 레이어

**신규 파일.** `src/api/apiCache.js`

```js
// src/api/apiCache.js
const cache = new Map()

export function getCached(key) {
  const entry = cache.get(key)
  if (!entry) return null
  if (Date.now() > entry.expiresAt) {
    cache.delete(key)
    return null
  }
  return entry.value
}

export function setCached(key, value, ttlMs) {
  cache.set(key, { value, expiresAt: Date.now() + ttlMs })
}

export function invalidateCache(keyPrefix) {
  for (const key of cache.keys()) {
    if (key.startsWith(keyPrefix)) cache.delete(key)
  }
}
```

TTL 기준.

| 데이터 종류 | TTL | 근거 |
|---|---|---|
| 시세(quote) | 60초 | 주식 시장은 1분 단위로 유의미한 변화 |
| 뉴스 | 3분 | 뉴스 생성 주기 |
| 공시 | 15분 | 수시 업로드지만 분 단위 변화는 적음 |
| 지수 | 60초 | 시세와 동일 |

### 4-2. fetchNews — 캐시 적용 + 중복 제거 + 시간 정렬

**변경 파일.** `src/api/newsApi.js`

```js
import { getCached, setCached } from './apiCache'

export async function fetchNews(ticker, market) {
  const cacheKey = `news:${ticker}:${market}`
  const cached = getCached(cacheKey)
  if (cached) return cached

  const isKorean = market === 'KRX' || market === 'KOSDAQ'
  const pureTicker = ticker.replace(/\.(KS|KQ)$/, '')
  let result

  if (isKorean) {
    const [naverNews, yahooNews] = await Promise.all([
      fetchNewsNaver(pureTicker),
      fetchNewsYahoo(`${pureTicker}.KS`),
    ])
    const merged = dedupeByTitle([...naverNews, ...yahooNews])
    result = sortByDate(merged).slice(0, 5)
  } else {
    result = (await fetchNewsYahoo(ticker)).slice(0, 5)
  }

  setCached(cacheKey, result, 3 * 60 * 1000)
  return result
}

function dedupeByTitle(items) {
  const seen = new Set()
  return items.filter(n => {
    const key = n.title.slice(0, 20)
    if (seen.has(key)) return false
    seen.add(key)
    return true
  })
}

function sortByDate(items) {
  return [...items].sort((a, b) => {
    if (!a.date) return 1
    if (!b.date) return -1
    return b.date.localeCompare(a.date)
  })
}
```

### 4-3. fetchQuote — 캐시 적용 + timeout 단축

**변경 파일.** `src/api/stockApi.js`

```js
import { getCached, setCached } from './apiCache'

export async function fetchQuote(ticker, market) {
  const cacheKey = `quote:${ticker}`
  const cached = getCached(cacheKey)
  if (cached) return cached

  const result = await fetchQuoteRaw(ticker, market)
  if (result) setCached(cacheKey, result, 60 * 1000)
  return result
}
```

`yahooApi` timeout을 10,000ms → 5,000ms로 단축. 5초 내 응답 없으면 null 반환.

### 4-4. 지수 데이터 공유 캐시

**변경 파일.** `src/api/claudeApi.js`

```js
async function getMarketIndices() {
  const cacheKey = 'indices:major'
  const cached = getCached(cacheKey)
  if (cached) return cached

  const INDICES = [
    { label: 'KOSPI',  ticker: '^KS11', market: 'NYSE' },
    { label: 'KOSDAQ', ticker: '^KQ11', market: 'NYSE' },
    { label: 'NASDAQ', ticker: '^IXIC', market: 'NASDAQ' },
    { label: 'S&P500', ticker: '^GSPC', market: 'NYSE' },
  ]
  const results = await Promise.allSettled(
    INDICES.map(idx => fetchQuote(idx.ticker, idx.market))
  )
  const indices = INDICES.map((idx, i) => ({
    label: idx.label,
    ticker: idx.ticker,
    price: results[i].status === 'fulfilled' ? results[i].value?.currentPrice ?? 0 : 0,
    changePercent: results[i].status === 'fulfilled' ? results[i].value?.changePercent ?? 0 : 0,
  }))

  setCached(cacheKey, indices, 60 * 1000)
  return indices
}
```

alert case에서 `getMarketIndices()`를 호출하여 지수 요약을 contextText에 추가한다. analysis 경로 3도 동일 함수를 재사용하여 중복 코드를 제거한다.

### 4-5. DART 일일 한도 — 임계값 도달 시 조회 차단

**변경 파일.** `src/api/disclosureApi.js`

```js
function trackDartCall() {
  const today = new Date().toDateString()
  if (dartCallDate !== today) { dartCallCount = 0; dartCallDate = today }
  dartCallCount++

  if (dartCallCount >= 38_000) {
    throw new Error('DART_DAILY_LIMIT_REACHED')
  } else if (dartCallCount >= 35_000) {
    console.warn(`[DisclosureAPI] DART 일일 호출 ${dartCallCount}건 — 한도 근접`)
  }
}

export async function fetchDisclosures(ticker, market, days = 30) {
  try {
    if (isKorean) {
      trackDartCall()  // 38,000건 이상이면 여기서 throw
      // ... 기존 호출 로직
    }
  } catch (err) {
    if (err.message === 'DART_DAILY_LIMIT_REACHED') {
      return [{ title: '[공시 조회 일시 중단] DART API 일일 한도 근접 — 자정 이후 재개됩니다.', date: '', url: '' }]
    }
    return []
  }
}
```

## 8. 고려 사항

### 캐시 무효화

사용자가 "최신 데이터로 다시 분석해줘"라고 하면 캐시를 무효화해야 한다. "새로", "다시", "최신" 키워드 감지 시 해당 ticker의 캐시를 invalidateCache()로 삭제하고 재조회하는 로직을 라우팅 단계에서 추가할 수 있다.

### 시장 휴장일 TTL 연장

거래 시간 외(시장 휴장)에는 시세가 변하지 않는다. 휴장 시간 감지 후 quote TTL을 연장(예: 30분)하면 불필요한 호출을 추가로 줄일 수 있다. 1차 개선에서는 단순 TTL로 처리하고 2차에서 적용을 검토한다.

### 탭 간 캐시 공유

현재 캐시는 모듈 스코프 Map이므로 같은 탭 내에서만 공유된다. 필요 시 BroadcastChannel 또는 SharedWorker로 확장 가능하나 1차 개선에서는 단순 모듈 캐시로 충분하다.
