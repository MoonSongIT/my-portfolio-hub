## 2. 의존관계 분석

개선 항목 사이에는 다음과 같은 실행 선후관계가 있다.

```
10.10.07 오류복구 (callClaudeWithRetry)
    │
    └─ 모든 Claude 호출의 기반
           │
           ├─ 10.10.03 데이터 신선도 (TTL 캐시)
           │       │
           │       └─ 10.10.02 컨텍스트 도출 (올바른 데이터로 컨텍스트 구성)
           │               │
           │               └─ 10.10.01 라우팅 (정확한 컨텍스트로 라우팅 판단)
           │                       │
           │                       └─ 10.10.04 에이전트 협력 (안정된 라우팅 위에서 파이프라인)
           │
           ├─ 10.10.06 응답 형식 (독립적 — Phase 3과 병렬 진행 가능)
           │
           └─ 10.10.05 피드백 루프 (응답이 안정된 후 수집 의미 있음)
```

**핵심 원칙.**

- 오류 복구(10.10.07)가 가장 먼저다. Claude 호출이 불안정한 상태에서 다른 개선을 쌓으면 불안정성이 전파된다.
- 데이터 신선도(10.10.03) → 컨텍스트(10.10.02) 순서로 진행해야 한다. 올바른 데이터 없이 컨텍스트를 조립해도 버그는 그대로다.
- 라우팅(10.10.01)은 컨텍스트가 정확해진 후에 개선해야 라우팅 결과를 신뢰할 수 있다.
- 에이전트 협력(10.10.04)은 라우팅이 안정돼야 복합 의도 감지 오탐이 줄어든다.
- 응답 형식(10.10.06)은 의존성이 낮아 Phase 3과 병렬 진행 가능하다.
- 피드백 루프(10.10.05)는 응답 품질이 안정된 후 수집해야 의미 있다.
