# 14.04.02 AI 분석 기능 고도화 구현계획

## 작성일
2026-06-15

## 근거 문서
[14.04.01 AI 분석 기능고도화 조사](./14.04.01%20AI%20분석%20기능고도화%20조사.md) — 본 계획은 조사 문서의 한계(L1~L8)와 우선순위 제안(P1~P6)을 구현 단위로 구체화한다.

## 사용 모델
구현 시 분석 계열 에이전트는 최고 사양 모델(`claude-opus-4-8`)을 사용하도록 한다.

---

## 1. 목표

1. 분석 계열 에이전트가 **최고 사양 모델**을 사용할 수 있게 한다 (현재 프록시가 Sonnet으로 하드코딩, L1).
2. analysis·research·alert 에이전트가 **실시간 웹 검색으로 최신 뉴스를 직접 탐색·인용**하게 한다 (L3·L5·L6).
3. 비용을 통제 가능한 범위로 묶는다 (검색 횟수 상한 + 캐시 + 설정 토글).

## 2. 범위 (Phase 구분)

| Phase | 항목 | 조사 문서 매핑 | 상태 |
|-------|------|---------------|------|
| **Phase 1** | 프록시 모델 파라미터화 + web_search 도구 결합 | P1 + P2 (권장 1차) | 본 계획 주 대상 |
| Phase 2 | 뉴스 감성 점수 구조화 + LLM 기반 라우팅 | P3 + P4 | 후속 |
| Phase 3 | max_tokens 상향 + 확장적 사고 + 거시 뉴스 결합 | P5 + P6 | 후속 |

본 문서는 **Phase 1을 상세 설계**하고, Phase 2·3은 방향만 기술한다.

---

## 3. Phase 1 상세 설계

### 3-1. P1 — 프록시 모델 파라미터화

**현재 상태**
- `api/claude.js:36~41` — `model: 'claude-sonnet-4-6'` 하드코딩. 본문의 `model`을 읽지 않음.
- 호출부(`src/api/claudeApi.js`)에서 `model`을 일부 넘기지만(예: `generatePostTradeCoaching`) 메인 경로에서 무시됨.

**변경안**
1. `api/claude.js`
   - 요청 본문에서 `model`을 수용한다.
   - 허용 모델 화이트리스트를 두고, 미허용·미지정 시 기본값으로 보정한다.
     - 화이트리스트(안): `claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5-20251001`, `claude-haiku-4-5`.
     - 기본값(안): `claude-sonnet-4-6` (하위호환 유지).
   - 검증을 통과한 `model`만 Anthropic 요청에 전달한다.
2. `src/api/claudeApi.js`
   - 에이전트별 모델 맵 `AGENT_MODELS`를 추가한다.
     - `analysis`·`research`·`report` → `claude-opus-4-8` (깊은 분석)
     - `journal`·`portfolio`·`alert` → `claude-sonnet-4-6` (기본)
   - `sendToAgent` / `runAgentPipeline` / `sendWithHistory` 의 payload에 `model`을 포함한다.

> 트레이드오프: Opus는 토큰 단가가 높다. 사용자 본인 키 부담 구조이므로, 분석 깊이가 필요한 에이전트에만 선별 적용한다.

### 3-2. P2 — web_search 서버 도구 결합

**도구 사양 (조사 문서 2-1 근거)**
- 도구 타입: `web_search_20260209`(동적 필터링) 또는 `web_search_20250305`(기본형).
  - 동적 필터링은 code execution 도구 동시 활성이 필요하므로 **1차는 기본형(`web_search_20250305`)** 으로 단순하게 시작한다.
- `max_uses`로 요청당 검색 횟수 상한.
- `user_location`으로 한국 지역화(country=KR, timezone=Asia/Seoul).
- `allowed_domains`로 신뢰 출처 화이트리스트.
- 출처 인용은 항상 자동 — 응답에 `citations`(url/title/cited_text) 포함.
- 비용: 검색 1,000건당 $10 (+ 검색 결과 토큰).

**변경안**

1. `api/claude.js`
   - 요청 본문에서 `tools` 배열을 수용하여 Anthropic 요청에 그대로 전달(passthrough)한다.
   - **응답 처리 변경 (중요)**: web_search 사용 시 응답 `content`는 여러 블록(`text`, `server_tool_use`, `web_search_tool_result`, 인용 포함 `text`)으로 구성된다.
     - 현재 클라이언트 파서 `response.data.content[0].text`는 첫 블록만 읽어 **깨질 수 있다**.
     - 프록시 또는 클라이언트에서 **모든 `type === 'text'` 블록을 결합**하고, `citations`를 수집하도록 한다.
     - `stop_reason: 'pause_turn'` 처리(서버 도구 루프)는 1차 범위에서 단순화하되, 발생 시 그대로 사용자에게 텍스트 반환한다(무한 루프 방지).

2. `src/api/claudeApi.js`
   - 에이전트별 도구 맵 `AGENT_TOOLS`를 추가한다.
     - `analysis`·`research`·`alert` → web_search 활성
     - `journal`·`portfolio`·`report` → 비활성(불필요)
   - 도구 설정(안):
     ```
     {
       type: 'web_search_20250305',
       name: 'web_search',
       max_uses: 3,
       user_location: { type: 'approximate', country: 'KR', timezone: 'Asia/Seoul' },
       allowed_domains: ['finance.naver.com', 'hankyung.com', 'mk.co.kr', 'dart.fss.or.kr', 'sedaily.com']
     }
     ```
   - **응답 파서 개선**: `content`의 모든 text 블록 결합 + 인용 추출 → `{ text, citations }` 형태로 정규화한다.
   - **출처 표기**: 수집한 citations를 응답 하단 `[참고 출처]`로 렌더링(기존 researchAgent의 출처 규칙과 통일).

3. 비용 가드
   - `settingsStore`에 `webSearchEnabled` 토글을 추가한다(기본값은 착수 전 결정).
   - 토글 OFF면 `AGENT_TOOLS`를 비활성화하여 기존 프리패치 방식으로 폴백한다.
   - 동일 질의 재검색은 기존 `apiCache`로 완화한다.

> 호환: web_search가 켜져도 기존 Yahoo/Naver/DART 프리패치는 유지한다. 모델이 프리패치 컨텍스트 + 웹 검색을 함께 활용하게 하여, 검색 실패·OFF 시에도 최소 품질을 보장한다.

### 3-3. Phase 1 검증 방법

| 검증 | 방법 | 기대 결과 |
|------|------|----------|
| 모델 적용 | analysis 호출 시 네트워크 응답 `model` 필드 확인 | `claude-opus-4-8` |
| 화이트리스트 | 임의 model 문자열 전달 | 기본값으로 보정 |
| 웹 검색 동작 | "오늘 삼성전자 왜 움직였어?" 질의 | 검색 수행 + 출처 인용 포함 응답 |
| 응답 파서 | web_search 응답의 멀티 text 블록 | 전체 텍스트 정상 결합, 잘림 없음 |
| 토글 OFF | 설정에서 웹 검색 OFF 후 질의 | 기존 프리패치 방식으로 정상 응답 |
| 비용 상한 | max_uses=3 초과 시 | `max_uses_exceeded` 무해 처리 |
| 하위호환 | journal/portfolio/report | 기존과 동일 동작(도구·Opus 미적용) |

## 4. Phase 2 · 3 방향 (후속)

- **P3 뉴스 감성 점수**: 수집 뉴스를 LLM 1콜로 종목별 감성(-1~+1)·강도·근거 1줄 구조화 → `analysisAgent` 컨텍스트에 주입.
- **P4 LLM 라우팅**: `orchestrator.routeToAgent`를 Haiku 분류 기반으로 보강(정적 규칙은 폴백 유지).
- **P5 추론 강화**: `AGENT_MAX_TOKENS.analysis` 상향(1024→2048+) + 확장적 사고 옵션(`thinking`) 프록시 수용.
- **P6 거시 뉴스**: alert 일일 브리핑에 "오늘 한국 증시 영향 뉴스" 류 거시 검색 결합(P2 종속).

## 5. 리스크 & 롤백

| 리스크 | 영향 | 대응 |
|--------|------|------|
| web_search 응답 파싱 불일치 | 응답 텍스트 깨짐 | text 블록 결합 파서 + 단위 테스트 우선 작성 |
| Opus 단가 상승 | 사용자 비용 부담 | 분석 계열에만 선별 적용 + 토글 |
| 검색 비용 폭증 | $10/1,000건 누적 | `max_uses` 상한 + 캐시 + 설정 토글 |
| Vercel 함수 한도(12개) | 신규 함수 추가 불가 | 신규 엔드포인트 없이 기존 `api/claude.js` 확장으로 처리 |
| 콘솔 웹 검색 미허용 | 401/도구 무시 | 사용자에게 콘솔 설정 안내 |

**롤백**: 변경은 `api/claude.js` + `src/api/claudeApi.js` + (토글)`settingsStore` 한정. 커밋 단위 분리로 P1·P2 개별 롤백 가능.
