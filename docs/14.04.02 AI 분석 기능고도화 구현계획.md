# 14.04.02 AI 분석 기능 고도화 구현계획

## 작성일
2026-06-15

## 근거 문서
[14.04.01 AI 분석 기능고도화 조사](./14.04.01%20AI%20분석%20기능고도화%20조사.md) — 본 계획은 조사 문서의 한계(L1~L8)와 우선순위 제안(P1~P6)을 구현 단위로 구체화한다.

## 사용 모델
구현 시 분석 계열 에이전트는 최고 사양 모델(`claude-opus-4-8`)을 사용하도록 한다.

---

## 1. 목표

1. 분석 계열 에이전트가 **최고 사양 모델**을 사용할 수 있게 한다 (현재 프록시가 Sonnet으로 하드코딩, L1).
2. analysis·research·alert 에이전트가 **실시간 웹 검색으로 최신 뉴스를 직접 탐색·인용**하게 한다 (L3·L5·L6).
3. 비용을 통제 가능한 범위로 묶는다 (검색 횟수 상한 + 캐시 + 설정 토글).

## 2. 범위 (Phase 구분)

| Phase | 항목 | 조사 문서 매핑 | 상태 |
|-------|------|---------------|------|
| **Phase 1** | 프록시 모델 파라미터화 + web_search 도구 결합 | P1 + P2 (권장 1차) | 본 계획 주 대상 |
| Phase 2 | 뉴스 감성 점수 구조화 + LLM 기반 라우팅 | P3 + P4 | 후속 |
| Phase 3 | max_tokens 상향 + 확장적 사고 + 거시 뉴스 결합 | P5 + P6 | 후속 |

본 문서는 **Phase 1을 상세 설계**하고, Phase 2·3은 방향만 기술한다.

## 3. Phase 1 상세 설계

### 3-1. P1 — 프록시 모델 파라미터화

**현재 상태**
- `api/claude.js:36~41` — `model: 'claude-sonnet-4-6'` 하드코딩. 본문의 `model`을 읽지 않음.
- 호출부(`src/api/claudeApi.js`)에서 `model`을 일부 넘기지만(예: `generatePostTradeCoaching`) 메인 경로에서 무시됨.

**변경안**
1. `api/claude.js`
   - 요청 본문에서 `model`을 수용한다.
   - 허용 모델 화이트리스트를 두고, 미허용·미지정 시 기본값으로 보정한다.
     - 화이트리스트(안): `claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5-20251001`, `claude-haiku-4-5`.
     - 기본값(안): `claude-sonnet-4-6` (하위호환 유지).
   - 검증을 통과한 `model`만 Anthropic 요청에 전달한다.
2. `src/api/claudeApi.js`
   - 에이전트별 모델 맵 `AGENT_MODELS`를 추가한다.
     - `analysis`·`research`·`report` → `claude-opus-4-8` (깊은 분석)
     - `journal`·`portfolio`·`alert` → `claude-sonnet-4-6` (기본)
   - `sendToAgent` / `runAgentPipeline` / `sendWithHistory` 의 payload에 `model`을 포함한다.

> 트레이드오프: Opus는 토큰 단가가 높다. 사용자 본인 키 부담 구조이므로, 분석 깊이가 필요한 에이전트에만 선별 적용한다.

### 3-2. P2 — web_search 서버 도구 결합

**도구 사양 (조사 문서 2-1 근거)**
- 도구 타입: `web_search_20260209`(동적 필터링) 또는 `web_search_20250305`(기본형).
  - 동적 필터링은 code execution 도구 동시 활성이 필요하므로 **1차는 기본형(`web_search_20250305`)** 으로 단순하게 시작한다.
- `max_uses`로 요청당 검색 횟수 상한.
- `user_location`으로 한국 지역화(country=KR, timezone=Asia/Seoul).
- `allowed_domains`로 신뢰 출처 화이트리스트.
- 출처 인용은 항상 자동 — 응답에 `citations`(url/title/cited_text) 포함.
- 비용: 검색 1,000건당 $10 (+ 검색 결과 토큰).

**변경안**

1. `api/claude.js`
   - 요청 본문에서 `tools` 배열을 수용하여 Anthropic 요청에 그대로 전달(passthrough)한다.
   - **응답 처리 변경 (중요)**: web_search 사용 시 응답 `content`는 여러 블록(`text`, `server_tool_use`, `web_search_tool_result`, 인용 포함 `text`)으로 구성된다.
     - 현재 클라이언트 파서 `response.data.content[0].text`는 첫 블록만 읽어 **깨질 수 있다**.
     - 프록시 또는 클라이언트에서 **모든 `type === 'text'` 블록을 결합**하고, `citations`를 수집하도록 한다.
     - `stop_reason: 'pause_turn'` 처리(서버 도구 루프)는 1차 범위에서 단순화하되, 발생 시 그대로 사용자에게 텍스트 반환한다(무한 루프 방지).

2. `src/api/claudeApi.js`
   - 에이전트별 도구 맵 `AGENT_TOOLS`를 추가한다.
     - `analysis`·`research`·`alert` → web_search 활성
     - `journal`·`portfolio`·`report` → 비활성(불필요)
   - 도구 설정(안):
     ```
     {
       type: 'web_search_20250305',
       name: 'web_search',
       max_uses: 3,
       user_location: { type: 'approximate', country: 'KR', timezone: 'Asia/Seoul' },
       allowed_domains: ['finance.naver.com', 'hankyung.com', 'mk.co.kr', 'dart.fss.or.kr', 'sedaily.com']
     }
     ```
   - **응답 파서 개선**: `content`의 모든 text 블록 결합 + 인용 추출 → `{ text, citations }` 형태로 정규화한다.
   - **출처 표기**: 수집한 citations를 응답 하단 `[참고 출처]`로 렌더링(기존 researchAgent의 출처 규칙과 통일).

3. 비용 가드
   - `settingsStore`에 `webSearchEnabled` 토글을 추가한다(기본값은 착수 전 결정).
   - 토글 OFF면 `AGENT_TOOLS`를 비활성화하여 기존 프리패치 방식으로 폴백한다.
   - 동일 질의 재검색은 기존 `apiCache`로 완화한다.

> 호환: web_search가 켜져도 기존 Yahoo/Naver/DART 프리패치는 유지한다. 모델이 프리패치 컨텍스트 + 웹 검색을 함께 활용하게 하여, 검색 실패·OFF 시에도 최소 품질을 보장한다.

### 3-3. Phase 1 검증 방법

| 검증 | 방법 | 기대 결과 |
|------|------|----------|
| 모델 적용 | analysis 호출 시 네트워크 응답 `model` 필드 확인 | `claude-opus-4-8` |
| 화이트리스트 | 임의 model 문자열 전달 | 기본값으로 보정 |
| 웹 검색 동작 | "오늘 삼성전자 왜 움직였어?" 질의 | 검색 수행 + 출처 인용 포함 응답 |
| 응답 파서 | web_search 응답의 멀티 text 블록 | 전체 텍스트 정상 결합, 잘림 없음 |
| 토글 OFF | 설정에서 웹 검색 OFF 후 질의 | 기존 프리패치 방식으로 정상 응답 |
| 비용 상한 | max_uses=3 초과 시 | `max_uses_exceeded` 무해 처리 |
| 하위호환 | journal/portfolio/report | 기존과 동일 동작(도구·Opus 미적용) |

## 4. Phase 2 상세 설계 (P3 + P4)

Phase 1로 "최신 데이터 수집·웹 검색"이 갖춰졌으므로, Phase 2는 **수집한 데이터의 해석 품질**(뉴스 감성)과 **요청 분배 정확도**(라우팅)를 높인다.

### 4-1. P3 — 뉴스 감성 점수 구조화

**현재 상태**
- `analysisAgent.buildMovementContext` / `buildPortfolioMovementContext` / `buildMarketBriefContext`는 뉴스 제목을 **그대로 나열**만 한다 (L4).
- 모델이 매번 제목 텍스트에서 긍/부정을 즉석 추론 → 일관성·정밀도 한계.

**변경안**
1. 신규 모듈 `src/api/sentimentApi.js`
   - `scoreNewsSentiment(newsItems, { name, ticker })` 함수.
   - Haiku 1콜로 뉴스 묶음을 받아 **JSON 배열** 반환:
     ```
     [{ "i": 0, "sentiment": -1.0~1.0, "strength": "high|mid|low", "reason": "한 줄 근거" }, ...]
     ```
   - 모델: `claude-haiku-4-5` (저비용·저지연). max_tokens 512.
   - 실패·타임아웃(5s) 시 빈 배열 반환 → 감성 없이 기존 동작 폴백.
2. `src/api/apiCache.js` 캐시 연동
   - 캐시 키 `sentiment:${ticker}:${market}` — 뉴스 캐시(3분)와 동일 수명.
3. `src/agents/analysisAgent.js`
   - `buildMovementContext`가 `news[i].sentiment`(점수·강도·근거)를 함께 렌더:
     ```
     [최근 뉴스]
     1. (감성 -0.7 / high) 제목 — 근거 …
     ```
   - 종목별 **종합 감성 라벨**(예: 부정 우세) 한 줄 요약 추가.
4. `src/api/claudeApi.js`
   - analysis 경로(`sendToAgent`)에서 `fetchNews` 직후 `scoreNewsSentiment`를 병렬/후속 호출하여 news에 sentiment 병합 → 기존 `buildMovementContext`에 전달.

**적용 범위(결정 필요)**: ① movement(종목 급등락)만 vs ② movement+portfolio+market brief 전체.
**항상 vs 토글(결정 필요)**: 비용/지연을 고려해 `settingsStore.newsSentimentEnabled`(기본 ON 권장 — Haiku라 저렴) 또는 web_search 토글에 종속.

> 트레이드오프: 분석 1회당 Haiku 1콜 추가(수백 토큰). web_search 대비 매우 저렴하나 지연 +0.5~1s. 캐시로 반복 질의 비용 완화.

### 4-2. P4 — LLM 기반 라우팅 (하이브리드)

**현재 상태**
- `orchestrator.routeToAgent`는 **정적 키워드 매칭**, 미매칭 시 `portfolio`로 폴백 (L2).
- 오타·동의어·자연어 의도("무슨 일 있었길래", "이 종목 담아도 될까")에 취약.

**변경안 — 정적 우선 + LLM 보정 (지연 최소화)**
1. `src/agents/orchestrator.js`
   - 신규 `classifyIntentLLM(message)` — Haiku로 6개 에이전트 중 하나를 분류(단일 토큰/JSON). max_tokens 16, 타임아웃 2s.
   - 신규 `routeToAgentSmart(message, context)`:
     1. `detectCompoundIntent` → 복합 의도면 그대로 파이프라인.
     2. 정적 `routeToAgent` 시도.
     3. **정적 결과가 기본 폴백(`portfolio`)인데 포트폴리오 키워드가 없을 때만** `classifyIntentLLM` 호출로 보정.
     4. LLM 실패·타임아웃 시 정적 결과 유지.
   - → 대부분 메시지는 LLM 호출 없이 정적 처리(지연 0). 모호한 경우만 Haiku 1콜.
2. `src/api/claudeApi.js`
   - `sendToAgent`의 `forceAgent || await routeToAgent(...)`를 `routeToAgentSmart`로 교체(이미 await 구조).
3. 회귀 방지
   - 기존 `routeToAgent`(정적)는 유지 — 폴백·테스트 기준.

> 트레이드오프: 명확한 키워드 메시지는 추가 비용·지연 0. 모호한 메시지만 Haiku 보정 → 정확도↑, 비용 최소.

### 4-3. Phase 2 검증 방법

| 검증 | 방법 | 기대 결과 |
|------|------|----------|
| 감성 JSON 파싱 | 합성 뉴스 입력 단위 테스트 | 점수·강도·근거 정상 파싱, 깨진 JSON 폴백 |
| 감성 주입 | 급등락 분석 응답 | 뉴스별 감성·종합 라벨 반영 |
| 감성 폴백 | Haiku 실패 모킹 | 감성 없이 기존 분석 정상 |
| 라우팅 정확도 | 모호 문장 세트("무슨 일 있었길래" 등) | 의도에 맞는 에이전트 선택 |
| 라우팅 지연 | 명확 키워드 메시지 | LLM 호출 없이 즉시 라우팅 |
| 라우팅 폴백 | LLM 타임아웃 모킹 | 정적 결과로 안전 폴백 |

## 4-9. Phase 3 상세 설계 (P5 + P6)

Phase 1·2로 데이터 수집·해석·분배가 갖춰졌으므로, Phase 3는 **추론 깊이**(확장적 사고)와 **시장 전반 맥락**(거시 뉴스)을 강화한다.

### 4-9-1. P5 — 추론 강화 (확장적 사고)

**현재 상태**
- 후속 보완으로 `AGENT_MAX_TOKENS.analysis` 1024→2048 완료(잘림 방지). 이로써 P5의 절반(토큰)은 선반영됨.
- 확장적 사고(`thinking`)는 미사용 → 뉴스·공시·감성을 교차하는 복합 원인 추론에 깊이 한계(L8).

**변경안**
1. `api/claude.js`
   - 요청 본문에서 `thinking`을 수용해 Anthropic 요청에 passthrough(tools와 동일 패턴).
   - 안전장치: `thinking.budget_tokens < max_tokens` 검증, 위반 시 thinking 제거 또는 max_tokens 보정.
2. `src/api/claudeApi.js`
   - `AGENT_THINKING` 맵 추가: analysis(및 선택적으로 research)에 `{ type:'enabled', budget_tokens: 2000, display:'omitted' }`.
   - thinking 활성 에이전트는 `max_tokens`를 동반 상향(예: analysis 2048→4096 = budget 2000 + 출력 여유).
   - `display:'omitted'`로 사고 과정을 응답에서 제외 → 스트리밍 속도 확보.
3. 응답 파서
   - `extractTextAndCitations`는 `type==='text'` 블록만 취하므로 thinking 블록을 자동 무시 → **추가 변경 불필요(호환)**.

> 주의: thinking 활성 시 Anthropic은 `temperature=1`을 요구하고 `max_tokens > budget_tokens` 여야 한다. 프록시에서 이 제약을 보정한다.
> 결정 필요: ① 적용 에이전트(analysis만 / +research), ② budget 크기, ③ 항상 ON vs 토글.

### 4-9-2. P6 — 거시·테마 뉴스 결합

**현재 상태**
- market brief(분석 경로 3)는 `fetchNews('^GSPC')`만 사용 → 종목 티커 단위 뉴스에 한정.
- 금리·환율·정책·지정학 같은 **거시 이슈는 수집 경로가 없음(L3)**.

**변경안 (P2 web_search 종속 — `webSearchEnabled` ON일 때만)**
1. `analysisAgent.buildMarketBriefContext` + (범위 확정 시) `alertAgent`
   - web_search로 거시 질의("오늘 한국·미국 증시에 영향을 준 주요 뉴스·금리·환율") 수행 → 거시 뉴스 섹션 보강.
2. `webSearchEnabled` OFF면 기존 지수+종목 뉴스 브리핑 그대로(폴백).
3. 출처 인용은 Phase 1의 citations 렌더를 재사용.

> 결정 필요: ④ 거시 소스(web_search 비용 vs 정적 소스 추가), ⑤ 적용 범위(market brief만 / +alert).

### 4-9-3. Phase 3 검증 방법

| 검증 | 방법 | 기대 결과 |
|------|------|----------|
| 확장적 사고 | analysis 응답 | 다요인(뉴스·공시·감성) 교차 추론 심화, 잘림 없음 |
| thinking 호환 | 응답 파싱 | thinking 블록 무시, 본문 text만 결합 |
| budget 안전장치 | budget≥max_tokens 입력 | thinking 제거/보정으로 400 방지 |
| 거시 뉴스 | 시장 브리핑 | 금리·환율·정책 등 거시 이슈 반영 |
| 거시 폴백 | webSearch OFF | 기존 지수+종목 브리핑 정상 |

## 5. 리스크 & 롤백

| 리스크 | 영향 | 대응 |
|--------|------|------|
| web_search 응답 파싱 불일치 | 응답 텍스트 깨짐 | text 블록 결합 파서 + 단위 테스트 우선 작성 |
| Opus 단가 상승 | 사용자 비용 부담 | 분석 계열에만 선별 적용 + 토글 |
| 검색 비용 폭증 | $10/1,000건 누적 | `max_uses` 상한 + 캐시 + 설정 토글 |
| Vercel 함수 한도(12개) | 신규 함수 추가 불가 | 신규 엔드포인트 없이 기존 `api/claude.js` 확장으로 처리 |
| 콘솔 웹 검색 미허용 | 401/도구 무시 | 사용자에게 콘솔 설정 안내 |
| (P3) 감성 Haiku 실패 | 감성 누락 | 빈 배열 폴백 — 기존 분석 그대로 |
| (P3) 분석 지연 +0.5~1s | UX 저하 | 캐시 + (옵션)토글 + Haiku 사용 |
| (P4) LLM 라우팅 오분류 | 잘못된 에이전트 | 정적 폴백 + 명확 키워드는 LLM 미호출 |
| (P4) 라우팅 지연 | 매 메시지 지연 | 폴백 케이스에만 LLM 호출 |

**롤백**: Phase 1 변경은 `api/claude.js`+`claudeApi.js`+`settingsStore` 한정. Phase 2는 신규 모듈(`sentimentApi.js`) + `analysisAgent.js`/`orchestrator.js`/`claudeApi.js` 한정. 커밋 단위 분리로 P1·P2·P3·P4 개별 롤백 가능.
