# 12.01.01 서버용 버전 확대를 위한 조사

> 작성일: 2026-05-27  
> 목적: 로컬 MVP → 서버 서비스 확장 전략 수립을 위한 경쟁사 기능 조사 및 아키텍처 방향 도출

---

## 1. 요약 (Executive Summary)

현재 My Portfolio Hub는 브라우저 로컬 스토리지(IndexedDB/Dexie)에 전적으로 의존하는 로컬 퍼스트 MVP다. 이를 서버 기반 서비스로 확장할 때 핵심 과제는 세 가지다.

1. **접근 방식 이원화** — 서버 URL로 바로 사용(웹 SaaS)하거나 로컬 앱으로 설치(PWA/Electron)하는 두 경로를 모두 지원
2. **DB 동기화** — 로컬 ↔ 서버 간 양방향 동기화, 버전 충돌 보호 포함
3. **경쟁 차별화** — 국내외 유사 서비스 대비 AI 심리 코칭이라는 명확한 포지션 유지

경쟁사 조사 결과, 서버 전환에서 가장 성공적인 사례는 **Wealthfolio**와 **Edgewonk → 클라우드 전환** 패턴이었다. 이 조사는 해당 사례를 포함해 주요 7개 서비스를 분석하고, 우리 프로젝트에 적용 가능한 아키텍처와 기능 우선순위를 도출한다.

## 2. 현재 MVP 상태

### 2.1 기술 현황

| 항목 | 현재 상태 |
|------|-----------|
| 데이터 저장 | IndexedDB(Dexie) — 브라우저 로컬 |
| 인증 | 없음 (단일 사용자, 로컬) |
| 서버 | Vite 개발 서버 + Claude API 프록시(서버리스) |
| 배포 | Vercel (정적 빌드 + Serverless API) |
| 데이터 이동 | 없음 (내보내기/가져오기만 제한적 지원) |

### 2.2 핵심 데이터 구조 (동기화 대상)

```

```

## 3. 경쟁사 분석

### 3.1 글로벌 포트폴리오 트래커

#### Sharesight (sharesight.com)
- **서비스 형태**: 클라우드 전용 SaaS, 오프라인 없음
- **접근 방식**: 웹 + iOS/Android 앱
- **동기화**: 실시간 클라우드 동기화 (단일 진실 소스 = 서버)
- **멀티디바이스**: 완전 지원 (계정 기반)
- **요금**: Free(10개 종목) / Starter / Standard / Premium (최대 $13.50/포트폴리오/월)
- **증권사 연동**: 200개+ 브로커 자동 연동, 240,000개+ 글로벌 종목
- **우리와 비교**: 심리 카테고리 없음, AI 코칭 없음. 단순 수익률 추적에 집중

#### Portseido (portseido.com)
- **서비스 형태**: 클라우드 SaaS
- **접근 방식**: 웹 앱 중심, 160개국 지원
- **동기화**: 클라우드 단일 소스
- **요금**: Free(1포트폴리오, 50거래) / 유료 티어 (14일 무료 체험)
- **차별화**: 70개+ 거래소, 20,000개+ ETF·크립토 지원, 포트폴리오 시각화 강조
- **우리와 비교**: 국제 시장 커버리지는 우세, 심리·AI 기능 없음

#### Wealthfolio (wealthfolio.app) ⭐ 가장 참고할 사례
- **서비스 형태**: **로컬 퍼스트** → 클라우드 확장 (우리와 동일한 방향)
- **접근 방식**: 데스크톱 앱(macOS/Windows/Linux) + 모바일(iOS) + **Docker 셀프호스팅**
- **동기화 방식**: Wealthfolio Connect로 QR 페어링 기반 기기 간 동기화 (E2E 암호화 적용)
- **v2.0 전환**: 오픈소스 로컬 전용 → 모바일 + Docker 클라우드 (Hacker News에 공개 발표)
- **핵심 원칙**: "데이터는 사용자 소유, 클라우드는 선택사항"
- **수익화**: 무료(로컬 전용) / Connect(유료, 기기 동기화)
- **우리와 비교**: AI 기능 없음, 심리 카테고리 없음. 아키텍처 전환 패턴이 우리와 동일

- **현재 요금**: $197/년 (2026 기준)

- **교훈**: 오프라인 전용의 멀티디바이스 한계가 클라우드 전환의 핵심 동인

- **서비스 형태**: Windows 전용 데스크톱, 일회성 구매 모델

### 3.4 참고: 로컬-클라우드 전환 모범 사례 (도구 앱)

#### Obsidian
- **철학**: 로컬 마크다운 파일 → 클라우드 Sync는 유료 애드온 (선택적)
- **동기화**: E2E 암호화, 충돌 시 양쪽 버전 보존 (사용자가 선택)

- **문제**: 진정한 로컬 퍼스트 불가 → 데이터 주권 민감 사용자 이탈 (Obsidian으로 대거 전환)

## 5. 서버 확장 핵심 요구사항

### 5.1 접근 방식 이원화

```
[사용자] ──┬──▶ 서버 URL (https://app.mypfhub.io)
           │        └─▶ 웹 앱 (React SPA, 클라우드 DB)
           │
           └──▶ 로컬 설치
                    └─▶ PWA (Add to Home Screen / 브라우저 설치)
```

핵심 원칙: 어느 경로든 동일한 사용자 경험을 보장한다. 로컬 설치 앱도 서버와 선택적 동기화가 가능하다.

---

### 5.2 데이터 저장 계층

```
[로컬 앱]                          [서버]
IndexedDB (Dexie) ◀──동기화──▶ PostgreSQL (Supabase)
     │                                   │
     │  오프라인 완전 독립 동작           │  멀티디바이스·백업·복구
     └───────────────────────────────────┘
              양방향 동기화 (버전 기반 충돌 보호)
```

---

### 5.3 DB 동기화 전략

경쟁사 사례와 2025년 오프라인 퍼스트 PWA 모범 사례를 종합한 권장 전략.

#### (A) 버전 기반 충돌 보호 (필수)

모든 레코드에 `updated_at` 타임스탬프와 `version` 정수를 부여한다.

```json
{
  "id": "entry-001",
  "version": 7,
  "updated_at": "2026-05-27T14:23:00Z",
  "device_id": "chrome-macbook",
  "data": { ... }
}
```

동기화 규칙.
- `version` 높은 쪽이 승리 (Version-based Last-Write-Wins)
- 동일 `version`이지만 내용이 다르면 → **충돌 경고** (사용자에게 선택권 제공)
- **낮은 버전으로 덮어쓰기 시도 시** → 차단 + 경고 팝업 표시

#### (B) 사용자에게 제공할 충돌 정보

```
⚠️  동기화 충돌 감지

  서버 버전: v12  (2026-05-27 14:23, PC-Chrome에서 수정됨)
  로컬 버전: v9   (2026-05-25 09:11, 현재 기기에서 수정됨)

  ❗ 로컬 버전이 서버보다 3단계 낮습니다.
     로컬로 덮어쓰면 2026-05-25 이후 PC에서 한 작업이 사라집니다.

  [서버 버전 유지]   [로컬로 덮어쓰기]   [병합 미리보기]
```

#### (C) 동기화 흐름

```
로컬 변경 발생
    │
    ▼
변경사항 큐(Queue)에 적재
    │
    ▼
온라인 상태? ──No──▶ 큐 보관 (오프라인 정상 사용 지속)
    │
   Yes
    │
    ▼
서버 최신 버전 조회
    │
    ├── 버전 일치 → 업로드 완료
    ├── 서버 > 로컬 → 서버 데이터 다운로드 후 로컬에 병합
    └── 서버 < 로컬 → 로컬 우선 업로드 (정상 케이스)
```

## 6. 서버 아키텍처 방향

### 6.1 권장 스택 (기존 스택 연장선)

| 계층 | 기존 | 서버 확장 후 |
|------|------|------------|
| 프론트엔드 | React 18 + Vite | 동일 (PWA 강화) |
| 로컬 DB | IndexedDB (Dexie) | 동일 (계속 유지) |
| 서버 DB | 없음 | Supabase (PostgreSQL + Auth + Realtime) |
| 인증 | 없음 | Supabase Auth (소셜 로그인 + 이메일) |
| API | Vercel Serverless | Vercel Serverless 확장 |
| 파일 저장 | 없음 | Supabase Storage (Excel import 파일 등) |
| 동기화 엔진 | 없음 | 커스텀 동기화 서비스 (버전 기반) |

**Supabase를 선택하는 이유.**
- 기존 Vercel 배포와 궁합이 좋음
- Row Level Security(RLS)로 사용자별 데이터 격리 내장
- Realtime 웹소켓으로 멀티디바이스 즉시 반영 가능
- 오픈소스라 향후 셀프호스팅 전환 가능 (Wealthfolio Docker 전략과 동일)

---

### 6.2 사용자 데이터 소유권 원칙

Obsidian과 Wealthfolio가 성공한 핵심 원칙을 채택한다.

```
1. 로컬 DB는 항상 완전한 독립 상태를 유지한다.
   → 인터넷 없이도 100% 동작

2. 서버는 선택적 부가서비스다.
   → 계정 없이도 사용 가능 (단, 멀티디바이스·백업 불가)

3. 언제든지 전체 데이터 내보내기가 가능하다. (JSON/CSV/Excel)
   → 벤더 종속 없음

4. AI API 키는 서버에 절대 동기화하지 않는다.
   → 사용자 기기에만 존재 (현행 유지)
```
