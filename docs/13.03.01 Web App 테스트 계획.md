## 1. 목적

Phase 12 (Supabase 인증 + 동기화) 및 Phase 13 (동기화 시점 개선) 구현 완료 후, Vercel에 배포된 Web 버전에서 전체 기능이 정상 동작하는지 검증한다.

## 2. 테스트 범위

### 2-1. 포함 범위

| 영역 | 내용 |
|------|------|
| 인증 | 이메일 가입/로그인, Google OAuth, 로그아웃, 재로그인 |
| 동기화 — 이탈 시 업로드 | PendingUploadModal 표시, 업로드/건너뛰기/취소 흐름 |
| 동기화 — 로그인 후 다운로드 | 최초 전체 다운로드, 증분 다운로드, 실패 복구 |
| 동기화 — 다중 기기 | 기기 A→B 데이터 전파 확인 |
| 페이지별 기능 | 대시보드, 매매일지, 포트폴리오, 자금관리, 종목탐색, 관심종목, 리포트, AI채팅, 증시캘린더, 설정 |
| 보안 | RLS 차단, AI 키 비동기화, Service Role Key 미노출 |

### 2-2. 제외 범위

- 모바일 네이티브 앱 (PWA 설치 후 동작은 별도 테스트)
- 자동 동기화 인터벌 (15분/1시간) — 시간 소요로 이번 테스트 제외

## 3. 테스트 환경

### 3-1. Vercel 배포 URL 획득

**방법 A — git push 자동 배포 (권장)**

```powershell
git push origin <현재_브랜치명>
```

Vercel이 자동으로 Preview 배포를 시작한다. 완료 후 Vercel Dashboard → Deployments 탭에서 Preview URL을 확인한다.

**방법 B — Vercel CLI 수동 배포**

```powershell
# Vercel CLI 설치 (최초 1회)
npm i -g vercel

# Preview 배포
vercel

# 운영 배포 (테스트 완료 후)
vercel --prod
```

### 3-2. Vercel 환경변수 확인

Vercel Dashboard → 프로젝트 → **Settings → Environment Variables** 에서 아래 3개가 등록되어 있어야 한다.

| 변수명 | 적용 환경 | 비고 |
|--------|----------|------|
| `VITE_SUPABASE_URL` | Production, Preview | Supabase Project URL |
| `VITE_SUPABASE_ANON_KEY` | Production, Preview | Supabase anon public 키 |
| `SUPABASE_SERVICE_ROLE_KEY` | Production, Preview | 서버 전용 — `VITE_` 접두사 절대 금지 |

누락된 변수가 있으면 동기화 API가 작동하지 않는다.

### 3-3. Supabase OAuth 콜백 URL 등록

Google 로그인을 테스트하려면 Vercel Preview URL을 Supabase에 미리 등록해야 한다.

Supabase Dashboard → **Authentication → URL Configuration**

- **Site URL**: `https://<운영도메인>` 또는 Preview URL
- **Redirect URLs**: `https://<preview-url>/auth/callback` 추가

### 3-4. 브라우저 요건

| 구분 | 브라우저 |
|------|---------|
| 기기 A | Chrome (일반 탭) |
| 기기 B | Chrome (시크릿 탭), Firefox, 또는 실제 모바일 기기 |

> Vercel URL은 외부에서 접근 가능하므로 PC + 실제 스마트폰으로 다중 기기 테스트가 가능하다.

## 4. 테스트 계정 준비

| 계정 | 역할 | 준비 방법 |
|------|------|----------|
| 테스트 계정 A | 기기 A 로그인, 기준 데이터 보유 | Supabase 이메일 가입 |
| 테스트 계정 B (선택) | RLS 차단 검증용 별도 계정 | 별도 이메일로 Supabase 가입 |

> 기존 운영 데이터가 있는 계정을 그대로 사용해도 무방하다.

---

## 5. 테스트 전제 조건

테스트 시작 전 아래 항목이 모두 충족되어야 한다.

- [ ] Vercel 배포 성공 — Dashboard에서 배포 상태 **Ready** 확인
- [ ] Vercel Preview URL 브라우저 접속 가능 확인
- [ ] Vercel 환경변수 3개 등록 확인 (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`)
- [ ] Supabase 프로젝트 활성 상태 (Dashboard 접속 가능)
- [ ] Supabase DB — 4개 테이블 RLS 활성화 확인 (`transactions`, `cash_flows`, `calendar_events`, `watchlist`)
- [ ] 테스트 계정 A 가입 완료 (이메일 인증 포함)

## 6. 테스트 실행 순서

아래 순서로 진행하면 앞 단계의 데이터가 뒤 단계의 전제가 된다.

```
단계 1 — 환경 준비 확인        → Vercel 배포 URL + 환경변수 확인
단계 2 — 인증 흐름              → 가입, 로그인, 로그아웃
단계 3 — 최초 기기 동기화       → 로그인 후 전체 다운로드
단계 4 — 기본 기능 페이지 순회  → 10개 페이지 핵심 기능
단계 5 — 이탈 시 업로드 팝업    → PendingUploadModal 시나리오
단계 6 — 다중 기기 동기화       → 기기 A↔B 데이터 전파
단계 7 — 오프라인 내성           → 네트워크 차단 후 복구
단계 8 — 보안 검증               → RLS, AI 키 비동기화
단계 9 — 운영 배포               → vercel --prod 또는 main 브랜치 머지
```

## 7. 합격 기준

| 등급 | 조건 | 결과 |
|------|------|------|
| PASS | 체크리스트 전 항목 통과, 콘솔 에러 없음 | 운영 배포 가능 |
| PARTIAL | 보안 항목 전부 통과, 기능 항목 80% 이상 통과 | 미통과 항목 수정 후 재검증 필요 |
| FAIL | 보안 항목 1개 이상 실패, 또는 인증 흐름 실패 | 배포 불가 |
