# AI분석 에이전트 협력 개선 계획

_작성일: 2026-05-20_

---

## 1. 현행 에이전트 협력의 구체적 문제

### 1-1. 사실상 단일 Claude 호출 — 에이전트 간 협력 없음

현재 구조에서 "에이전트"는 서로 다른 시스템 프롬프트를 가진 독립된 단일 호출이다. 두 에이전트가 결과를 공유하거나 이어받아 처리하는 흐름이 없다.

```
사용자 메시지
    │
    ▼
orchestrator.js  →  scoreRouting()  →  agentType 결정
    │
    ▼
sendToAgent(agentType)           ← 단 한 번의 Claude 호출
    │
    ▼
사용자에게 응답
```

"삼성전자 분석해줘, 그리고 내 포트폴리오에 미치는 영향도 알려줘"와 같은 복합 요청은 하나의 에이전트(research 또는 analysis)로만 라우팅되어, 다른 에이전트의 전문 능력을 활용하지 못한다.

### 1-2. 복합 분석 요청이 단순화되어 처리됨

```js
// claudeApi.js — sendToAgent L107-254
// analysis, research, portfolio, alert, report 중 하나만 실행
// 두 에이전트의 결과를 합산하는 경로 없음

if (agentType === 'analysis') {
  // 3가지 경로 중 하나 실행
  if (hasTicker) { ... }
  else if (hasHoldings) { ... }
  else { ... }
}
```

- "삼성전자 지금 살만해? 내 포트폴리오에 몇 % 담아야 할까?" → research만 실행, 포트폴리오 비중 제안 없음
- "오늘 급등락 종목 중 내 관심종목 있어?" → alert만 실행, watchlist 대조 로직 없음
- "지난달 실적과 이번 달 매매일지 비교해줘" → report만 실행, journal coach와 교차 분석 없음

### 1-3. 에이전트 간 컨텍스트 공유 불가

각 에이전트 호출은 독립적이므로 이전 에이전트가 도출한 인사이트를 다음 에이전트가 참조할 수 없다.

```js
// 현재: A 에이전트 결과를 B 에이전트에 전달하는 구조 없음
const resultA = await sendToAgent('research', message, context)
// resultA.text는 화면에 표시될 뿐, B 에이전트 호출 시 입력으로 쓰이지 않음
```

- research가 "삼성전자 목표주가 90,000원" 결론을 냈어도 portfolio 에이전트는 이 정보를 모른다.
- journal coach가 "추격매매 패턴"을 감지했어도 alert 에이전트는 동일 패턴의 관심종목을 연계해 경고하지 못한다.

### 1-4. 다단계 분석 흐름 설계 불가

현재는 오케스트레이터가 "어느 에이전트 하나"를 고르는 역할만 한다. 여러 에이전트를 순차/병렬로 실행하고 결과를 종합하는 파이프라인을 구성할 방법이 없다.

```js
// orchestrator.js — 단일 선택만 존재
export function scoreRouting(message, context) {
  // ...점수 계산...
  return topAgent  // ← 항상 단 하나
}
```

## 2. 문제 요약

| 문제 | 영향 에이전트 | 심각도 |
|------|--------------|--------|
| 복합 질문이 단일 에이전트로 처리 | 전체 | 높음 |
| 에이전트 간 결과 전달 구조 없음 | 전체 | 높음 |
| 오케스트레이터가 단일 선택만 가능 | orchestrator | 중간 |
| 종목분석 + 포트폴리오 연계 불가 | research, portfolio | 높음 |
| 일지 패턴 + 알림 연계 불가 | journal, alert | 중간 |

## 3. 개선 방향

### 옵션 A — 단일 에이전트 내 확장 (최소 변경)

각 에이전트 시스템 프롬프트에 다른 에이전트 영역 지식을 추가한다.

- 장점: 구조 변경 없음, 즉시 적용 가능
- 단점: 프롬프트 비대화, 에이전트 전문성 희석, 근본적 해결 아님

### 옵션 B — 순차 파이프라인 (추천)

오케스트레이터가 복합 의도를 감지하면 에이전트를 순차로 실행하고, 앞 에이전트의 출력을 다음 에이전트의 입력 컨텍스트로 주입한다.

```
사용자 메시지
    │
    ▼
복합 의도 감지 (compoundIntent)
    │
    ├─ 단순 의도 → 기존 단일 에이전트 호출
    │
    └─ 복합 의도 → 파이프라인 실행
           ├─ 1단계: research 호출 → result1
           ├─ 2단계: portfolio 호출 (context + result1 포함) → result2
           └─ 최종 응답 합성
```

- 장점: 에이전트 전문성 유지, 점진적 구현 가능, 컨텍스트 누적
- 단점: 응답 시간 증가(순차 호출), 파이프라인 관리 복잡도

### 옵션 C — 병렬 팬아웃 + 종합 에이전트

복합 의도 시 여러 에이전트를 병렬 실행하고, 별도 합성 에이전트(synthesizer)가 결과를 통합한다.

- 장점: 빠른 응답(병렬), 결과 교차 검증 가능
- 단점: 비용 대폭 증가(호출 수 3배+), 합성 프롬프트 설계 복잡

**추천: 옵션 B — 순차 파이프라인**

비용 효율과 구현 난이도의 균형이 가장 좋다. 복합 의도 패턴을 사전에 정의해 오용을 방지하고, 파이프라인 스텝 수를 최대 2단계로 제한해 응답 시간 증가를 관리한다.

## 4. 항목별 개선 상세

### 4-1. 복합 의도 감지 — compoundIntentDetector

오케스트레이터에 복합 의도 감지 로직을 추가한다. 단순 점수 기반이므로 Haiku 호출 없이 즉시 실행된다.

```js
// orchestrator.js 추가
const COMPOUND_PATTERNS = [
  {
    agents: ['research', 'portfolio'],
    keywords: [['분석', '종목', '살만'], ['포트폴리오', '비중', '담아야']],
  },
  {
    agents: ['alert', 'journal'],
    keywords: [['급등', '급락', '관심종목'], ['패턴', '실수', '일지']],
  },
  {
    agents: ['report', 'journal'],
    keywords: [['리포트', '결산'], ['일지', '비교', '되돌아']],
  },
]

export function detectCompoundIntent(message) {
  for (const { agents, keywords } of COMPOUND_PATTERNS) {
    const matched = keywords.every(group => group.some(kw => message.includes(kw)))
    if (matched) return agents  // ['research', 'portfolio'] 등
  }
  return null  // 단순 의도
}
```

### 4-2. 에이전트 파이프라인 실행 — runAgentPipeline

```js
// claudeApi.js 추가
export async function runAgentPipeline(agentTypes, message, context) {
  let cumulativeContext = { ...context }
  const results = []

  for (const agentType of agentTypes) {
    const result = await sendToAgent(agentType, message, cumulativeContext)
    results.push({ agentType, text: result.text })

    // 앞 에이전트 결과를 다음 에이전트 컨텍스트에 주입 (1,000자 이하로 요약)
    cumulativeContext = {
      ...cumulativeContext,
      previousAnalysis: result.text.slice(0, 1000),
      previousAgent: agentType,
    }
  }

  return {
    text: synthesizeResults(results),
    agentType: agentTypes.join('+'),
    pipeline: results,
  }
}

function synthesizeResults(results) {
  if (results.length === 1) return results[0].text
  return results.map((r, i) => `### ${i + 1}단계 분석\n${r.text}`).join('\n\n---\n\n')
}
```

### 4-3. AIChat.jsx — 파이프라인 진입점 연결

```js
// AIChat.jsx — handleSend 수정
import { detectCompoundIntent, runAgentPipeline, sendToAgent } from '../api/claudeApi'

const compoundAgents = detectCompoundIntent(userMessage)
let result
if (compoundAgents) {
  result = await runAgentPipeline(compoundAgents, userMessage, context)
} else {
  result = await sendToAgent(agentType, userMessage, context)
}
```

### 4-4. previousAnalysis 컨텍스트 활용 — 2단계 에이전트 프롬프트

2단계 에이전트(portfolio 등)의 컨텍스트 빌더에서 `previousAnalysis`를 활용한다.

```js
// portfolioAgent.js — buildPortfolioContext 수정
export function buildPortfolioContext(holdings, previousAnalysis) {
  let ctx = `[보유 종목]\n${formatHoldings(holdings)}`
  if (previousAnalysis) {
    ctx += `\n\n[선행 분석 결과]\n${previousAnalysis}\n위 분석을 참조하여 포트폴리오 관점에서 추가 의견을 제시하세요.`
  }
  return ctx
}
```

## 8. 고려 사항

- **응답 시간**: 파이프라인은 순차 호출이므로 응답 시간이 2배 증가한다. `previousAnalysis`를 1,000자 이하로 잘라 2단계 프롬프트 크기를 제한한다.
- **비용**: 파이프라인 1회 = Claude 호출 2회. 복합 의도 감지를 엄격하게 유지해 불필요한 파이프라인 실행을 방지한다.
- **스텝 한계**: 파이프라인 스텝을 최대 2단계로 제한한다. 3단계 이상은 UX 지연이 과도하다.
- **오류 처리**: 1단계가 실패하면 파이프라인을 중단하고 에러를 반환한다. 1단계 성공, 2단계 실패 시 1단계 결과만 반환한다.
- **패턴 확장**: `COMPOUND_PATTERNS`는 배열이므로 추후 패턴 추가가 용이하다. 단, 패턴이 많아지면 감지 오탐 가능성이 높아지므로 키워드를 구체적으로 유지한다.
