# 10.06.01 종목 탐색(Research) 현황 분석 및 개선 계획

작성일: 2026-05-14  
스프린트: 10.6.x

---

## 1. 현황 분석

### 1.1 페이지 구조

```
종목 탐색 (/research)
└── 검색창 (debounce 300ms)
    └── 검색 결과 그리드 (3열)
        └── SearchResultCard × N  ← 클릭 → /research/{ticker}

종목 상세 (/research/{ticker}?market={market})
├── 헤더 (뒤로가기, AI분석, 관심종목 추가)
├── 가격 정보 카드 (4개 — 현재가, 52주, 시총/거래량, 목표가)
├── 가격 차트 (라인↔캔들, 1w/1mo/3mo/6mo/1y)
├── 기업 개요 (섹터, 업종, 시총, 배당 등)
├── 재무 지표 (PER, PBR, ROE, 부채비율 등)
└── AI 채팅 패널 (리서치 번들 기반)
```

### 1.2 구현 현황

| 기능 영역 | 상태 | 비고 |
|----------|------|------|
| **텍스트 검색** | ✅ 완료 | IDB Master DB → 로컬 → Yahoo 3단계 폴백 |
| **종목 상세** | ✅ 완료 | 실시간 시세, 재무지표, 차트 |
| **가격 차트** | ✅ 완료 | 라인/캔들, 최대 5년, 기간 확장 |
| **AI 분석** | ✅ 완료 | 리서치 번들(시세+재무+뉴스+공시) |
| **관심종목 연동** | ✅ 완료 | 상세 페이지에서 추가/제거 |
| **탐색 홈 화면** | ❌ 없음 | 검색 전 빈 화면, 발견 경험 없음 |
| **최근 본 종목** | ❌ 없음 | 히스토리 미저장 |
| **최근 검색어** | ❌ 없음 | 검색창 자동완성 없음 |
| **섹터/테마 탐색** | ❌ 없음 | 브라우징 경로 없음 |
| **종목 비교** | ❌ 없음 | 단일 종목만 분석 가능 |
| **주식 스크리너** | ❌ 없음 | 조건 기반 검색 불가 |
| **기술적 지표 오버레이** | ❌ 없음 | 차트에 MA/RSI 등 미표시 |

### 1.3 UX 현황

**잘 된 것**
- 검색창 단일 진입점으로 UI 단순함
- 검색 결과 카드에 실시간 시세 포함 (개별 quote 호출)
- 종목 상세 페이지 정보 밀도 높음 (재무지표, 차트, AI 분석)
- 한국·미국 시장 동시 지원 (Naver + Yahoo Finance)
- 차트 에러 바운더리 격리 (전체 페이지 크래시 방지)

**UX 갭**
- 검색어 없을 때 빈 화면 — 무엇을 할 수 있는지 안내 없음
- 한 번 방문한 종목을 다시 찾으려면 재검색 필요
- 미국/한국 시장 필터 없어 "삼성" 검색 시 미국 ETF도 혼재
- 섹터나 테마로 종목을 발견하는 경로 없음
- 두 종목을 나란히 비교하는 기능 없음
- 차트에 보조 지표(이동평균 등) 없어 기술적 분석 제한

## 2. 기술 아키텍처 현황

### 2.1 데이터 흐름

```
검색 (3단계 폴백)
  1단계: IndexedDB Master DB (getAllStocks → 로컬 풀텍스트)
  2단계: 로컬 번들 종목 목록 (KRX/NASDAQ 요약본)
  3단계: Yahoo Finance 원격 검색 API

시세 조회
  KRX/KOSDAQ: Naver Finance API → fetchNaverQuote()
  NASDAQ/NYSE: Yahoo Finance v8 API → fetchYahooQuote()

재무 지표
  한국: Naver Finance → fetchNaverProfile()
  미국: Yahoo quoteSummary v2 → fetchYahooProfile()

차트 데이터
  한국: Naver 페이지네이션 (range 기반, 최대 5년)
  미국: Yahoo Finance (period1/period2 파라미터)
```

### 2.2 상태 관리

| 스토어 | 역할 | 영속화 |
|--------|------|-------|
| `useWatchlistStore` | 관심종목 + 알림 | localStorage (Zustand persist) |
| `useStockMasterStore` | IDB 메타데이터 (카운트, 동기화 시점) | localStorage |
| `useStockDbStore` | 폴백용 로컬 종목 목록 | localStorage |

> TanStack Query가 시세/재무/차트 서버 상태 캐싱 담당 (staleTime 5~10분)

### 2.3 API 한계

| 한계 | 내용 |
|------|------|
| Naver API | 날짜 파라미터 없음, range 방식만 지원 |
| Yahoo Finance | 한국 종목 PER/시총 간헐적 누락 |
| DART API | 공시 데이터 응답 지연 (1~3초) |
| 일괄 시세 조회 | 5건씩 배치 처리 → 대형 관심목록 시 지연 |

## 3. 벤치마크 분석

### 3.1 참고 시스템

| 시스템 | 핵심 강점 | 우리 앱 적용 포인트 |
|--------|----------|-------------------|
| **토스증권** | 테마 카드 피드, 최근 본 종목 | 홈 화면 테마·인기종목 |
| **네이버 금융** | 인기 검색어 Top10, 섹터 시세판 | 인기검색어 노출, 섹터 브라우징 |
| **카카오페이증권** | 최근 본 종목 (10개), 저장 리스트 | 최근 본 종목 히스토리 |
| **TradingView** | 차트 지표 오버레이, % 비교 차트 | MA 오버레이, 비교 기능 |
| **Morningstar** | 정량적 스크리너, 섹터 분류 체계 | AI 스크리너 참고 |
| **Investing.com** | 검색 결과 시장 탭 필터 | 한국/미국 탭 분리 |

### 3.2 핵심 발견

**발견 #1 — 탐색 홈 화면이 가장 큰 UX 갭**  
토스증권·네이버 금융 모두 검색창 아래에 인기 검색어/테마 카드를 배치한다. 현재 빈 화면은 신규 사용자 이탈 원인이다.

**발견 #2 — 최근 본 종목은 개인 투자자 필수 기능**  
카카오페이·토스 모두 최근 방문 종목 5~10개를 빠른 재진입 경로로 제공한다. 매일 같은 종목을 모니터링하는 개인 투자자에게 핵심 편의 기능이다.

**발견 #3 — 시장 필터로 검색 노이즈 제거**  
Investing.com은 검색 결과를 시장 탭으로 나눈다. "삼성" 검색 시 한국주·미국 ADR·ETF 혼재 문제를 탭 하나로 해결한다.

**발견 #4 — 종목 비교는 투자 의사결정 핵심 도구**  
TradingView 비교 차트(% 정규화)는 두 종목의 상대 수익률을 직관적으로 보여준다. 간단한 버전만으로도 가치가 충분하다.

**발견 #5 — AI 스크리너는 기존 인프라 활용 가능**  
외부 스크리너 API 없이 Claude에게 자연어 조건을 전달하고 관심종목·일지 컨텍스트를 주입하면 개인화된 종목 추천이 가능하다.

## 4. 개선 계획

### 4.1 우선순위 HIGH (Sprint 10.6.1)

#### A. 탐색 홈 화면 — Discovery Panel

**문제.** 검색어 없을 때 빈 화면. 사용자 발견 경험 전무.  
**해결.** 검색 전 상태에 세 가지 섹션 표시.  
**영향 파일.** `src/pages/Research.jsx`

```
탐색 홈 화면 구성 (query === '' 일 때 표시)
├── [최근 본 종목] 섹션 (최대 6개 칩)
│   └── 클릭 → navigate('/research/{ticker}?market={market}')
├── [인기 검색어] 섹션 (8~10개 태그)
│   └── 클릭 → setQuery(ticker)로 검색창 자동 채우기
└── [시장 요약] 섹션 (3개 카드 — KOSPI, NASDAQ, S&P500)
    └── useStockPrice('^KS11'|'^IXIC'|'^GSPC') 실시간 조회
```

인기 검색어는 초기에 하드코딩 상위 종목으로 시작한다 (AAPL, TSLA, 삼성전자, SK하이닉스, NVDA 등 10개). 추후 watchlist 추가 빈도 기반으로 동적화 가능.

**검증.**
- 검색어 지우면 Discovery Panel 재표시
- 최근 본 종목 칩 클릭 → 상세 페이지 정상 이동
- 시장 요약 카드 지수 실시간 갱신

---

#### B. 최근 본 종목 히스토리

**문제.** 종목 상세 방문 기록 미저장으로 재진입 시 재검색 필요.  
**해결.** 상세 페이지 진입 시 localStorage에 최대 10개 저장.  
**영향 파일.** `src/pages/Research.jsx` (읽기), 종목 상세 컴포넌트 (쓰기)

```js
// localStorage 키: 'recentlyViewedStocks'
// 저장 형식
[
  { ticker: 'AAPL', name: 'Apple Inc.', market: 'NASDAQ', visitedAt: '2026-05-14T10:30:00.000Z' },
  ...  // 최대 10개, 최신순 정렬
]
// 중복 진입 시: 기존 항목 제거 후 맨 앞에 재삽입 (visitedAt 갱신)
// 10개 초과 시: 배열 마지막 항목 제거
```

**검증.**
- 종목 상세 방문 후 탐색 홈 복귀 시 해당 종목 최근 본 목록 노출
- 동일 종목 재방문 시 중복 없이 맨 앞으로 이동
- 10개 초과 시 가장 오래된 항목 자동 제거

---

#### C. 검색 결과 시장 필터 탭

**문제.** "삼성" 검색 시 국내·미국 ETF·지수 혼재로 원하는 시장 찾기 어려움.  
**해결.** 검색 결과 상단에 시장 필터 탭 추가.  
**영향 파일.** `src/pages/Research.jsx`

```
[전체]  [한국 KRX·KOSDAQ]  [미국 NASDAQ·NYSE]  [ETF]
```

클라이언트 사이드 필터 (useStockSearch 결과를 market 필드로 걸러냄). 별도 API 호출 없음.

**검증.**
- 탭 전환 시 해당 시장 결과만 표시
- "전체" 탭은 기존과 동일하게 모든 결과 표시
- 필터 후 결과 0건 시 "해당 시장의 검색 결과가 없습니다" 안내

### 4.2 우선순위 MEDIUM (Sprint 10.6.2)

#### D. 종목 비교 기능

**문제.** 두 종목의 재무지표·수익률을 나란히 비교하는 기능 없음.  
**해결.** 종목 상세 페이지에 "비교 추가" 버튼, 비교 패널 슬라이드인.  
**영향 파일.** 종목 상세 컴포넌트, 신규 `src/components/research/StockComparePanel.jsx`

```
비교 패널 구성
├── 비교 종목 검색 (기존 useStockSearch 재사용)
├── 수익률 비교 차트 (Recharts LineChart)
│   ├── Y축: % 변화율 (첫날 = 0% 정규화)
│   ├── X축: 날짜
│   └── 기간 선택: 1mo / 3mo / 6mo / 1y
└── 지표 비교 테이블
    ├── 현재가 / 등락률
    ├── PER / PBR / ROE
    ├── 시가총액 / 52주 고저
    └── 배당수익률 (해당 시)
```

**검증.**
- 비교 종목 추가 후 수익률 차트에 두 선 표시
- 지표 테이블 숫자 정상 렌더링
- 비교 종목 제거 시 단일 뷰 복귀

---

#### E. AI 자연어 스크리너

**문제.** 조건 기반 종목 발견 불가. "배당 높은 국내 금융주 추천해줘" 불가능.  
**해결.** 탐색 홈에 AI 스크리너 입력창 추가, 기존 Claude API 연동.  
**영향 파일.** `src/pages/Research.jsx`, `src/agents/researchAgent.js`

```
AI 스크리너 입력 예시
- "PER 낮고 배당 있는 한국 금융주 추천해줘"
- "최근 52주 신저가 근접한 대형주"
- "내 관심종목과 비슷한 미국 반도체 종목"

처리 방식
1. 사용자 자연어 쿼리 → researchAgent buildResearchContext() 확장
2. watchlist 보유 정보 + 일지 심리 패턴 컨텍스트 주입
3. Claude 응답: 종목 목록 + 근거 + 면책 문구
4. 응답 내 ticker 파싱 → SearchResultCard 렌더링
```

**검증.**
- AI 응답에 ticker 포함 시 검색 결과 카드 변환 확인
- 면책 문구 항상 포함 여부 확인
- 응답 중 로딩 인디케이터 표시

---

### 4.3 우선순위 LOW (Sprint 10.6.3+)

#### F. 이동평균선 오버레이

**문제.** 차트에 보조 지표 없어 기술적 분석 불가.  
**해결.** 가격 차트에 MA(20일/60일) 토글 추가.  
**영향 파일.** 종목 상세 차트 컴포넌트

```
MA 계산: 기존 history 배열로 클라이언트 사이드 롤링 평균
토글: [MA20] [MA60] 체크버튼 — 체크 시 차트에 선 추가 (Recharts Line 추가)
```

#### G. 섹터/테마 브라우징

**문제.** 키워드 없이 섹터 전체 종목을 탐색하는 경로 없음.  
**해결.** 탐색 홈에 섹터 카드 그리드 추가.  
**영향 파일.** `src/pages/Research.jsx`

```
섹터 카드 (8개): 반도체 / AI·소프트웨어 / 금융 / 바이오 / 에너지 / 소비재 / 산업재 / ETF
클릭 → AI 스크리너에 섹터 키워드 자동 주입 (E 기능 연계)
```

#### H. 종목 메모/노트

**문제.** 관심종목 추가 전에도 개인 분석 메모를 남기고 싶은 경우 대응 불가.  
**해결.** 종목 상세 페이지에 로컬 메모 영역 추가.  
**영향 파일.** 종목 상세 컴포넌트

```js
// localStorage 키: 'stockNotes'
{
  'AAPL': { memo: '2026 AI 모멘텀 주시', updatedAt: '2026-05-14T10:30:00.000Z' },
  '005930': { memo: '반도체 사이클 저점 체크', updatedAt: '...' }
}
```
