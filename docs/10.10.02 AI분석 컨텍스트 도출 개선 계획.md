# AI분석 컨텍스트 도출 개선 계획

_작성일: 2026-05-20_

---

## 1. 현행 컨텍스트 도출의 구체적 문제

### 1-1. 에이전트와 무관하게 항상 전체 데이터를 조립

`AIChat.jsx`의 `context` 객체는 어떤 에이전트가 선택될지 모르는 상태에서 미리 구성된다.

```js
// AIChat.jsx L65-78 — 에이전트 결정 전에 모든 데이터 묶음
const context = useMemo(() => ({
  holdings: holdings.map(h => ({ ticker, name, quantity, avgPrice, currentPrice, market })),
  exchangeRate,
  watchlist: watchlist.map(w => ({ ticker, name, market })),
  journalEntries,   // 일지 전체 배열
  accounts,
}), [holdings, exchangeRate, watchlist, journalEntries, accounts])
```

- alert 에이전트가 선택돼도 holdings·journalEntries가 context에 포함된다.
- 각 에이전트 함수는 `context.watchlist`, `context.holdings` 등 필요한 것만 꺼내 쓰지만, 불필요한 데이터가 메모리에 항상 올라와 있다.
- 일지 건수가 수백 건이면 context 객체가 커지고 메모리 직렬화 부하가 생긴다.

### 1-2. alertAgent에 실시간 시세(quotesMap)가 전달되지 않음

```js
// claudeApi.js L204
case 'alert':
  contextText = buildAlertContext(context.watchlist || [], context.quotesMap || null)
  break
```

`context.quotesMap`은 AIChat.jsx에서 한 번도 채워지지 않는다 — 항상 `null`. 따라서 관심종목 브리핑을 요청해도 종목명·티커만 나열될 뿐 현재가·등락률·이상 신호 판별이 전혀 작동하지 않는다.

`buildAlertContext()`는 `quotesMap`이 있을 때 아래와 같이 이상 신호를 출력하도록 구현되어 있으나 실제로는 동작 불가 상태다.

```js
// alertAgent.js L62-64
if (Math.abs(pct) >= 10) parts.push(`🔴 긴급: ${Math.abs(pct).toFixed(1)}% 급등락`)
else if (Math.abs(pct) >= 5) parts.push(`🟡 주의: ...`)
```

### 1-3. reportAgent의 period가 항상 'monthly'로 고정

```js
// claudeApi.js L207
case 'report':
  contextText = buildReportContext(context.holdings || [], context.period || 'monthly', context.exchangeRate || null)
```

`context.period`는 AIChat.jsx에서 절대 채워지지 않는다. 사용자가 "이번 주 결산 해줘"라고 해도 monthly 컨텍스트가 빌드된다. `WEEKLY_REPORT_PROMPT`, `MONTHLY_REPORT_PROMPT` 분기가 있지만 systemPrompt 교체도 일어나지 않아 기간별 전용 프롬프트가 사실상 쓰이지 않는다.

### 1-4. changePercent가 context에서 누락되어 중복 fetchQuote 발생

```js
// AIChat.jsx L66-73 — changePercent 빠짐
holdings: holdings.map(h => ({
  ticker: h.ticker, name: h.name, quantity: h.quantity,
  avgPrice: h.avgPrice, currentPrice: h.currentPrice, market: h.market,
  // ← changePercent 없음
})),
```

analysis 경로 2(포트폴리오 분석)에서 changePercent가 없어서 각 종목마다 `fetchQuote`를 다시 호출한다.

```js
// claudeApi.js L137-152 — holdings 수만큼 fetchQuote 재호출
const [enrichedHoldings, news] = await Promise.all([
  Promise.all(context.holdings.map(async (h) => {
    const q = await fetchQuote(h.ticker, h.market)   // ← 보유 종목 N번 중복 호출
    return { ...h, changePercent: q?.changePercent ?? null }
  })),
  fetchNews('^GSPC', 'NYSE'),
])
```

처음부터 context에 changePercent를 포함했다면 이 루프가 필요 없다. 보유 종목이 10개면 10개 fetchQuote가 추가 발생한다.

### 1-5. journal 에이전트만 context를 system prompt에 임베드

```js
// journalCoachAgent.js L22-41
export function buildJournalCoachPrompt(journalContext) {
  return `당신은 ... 코치입니다.
아래는 사용자의 실제 매매 기록 데이터입니다:
${journalContext}    // ← 시스템 프롬프트 내부에 데이터 삽입
...`
}
```

다른 에이전트는 contextText를 user message에 붙여 전달하는 반면, journal만 system prompt에 삽입한다. 이 패턴은 멀티턴 대화 시 문제를 만든다. `sendWithHistory()`가 system prompt를 고정으로 보내기 때문에, 매 턴마다 system prompt에 일지 전체 데이터가 중복 전송된다.

### 1-6. 컨텍스트 크기 상한 관리 없음

journalEntries는 200건 이하면 전체가 그대로 직렬화된다. holdings도 개수 제한 없이 전달된다. Claude API max_tokens 설정(2048~4096)과 관계없이 입력 토큰이 커질수록 비용이 증가하고 응답 품질이 저하된다.

### 1-7. 에러 시 contextText를 무음으로 비움

```js
// claudeApi.js L210-212
} catch {
  contextText = ''   // 에러 원인 로그 없이 조용히 빔
}
```

실시간 API 호출 실패 시 어떤 데이터가 누락됐는지 Claude에게 알리지 않고 빈 문자열을 전달한다. Claude는 데이터 부재를 모르고 분석을 시도한다.

## 2. 현행 컨텍스트 문제 요약

| 문제 | 영향 에이전트 | 심각도 |
|---|---|---|
| 전체 데이터 항상 조립 | 전체 | 낮음 (기능 영향 없음, 메모리 낭비) |
| quotesMap 미전달 | alert | **높음** (이상 신호 판별 전혀 동작 안 함) |
| period 항상 'monthly' | report | **높음** (주간/연간 요청 무시) |
| changePercent 누락 → 중복 fetchQuote | analysis (경로 2) | 중간 (API 호출 낭비, 지연) |
| journal context = system prompt 임베드 | journal (멀티턴) | 중간 (토큰 중복) |
| 컨텍스트 크기 상한 없음 | journal, portfolio | 낮음 (비용 증가) |
| 에러 시 무음 처리 | analysis | 중간 (AI 오분석 유도 가능) |

## 3. 개선 방향

### 방향 A — 에이전트 선택 후 지연 컨텍스트 빌드 (Lazy Context)

에이전트가 결정된 후 해당 에이전트에 필요한 데이터만 선택적으로 조립한다.

**장점.** 불필요한 데이터 배제, 선택적 실시간 API 호출 가능.
**단점.** sendToAgent 내부 로직이 복잡해짐.

### 방향 B — context 스펙 명세화 + 필드 보강

현재 AIChat.jsx → sendToAgent 전달 구조는 유지하되, 각 에이전트가 필요로 하는 필드를 명세하고 AIChat.jsx에서 빠진 필드를 채운다.

**장점.** 변경 범위 최소, 빠른 적용.
**단점.** context 객체가 커질 수 있음.

### 방향 C — 하이브리드 (권장)

- **구조 변경 없이** 빠진 필드부터 채운다(방향 B).
- 에이전트 선택 후 해당 에이전트에서만 추가 fetch가 필요한 경우 실시간 조회를 수행한다(방향 A 부분 적용).
- 컨텍스트 크기 상한과 에러 알림만 공통으로 추가한다.

## 4. 항목별 개선 상세

### 4-1. changePercent를 context에 포함 (analysis 중복 fetch 제거)

**변경 파일.** `AIChat.jsx`

```js
// 변경 후 — Zustand store의 changePercent를 그대로 포함
holdings: holdings.map(h => ({
  ticker: h.ticker,
  name: h.name,
  quantity: h.quantity,
  avgPrice: h.avgPrice,
  currentPrice: h.currentPrice,
  changePercent: h.changePercent ?? null,   // ← 추가
  market: h.market,
})),
```

analysis 경로 2에서 changePercent가 null인 종목만 선택적으로 fetchQuote를 추가 호출하도록 조건을 추가한다.

```js
// claudeApi.js 변경 후 — 누락된 종목만 보충 조회
const enrichedHoldings = await Promise.all(
  context.holdings.map(async (h) => {
    if (h.changePercent !== null) return h           // 이미 있으면 재호출 없음
    try {
      const q = await fetchQuote(h.ticker, h.market)
      return { ...h, changePercent: q?.changePercent ?? null }
    } catch {
      return { ...h, changePercent: null }
    }
  })
)
```

### 4-2. alertAgent에 실시간 quotesMap 자동 주입

**변경 파일.** `claudeApi.js`

alert 에이전트가 선택됐을 때, watchlist 종목 전체 quote를 병렬 조회하여 quotesMap을 빌드한다.

```js
case 'alert': {
  const watchlist = context.watchlist || []
  let quotesMap = null

  if (watchlist.length > 0) {
    const quoteResults = await Promise.allSettled(
      watchlist.map(w => fetchQuote(w.ticker, w.market))
    )
    quotesMap = {}
    watchlist.forEach((w, i) => {
      if (quoteResults[i].status === 'fulfilled') {
        quotesMap[w.ticker] = quoteResults[i].value
      }
    })
  }

  contextText = buildAlertContext(watchlist, quotesMap)
  break
}
```

관심종목이 10개를 초과하면 병렬 호출 수가 많아질 수 있다. 10개를 초과할 경우 `5% 이상 등락` 유력 종목만 우선 조회하는 방식도 검토할 수 있으나, 1차 개선에서는 전체 조회로 구현한다.

### 4-3. reportAgent period 동적 추출

**변경 파일.** `claudeApi.js`

`sendToAgent` 내부 report case에서 사용자 메시지를 파싱해 period를 결정한다.

```js
case 'report': {
  const msg = userMessage.toLowerCase()
  let period = 'monthly'
  if (msg.includes('주간') || msg.includes('이번 주') || msg.includes('weekly')) period = 'weekly'
  else if (msg.includes('연간') || msg.includes('올해') || msg.includes('annual')) period = 'yearly'
  else if (msg.includes('일간') || msg.includes('오늘') || msg.includes('daily')) period = 'daily'

  contextText = buildReportContext(context.holdings || [], period, context.exchangeRate || null)

  // 기간별 전용 프롬프트 교체
  if (period === 'weekly') systemPrompt = WEEKLY_REPORT_PROMPT
  else if (period === 'monthly') systemPrompt = MONTHLY_REPORT_PROMPT
  break
}
```

### 4-4. journal context를 user message로 이동 (멀티턴 토큰 중복 해소)

**변경 파일.** `journalCoachAgent.js`, `claudeApi.js`

journal 에이전트도 다른 에이전트와 동일하게 contextText를 user message에 붙이는 패턴으로 통일한다.

```js
// 변경 전 — context가 system prompt에 임베드됨
export function buildJournalCoachPrompt(journalContext) {
  return `당신은 투자 심리 코치입니다.\n\n아래는 매매 기록:\n${journalContext}\n...`
}

// 변경 후 — system prompt는 역할 정의만, context는 별도 반환
export const JOURNAL_SYSTEM_PROMPT = `당신은 투자 매매 일지를 분석하는 투자 심리 코치입니다.
...역할 정의만...`

export function buildJournalContext(entries, accounts) { ... }  // 변경 없음
```

```js
// claudeApi.js 변경 후
case 'journal': {
  const entries = context.journalEntries || []
  const journalContext = entries.length > 200
    ? buildCompressedJournalContext(entries, context.accounts || [])
    : buildJournalContext(entries, context.accounts || [])
  systemPrompt = JOURNAL_SYSTEM_PROMPT   // 고정 시스템 프롬프트
  contextText = journalContext            // user message에 데이터 주입
  break
}
```

멀티턴 시 system prompt가 고정되므로 Anthropic prompt caching이 자동으로 적용 가능해진다.

### 4-5. 컨텍스트 크기 상한 (토큰 예산 관리)

**변경 파일.** 각 에이전트 `buildXxxContext()` 함수

journal의 경우 이미 200건 초과 시 압축 로직이 있다. 이를 다른 에이전트로 확장한다.

| 에이전트 | 현행 | 개선 |
|---|---|---|
| journal | 200건 초과 → 압축 | 유지 (현행 양호) |
| portfolio | 제한 없음 | 보유 종목 50개 초과 시 비중 상위 20개 + 합산 요약 |
| alert | 제한 없음 | 관심종목 30개 초과 시 상위 20개만 포함 |
| report | 제한 없음 | holdings 동일하게 portfolio 규칙 적용 |

## 8. 고려 사항

### alert quotesMap 조회 비용

관심종목 10개 기준 fetchQuote 10회 병렬 호출. 한국 종목은 Naver API, 해외는 Yahoo Finance 경유. Yahoo Finance는 429 발생 시 1초 재시도 로직이 이미 있다. 관심종목이 많을 경우 응답이 느려질 수 있으므로 30개 상한을 두는 것이 좋다.

### journal 패턴 변경과 멀티턴 호환성

`sendWithHistory()`는 현재 system prompt를 외부에서 받는다. `buildJournalCoachPrompt()`가 반환하던 system prompt를 `JOURNAL_SYSTEM_PROMPT` 상수로 교체하면 `AIChat.jsx`에서 직접 `buildJournalCoachPrompt`를 import하는 코드도 같이 수정해야 한다.

```js
// AIChat.jsx L16 — import 교체 필요
// 변경 전: import { buildJournalCoachPrompt, buildJournalContext } from '../agents/journalCoachAgent'
// 변경 후: import { JOURNAL_SYSTEM_PROMPT, buildJournalContext } from '../agents/journalCoachAgent'
```

### changePercent의 신선도

AIChat.jsx context에 포함하는 changePercent는 portfolioStore에서 마지막으로 갱신된 시점 기준이다. 이는 마지막 quote 조회 시점과 차이가 있을 수 있다. 분석 시 "데이터 기준 시점"을 context에 함께 명시하는 것이 좋다.

```js
// 개선 예시 — context에 데이터 기준 시각 포함
contextText += `\n[데이터 기준: ${new Date().toLocaleString('ko-KR')}]\n`
```
