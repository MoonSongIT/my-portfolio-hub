# 13.02.03 수동 체크 방법

> 작성일: 2026-06-01
> 버전: 1.0
> 구현 참조: `docs/13.02.02 데이타 동기화 시점 체크리스트.md`

---

## 사전 준비

```
npm run dev  (로컬 개발 서버 실행)
```

앱 로그인 후 **설정 → 동기화** 에서 **동기화 활성화** 를 켠다.
동기화가 꺼져 있으면 S-1 이탈 가드가 동작하지 않는다.

---

## S-1: 이탈 팝업 체크

### T1 — 페이지 이동 시 팝업 표시

```
1. 매매일지 페이지에서 매매 1건 입력 후 저장
   (서버 업로드는 하지 않은 상태 유지)
2. 좌측 메뉴에서 다른 페이지(예: 포트폴리오) 클릭
3. ✅ "저장되지 않은 변경사항" 모달 표시 확인
   - "변경사항이 N개 있습니다." 문구 표시
   - 버튼 3개: [업로드 후 이동] / [그냥 이동] / [취소]
```

### T2 — [업로드 후 이동] 성공

```
1. T1 상태에서 [업로드 후 이동] 클릭
2. ✅ 버튼 비활성화 + 스피너 + "업로드 중..." 표시
3. ✅ 완료 후: 우하단 "N개 항목이 서버에 저장되었습니다." 초록 토스트
4. ✅ 모달 닫힘 + 목적지 페이지로 이동
5. Supabase Dashboard → Table Editor → transactions
   → 방금 입력한 레코드 존재 확인
```

### T3 — [업로드 후 이동] 실패 (오류 메시지)

```
1. DevTools(F12) → Network 탭 → 우상단 🚫 Offline 클릭 (네트워크 차단)
2. 매매 1건 입력 후 다른 페이지 이동 시도
3. [업로드 후 이동] 클릭
4. ✅ 모달 안에 빨간 오류 메시지 표시
   - "서버 업로드에 실패했습니다."
   - 오류 원인 (네트워크 오류 또는 HTTP 상태코드)
   - "변경사항은 로컬 저장소에 보존되어 있습니다." 문구
5. ✅ [그냥 이동] / [취소] 버튼 다시 활성화됨
6. Network → Offline 체크 해제 후 정상화
```

### T4 — [그냥 이동]

```
1. T1 상태에서 [그냥 이동] 클릭
2. ✅ 업로드 없이 목적지 페이지로 이동
3. DevTools → Application → IndexedDB → PortfolioHub → transactions
   → 방금 입력한 레코드의 syncedAt 값이 null 인지 확인
   (null = 로컬에만 저장됨, 서버 미업로드 상태)
```

### T5 — [취소]

```
1. T1 상태에서 [취소] 클릭
2. ✅ 모달 닫힘
3. ✅ 현재 페이지 유지 (이동 없음)
```

### T6 — 미동기화 없을 때 팝업 미표시

```
1. 설정 → 동기화 → "지금 업로드" 클릭 (전체 업로드 완료)
2. 좌측 메뉴에서 다른 페이지 클릭
3. ✅ 팝업 표시되지 않고 즉시 이동
```

### T7 — 브라우저 탭 닫기 확인창

```
1. 미동기화 레코드 있는 상태에서
2. 브라우저 탭 X 버튼 클릭 또는 Ctrl+W
3. ✅ 브라우저 기본 확인창 표시
   "변경사항이 있습니다. 이 페이지를 나가시겠습니까?"
   (커스텀 문구 아님 — 브라우저 정책상 기본 문구만 표시됨)
```

### T8 — 앱 새로고침 후 pendingChanges 정확성

```
1. 미동기화 레코드 N건 있는 상태에서 F5 새로고침
2. DevTools 콘솔에서 실행:
   JSON.parse(localStorage.getItem('sync-storage'))?.state?.pendingChanges
3. ✅ N과 일치하는지 확인
```

## S-2: 증분 다운로드 체크

### T1 — 최초 기기 전체 다운로드

```
1. 기존 기기에서 서버 업로드 완료 상태 확인
   (Supabase Dashboard → transactions 테이블에 데이터 있음)
2. 크롬 시크릿 탭(Ctrl+Shift+N) 또는 다른 브라우저에서 앱 접속
3. 동일 계정으로 로그인
4. ✅ 로그인 직후 우하단 초록 토스트:
   "서버에서 N개 항목을 받아왔습니다."
5. DevTools → IndexedDB → transactions 테이블에 데이터 존재 확인
```

### T2 — 기존 기기 재로그인 증분 다운로드

```
1. 기기A에서 로그인 + 서버 업로드 완료
   (localStorage에 lastSyncedAt 기록됨)
2. 기기B(시크릿 탭 또는 다른 브라우저)에서
   - 매매 1건 입력 후 서버 업로드
3. 기기A에서 로그아웃 → 재로그인
4. ✅ 파란 info 토스트:
   "서버에서 1개 변경사항을 받아왔습니다."
5. 매매일지 페이지에서 기기B에서 추가한 항목 표시 확인
```

**lastSyncedAt 확인 방법 (DevTools 콘솔).**
```javascript
JSON.parse(localStorage.getItem('sync-storage'))?.state?.lastSyncedAt
```

### T3 — 변경 없을 때 토스트 없음

```
1. 기기A에서 로그인 후 업로드 완료
2. 다른 기기에서 아무 변경 없음
3. 기기A에서 로그아웃 → 재로그인
4. ✅ 동기화 관련 토스트 표시되지 않음 (조용히 완료)
```

### T4 — 다운로드 실패 시 warning 토스트

```
1. DevTools → Network → Offline 설정
2. 시크릿 탭에서 앱 로그인
3. ✅ "서버 동기화에 실패했습니다. 로컬 데이터로 계속합니다." 노란 경고 토스트
4. ✅ 앱 정상 동작 (로컬 데이터 표시)
5. Network → Offline 해제
```

## 콘솔 디버깅 참고

개발 환경에서는 `window.__sync` 로 syncService 에 직접 접근할 수 있다.

```javascript
// 미동기화 레코드 건수 확인
await window.__sync.countPendingRecords()

// 전체 업로드
await window.__sync.uploadAll()

// 증분 다운로드 (since = 30분 전)
const since = new Date(Date.now() - 30 * 60 * 1000).toISOString()
await window.__sync.downloadAllDelta(since)

// syncStore 상태 전체 확인
JSON.parse(localStorage.getItem('sync-storage'))
```
