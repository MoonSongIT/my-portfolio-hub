## 단계 1 — 환경 준비 확인

### 1-A. Vercel 배포

```
1. 현재 브랜치를 git push
   git push origin <브랜치명>
2. Vercel Dashboard → Deployments 탭에서 배포 상태 확인
3. 상태가 Ready 로 바뀌면 Preview URL 복사
```

- [x] Supabase DB — 4개 테이블 존재 확인 (`transactions`, `cash_flows`, `calendar_events`, `watchlist`)
- [x] 모든 테이블 RLS 활성화 (pg_tables 쿼리로 rowsecurity=true 확인)
- [ ] Vercel Dashboard → 배포 상태 **Ready** 확인
- [ ] Vercel Preview URL 브라우저 접속 가능 확인

### 1-B. Vercel 환경변수 확인

Vercel Dashboard → 프로젝트 → Settings → Environment Variables

- [ ] `VITE_SUPABASE_URL` 등록 확인 (Production + Preview)
- [ ] `VITE_SUPABASE_ANON_KEY` 등록 확인 (Production + Preview)
- [ ] `SUPABASE_SERVICE_ROLE_KEY` 등록 확인 (Production + Preview, `VITE_` 접두사 없음)

### 1-C. Supabase OAuth 콜백 URL 등록 (Google 로그인 테스트 시)

Supabase Dashboard → Authentication → URL Configuration

- [ ] Redirect URLs에 `https://<preview-url>/auth/callback` 추가

## 단계 2 — 인증 흐름

### 2-A. 이메일 가입 및 로그인

```
1. 앱 접속 → 우상단 [로그인] 버튼 클릭
2. SupabaseLoginModal → [회원가입] 모드 전환
3. 이메일/비밀번호 입력 → [가입하기] 클릭
4. 이메일 인증 링크 클릭 후 인증 완료
5. 다시 [로그인] → 이메일/비밀번호 입력 → 로그인
```

- [ ] 로그인 성공 후 모달 닫힘
- [ ] 헤더에 동기화 아이콘 표시 (초록 Cloud)
- [ ] 설정 페이지 → Supabase 연결 섹션에 이메일 표시

### 2-B. 로그아웃 및 재로그인

```
1. 좌측 메뉴 → [설정] → [로그아웃] 버튼 클릭
2. 다시 [로그인] → 동일 계정으로 재로그인
```

- [ ] 로그아웃 후 관리자 섹션 사라짐
- [ ] 재로그인 후 관리자 섹션 자동 복원

### 2-C. Google OAuth (선택)

```
1. 로그인 모달 → [Google로 로그인] 클릭
2. Google 계정 선택
3. /auth/callback 처리 후 앱으로 복귀
```

- [ ] Google 로그인 후 헤더 동기화 아이콘 표시
- [ ] DevTools → Application → Local Storage → supabase 세션 존재 확인

## 단계 5 — 이탈 시 업로드 팝업 (PendingUploadModal)

### 5-T1. 미동기화 레코드 있을 때 페이지 이동 시 모달 표시

```
1. 매매일지에서 매매 1건 입력 (서버 업로드 전 상태)
2. 좌측 메뉴에서 다른 페이지 클릭
```

- [ ] PendingUploadModal 표시
- [ ] "서버에 저장되지 않은 변경사항이 N개 있습니다." 문구 표시
- [ ] 버튼 3개 표시: [업로드 후 이동] / [그냥 이동] / [취소]

### 5-T2. [업로드 후 이동] — 성공 케이스

```
1. PendingUploadModal → [업로드 후 이동] 클릭
```

- [ ] 버튼 비활성화 + 스피너 + "업로드 중..." 표시
- [ ] 업로드 완료 후 성공 토스트 ("N개 항목이 서버에 저장되었습니다.")
- [ ] 모달 닫힘 + 목적지 페이지로 이동
- [ ] Supabase Dashboard Table Editor에서 해당 레코드 확인

### 5-T3. [업로드 후 이동] — 실패 케이스 (오프라인)

```
1. DevTools → Network 탭 → "Offline" 선택
2. PendingUploadModal → [업로드 후 이동] 클릭
```

- [ ] 인라인 오류 메시지 표시 (에러 원인 포함)
- [ ] "변경사항은 로컬 저장소에 보존되어 있습니다." 문구 표시
- [ ] 버튼 재활성화

> ⚠️ 테스트 후 Network 탭을 반드시 "Online"으로 복원.

### 5-T4. [그냥 이동] 버튼

```
1. PendingUploadModal → [그냥 이동] 클릭
```

- [ ] 업로드 없이 목적지 페이지로 이동
- [ ] DevTools IDB → syncedAt=null 레코드 유지됨

### 5-T5. [취소] 버튼

```
1. PendingUploadModal → [취소] 클릭
```

- [ ] 모달 닫힘
- [ ] 현재 페이지 유지 (이동 없음)

### 5-T6. 미동기화 레코드 없을 때 모달 미표시

```
1. 설정 → [지금 동기화] 클릭 (또는 업로드 완료 상태 확인)
2. 좌측 메뉴에서 다른 페이지 클릭
```

- [ ] 모달 표시 없이 즉시 이동

### 5-T7. 브라우저 탭 닫기 — 기본 확인창

```
1. 미동기화 레코드 있는 상태에서 브라우저 탭 X 버튼 클릭
```

- [ ] 브라우저 기본 "페이지에서 나가시겠습니까?" 확인창 표시

## 단계 6 — 다중 기기 동기화

### 6-T1. 기기 A → 기기 B 데이터 전파

```
기기 A (일반 탭):
1. 매매일지에서 매매 2건 입력
2. 페이지 이동 → PendingUploadModal → [업로드 후 이동]
3. 업로드 완료 확인

기기 B (시크릿 탭):
4. 동일 계정으로 로그인
5. 로그인 후 토스트 확인
6. 매매일지 페이지에서 기기 A 데이터 2건 표시 확인
```

- [ ] 기기 B 로그인 후 "서버에서 N개 항목을 받아왔습니다." 토스트 표시
- [ ] 기기 B 매매일지에서 기기 A 입력 데이터 표시

### 6-T2. 재로그인 — 증분 다운로드

```
1. 기기 B에서 매매 1건 추가 → 업로드 완료
2. 기기 A에서 로그아웃 → 재로그인
```

- [ ] "서버에서 1개 변경사항을 받아왔습니다." info 토스트 표시
- [ ] 기기 A 매매일지에서 기기 B 추가 데이터 표시

### 6-T3. 재로그인 — 변경사항 없을 때 조용히 완료

```
1. 기기 A에서 아무 변경 없이 로그아웃 → 재로그인
```

- [ ] 토스트 메시지 없이 조용히 완료

- [ ] 동기화 완료 후 아이콘 초록색 복원

## 단계 8 — 보안 검증

### 8-S1. AI 키 비동기화 (필수)

```
1. 기기 A에서 설정 → AI API 키 입력 및 저장
2. 기기 B (시크릿 탭) 동일 계정으로 로그인
3. 기기 B 설정 페이지 확인
```

- [ ] 기기 B 설정에서 기기 A의 AI API 키 표시 안 됨

### 8-S2. RLS 차단 검증 (필수)

```
1. 테스트 계정 B로 로그인 (또는 계정 A JWT 토큰을 계정 B 토큰으로 교체)
2. DevTools 콘솔에서 직접 API 호출:
   fetch('/api/sync/download?table=transactions', {
     headers: { Authorization: 'Bearer <다른_계정_JWT>' }
   }).then(r => r.json()).then(console.log)
```

- [ ] 반환 데이터에 다른 계정 레코드 포함되지 않음

### 8-S3. 클라이언트 번들에 Service Role Key 미노출

```
1. Chrome DevTools → Sources 탭
2. Ctrl+Shift+F → "service_role" 검색
```

- [ ] 빌드된 JS 파일에서 Service Role Key 미발견

## 단계 9 — 운영 배포

테스트 전 항목 통과 후 운영 환경에 배포한다.

**방법 A — main 브랜치 머지 (권장)**

```
1. PR 생성: 현재 브랜치 → develop → main
2. 코드 리뷰 후 머지
3. Vercel이 main 브랜치를 자동으로 운영 배포
4. Vercel Dashboard → Deployments → Production 상태 Ready 확인
```

**방법 B — Vercel CLI 직접 운영 배포**

```powershell
vercel --prod
```

- [ ] 운영 배포 상태 **Ready** 확인
- [ ] 운영 URL 브라우저 접속 가능 확인
