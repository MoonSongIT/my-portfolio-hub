# 자금관리 섹터 분석 및 개선 계획

## Context

자금관리(CashFlow) 기능의 현재 구현 상태를 전수 분석하고, 발견된 버그·UX 문제·누락 기능을 정리한다.
특히 입금 항목의 카테고리 부재가 수익률 계산 정확도에 미치는 영향이 핵심 문제로 확인되었다.

### 관련 파일 목록

| 파일 | 역할 |
|------|------|
| `src/store/cashFlowStore.js` | 입출금 상태 관리 (핵심 스토어) |

### 데이터 흐름

```
수동 입출금 (CashFlowModal)
  └─ cashFlowStore.addCashFlow()
        └─ IndexedDB (cashFlows 테이블)

자동 입출금 (매매 연동)
  └─ journalStore.addEntry()
        └─ cashFlowStore.addAutoFlow()
              └─ IndexedDB (linkedJournalId ↔ linkedCashFlowId)

잔고 계산
  └─ cashFlowStore.getRunningBalance(accountId)
        └─ 모든 cashFlow를 날짜 오름차순 정렬 후 누계
              └─ getAvailableCash() → 마지막 balance 반환

총자산 계산
  └─ calculator.calculateTotalValue(holdings, cashKRW, cashUSD, exchangeRate)
        └─ 주식 평가액 + 현금(KRW + USD × 환율)
```

### 현재 데이터 구조

```js
// cashFlow 항목 (cashFlowStore.js)
{
  id: 'uuid',
  type: 'deposit' | 'withdrawal',   // ← 두 가지뿐
  amount: 1000000,
  currency: 'KRW' | 'USD',
  date: '2026-05-12',
  accountId: 'uuid',
  isAuto: false,                     // true면 매매 연동 자동 항목
  memo: '',
  userId: 'uuid',
  createdAt: 'ISO8601',
}
```

## 발견된 버그

### [BUG-1] 다중 통화 잔고 혼합 ⚠️ 높음

**파일:** `src/store/cashFlowStore.js:178`

```js
// 현재 코드 — KRW/USD 구분 없이 단순 합산
balance += f.type === 'deposit' ? f.amount : -f.amount
```

**문제:** `accountId === 'all'`로 전체 조회 시 KRW 금액과 USD 금액을 환율 변환 없이 더함.
예를 들어 KRW 1,000,000 입금 + USD 1,000 입금을 합산하면 2,000,000으로 잘못 표시.

**영향:** AvailableCashCard의 "투자 가능 금액", Dashboard의 현금 KPI가 전체 계좌 보기 시 왜곡.

**수정 방향:** 통화별로 분리 계산하거나, USD를 현재 환율로 KRW 환산 후 합산.

**수정 방향:** 카드 헤더나 레이블에 "수동 입출금 합계" 설명 추가, 또는 집계 기준 통일.

### [BUG-4] 버전 업 시 데이터 전손 위험 ⚠️ 높음

**파일:** `src/store/cashFlowStore.js:186-187`

```js
version: 3,
migrate: () => ({ cashFlows: [] }),   // ← 버전 변경 시 전체 삭제
```

버전이 바뀌면 localStorage가 초기화되는데, IndexedDB가 정식 저장소이므로 localStorage 손실은 무관하다.
그러나 버전을 잘못 올리거나 IDB 마이그레이션과 타이밍이 맞지 않으면 메모리 상태가 빈 배열로 시작할 수 있음.

**수정 방향:** `migrate` 함수에 IDB에서 재로드하는 fallback 추가 또는 migrate 로직을 명시적으로 작성.

## 핵심 개선 제안

### [P0] 입금 카테고리 구분 — 수익률 정확도의 핵심

**현재 문제:**

`type: 'deposit'`은 성격이 전혀 다른 항목들을 하나로 묶음.

| 현재 type | 실제 의미 | 수익률 분모 포함 여부 |
|-----------|----------|---------------------|
| `deposit` | 순수 투자금 유입 | ✅ 포함해야 함 |
| `deposit` | 배당금 수령 | ❌ 포함하면 수익률 왜곡 |
| `deposit` | 이자/CMA 수익 | ❌ 포함하면 수익률 왜곡 |
| `deposit` | 조정(+) | ❌ 포함하면 안 됨 |
| `withdrawal` | 순수 출금 | ✅ 포함해야 함 |
| `withdrawal` | 수수료/세금 | 별도 집계 필요 |
| `withdrawal` | 조정(-) | ❌ 포함하면 안 됨 |

**제안하는 카테고리 구조:**

```js
export const CASH_FLOW_CATEGORIES = {
  // 입금 계열
  INVESTMENT_IN:  { code: 'investment_in',  label: '투자금 입금', type: 'deposit',    isCapital: true  },
  DIVIDEND:       { code: 'dividend',       label: '배당금',      type: 'deposit',    isCapital: false },
  INTEREST:       { code: 'interest',       label: '이자/기타',   type: 'deposit',    isCapital: false },
  ADJUST_PLUS:    { code: 'adjust_plus',    label: '조정(+)',     type: 'deposit',    isCapital: false },

  // 출금 계열
  INVESTMENT_OUT: { code: 'investment_out', label: '투자금 출금', type: 'withdrawal', isCapital: true  },
  FEE_TAX:        { code: 'fee_tax',        label: '수수료/세금', type: 'withdrawal', isCapital: false },
  ADJUST_MINUS:   { code: 'adjust_minus',   label: '조정(-)',     type: 'withdrawal', isCapital: false },
}
```

**isCapital 플래그의 역할:**
- `isCapital: true` → 수익률 계산 분모(순 투자원금)에 포함
- `isCapital: false` → 현금 잔고에는 영향, 수익률 분모에서 제외

**수익률 계산 개선 효과:**

```
현재:  수익률 = 평가금액 / (전체 입금 합계 - 전체 출금 합계)

개선:  투자 수익률 = 평가금액 / (투자금 입금 합계 - 투자금 출금 합계)
       배당 수익률 = 배당금 합계 / 투자원금
       종합 수익률 = (미실현손익 + 실현손익 + 배당금) / 투자원금
```

**데이터 마이그레이션 전략:**
기존 `deposit` 항목 → 기본값 `investment_in`으로 일괄 변환.
기존 `withdrawal` 항목 → `investment_out`으로 변환.
사용자가 이후 개별 항목을 올바른 카테고리로 수정 가능.

**영향받는 파일:**
- `src/store/cashFlowStore.js` — `CASH_FLOW_CATEGORIES` 추가, `addCashFlow` 파라미터 확장
- `src/components/portfolio/CashFlowModal.jsx` — 카테고리 선택 UI 추가
- `src/utils/calculator.js` — 수익률 분모 계산 로직 개선
- `src/store/cashFlowStore.js` — `getTotalDeposit` 등 셀렉터에 `isCapital` 필터 옵션 추가

## 기타 관찰 사항

- `persist` 미들웨어가 `partialize: () => ({})`로 설정되어 localStorage에 아무것도 저장하지 않음.
  IndexedDB가 정식 저장소이므로 의도된 설계이나, 앱 첫 로드 시 IDB 로드 완료 전 빈 상태로 렌더링되는 깜빡임 가능성 있음.

- `moveCashFlowsByAccount` 함수가 구현되어 있으나 현재 UI에서 사용하는 곳이 없음.
  계좌 병합 시나리오를 위한 준비 코드로 보임.
