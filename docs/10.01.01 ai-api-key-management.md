# AI API Key 관리 기능 설계서

> 작성일: 2026-05-06
> 대상: my-portfolio-hub (React 18 + Vite + Zustand + IndexedDB)
> 관련 파일: `src/api/claudeApi.js`, `src/pages/Settings.jsx`, `src/store/settingsStore.js`

---

## 1. 개요

### 1.1 배경

현재 my-portfolio-hub의 AI 기능(JournalCoach, Research, Portfolio, Alert, Report 5개 에이전트)은
서버사이드 프록시(`VITE_API_BASE_URL`)에 등록된 **공용 Anthropic API Key**로 동작한다.
사용자가 자신의 키를 직접 등록·관리할 수 없고, 키 사용량/비용 모두 운영자가 부담하는 구조다.

### 1.2 목표

- 사용자가 **본인 소유의 Anthropic API Key를 브라우저에 안전하게 저장**하고, AI 기능 호출 시 자동으로 사용
- AI 기능 진입 시 키 미등록 사용자에게 **명확한 안내 팝업** 제공 (Settings 진입 유도)
- **키 유효성 검증**(API 테스트 호출)과 **마스킹/삭제** UX 제공
- 기존 공용 프록시 fallback 호환성 유지 (선택)

### 1.3 비목표 (Out of Scope)

- OpenAI/Gemini 등 다중 프로바이더 지원 (이번 단계는 Anthropic 단일)
- 다중 키 프로파일 관리 (사용자별 단일 키)
- 서버사이드 키 검증 강화 (브라우저 단 검증으로 시작)

## 2. 보안 저장 방식 결정

### 2.1 저장소 비교

| 항목 | localStorage | sessionStorage | IndexedDB | 메모리 (Zustand) |
|------|--------------|----------------|-----------|--------------------|
| 영속성 | 영구 | 탭 종료 시 삭제 | 영구 | 새로고침 시 삭제 |
| 동기 API | O | O | X (비동기) | O |
| 용량 | ~5MB | ~5MB | ~수백MB | RAM |
| XSS 노출 | **고위험** | **고위험** | **고위험** | **고위험** |
| Service Worker 접근 | X | X | O | X |
| 적합도 | △ (단순) | X (휘발성 과함) | O (앱 전체 IDB 사용 중) | △ (보조) |

> **핵심 결론**: 브라우저 환경에서는 **어떤 저장소도 XSS로부터 안전하지 않다**.
> JS가 읽을 수 있는 모든 영역은 악성 스크립트가 동일하게 읽을 수 있다.
> 따라서 저장소 선택보다 **(a) XSS 방지 (b) 암호화 (c) 사용자에게 위험 고지**가 우선이다.

### 2.2 업계 관행

- **OpenAI Playground / Anthropic Console**: 본인 계정 인증 후 서버에 보관, 브라우저에 노출하지 않음.
- **클라이언트-only 도구 (TypingMind, LibreChat 데스크톱, Cursor 무료티어 등)**:
  대부분 **localStorage 또는 IndexedDB에 평문 저장** + "본인 디바이스에만 저장됨" 안내.
  일부는 사용자 패스워드 기반 AES 암호화 (Web Crypto API) 추가.
- **Vercel AI SDK 데모**: 환경변수 기반, 사용자 키 미지원.

### 2.3 암호화 옵션 (Web Crypto API)

브라우저 표준 `crypto.subtle`로 AES-GCM 암호화 가능.
단, **암호화 키 자체를 어디 저장할지가 본질적 난제**:

1. **앱 하드코딩 키로 암호화** → 의미 없음 (코드만 보면 풀림)
2. **사용자 패스워드 PBKDF2 기반** → 매 사용 시 입력 필요 (UX 저하)
3. **무암호화 + 명확한 위험 고지** → 단순, 업계 표준

### 2.4 결정

**IndexedDB(Dexie) + 평문 저장 + 사용자 위험 고지 + 향후 선택적 PBKDF2 암호화 옵션 제공**

이유:
- 프로젝트 표준 저장소가 이미 IndexedDB(Dexie). 일관성 유지.
- localStorage 대비 동일 보안 수준이지만 용량/구조 확장성 우수.
- Service Worker 활용 가능성 (오프라인 대응).
- 평문 저장 시 명시적 경고 문구 + "내 키는 이 브라우저에만 저장됩니다" 고지.
- 패스워드 기반 암호화는 v2 마이그레이션 옵션으로 구조만 열어둠.

> ⚠️ 만약 **공유 PC 사용 시나리오**가 비중 있다면 sessionStorage 옵션을 추가할 수 있음.
> 본 앱은 개인 투자자용이므로 영속 저장 default가 합리적.

## 3. 기능 요구사항

### 3.1 설정 페이지 키 관리 UI

위치: `src/pages/Settings.jsx` 내 신규 섹션 "AI 설정"

**구성 요소:**

| 요소 | 설명 |
|------|------|
| 키 입력 input | `type="password"` + 토글 버튼(눈 아이콘)으로 평문 보기 |
| 마스킹 표시 | 저장된 키는 `sk-ant-•••••••••••XXXX` (앞 7자 + 뒤 4자) 형태로 표시 |
| 저장 버튼 | 입력값 검증 후 저장 (검증 실패 시 저장 거부) |
| 검증 버튼 | 저장된 키로 테스트 호출 → 성공/실패 토스트 |
| 삭제 버튼 | 확인 다이얼로그 후 IDB에서 제거 |
| 상태 뱃지 | "미설정" / "검증 완료 ✓ (yyyy-mm-dd)" / "검증 실패" |
| 위험 고지 | `이 키는 본인 브라우저(IndexedDB)에만 저장됩니다. 공유 PC 사용을 피하세요.` |
| 도움말 링크 | Anthropic Console로 이동 (https://console.anthropic.com/settings/keys) |

### 3.2 키 유효성 검증

**클라이언트측 형식 검증** (저장 전):
- prefix `sk-ant-` 시작
- 총 길이 60자 이상 (현재 Anthropic 키 형식 기준; 변동 가능성 있어 경고만, 차단은 안 함)

**API 테스트 호출** (검증 버튼 클릭 시):
- 프록시 서버에 신규 엔드포인트 `POST /api/claude/validate` 추가
  - body: `{ apiKey }` (HTTPS 전제)
  - 서버: `claude-haiku-4-5` 모델로 max_tokens=1, "ping" 메시지 → 200 OK 시 유효
- 또는 기존 `/api/claude` 엔드포인트가 사용자 제공 키를 헤더로 받도록 확장
- 응답 401 → 무효 / 200 → 유효 / 기타 → 네트워크 오류 안내
- 검증 결과(`isValid`, `validatedAt`)를 IDB에 함께 저장

### 3.3 AI 기능 사용 시 키 체크 & 안내 팝업

**진입 지점 (현 코드 기준):**
- `src/pages/Chat.jsx` (또는 `src/components/chat/ChatPanel.jsx`)
- `src/pages/Reports.jsx` AI 분석 버튼
- `src/pages/Research.jsx` 종목 분석 트리거
- 일지 코치 호출 지점

**가드 흐름:**
1. AI 호출 진입 직전에 `useApiKeyGuard()` 커스텀 훅 호출
2. 키가 없으면 **모달 다이얼로그** 노출:
   - 제목: "AI 기능을 사용하려면 API 키가 필요합니다"
   - 본문: 비용 안내 + Anthropic 가입 안내
   - 버튼: [설정 페이지로 이동] / [취소]
3. 키가 있고 마지막 검증 실패 상태면 **경고 토스트** + "재검증" CTA
4. 키가 정상이면 그대로 호출 진행

## 4. 구현 설계

### 4.1 데이터 저장 구조

Dexie 테이블 신규 추가 (`src/db/db.js` 등 기존 Dexie 정의 파일):

```js
// 테이블명: aiCredentials
// PK: provider (단일 행 보장 — 'anthropic' 고정)
{
  provider: 'anthropic',     // string PK
  apiKey: 'sk-ant-...',       // string (평문, v1)
  encrypted: false,           // boolean (v2 확장 대비)
  isValid: true,              // boolean | null
  validatedAt: '2026-05-06T...', // ISO string | null
  lastUsedAt: '2026-05-06T...',  // ISO string | null
  createdAt: '2026-05-06T...',
  updatedAt: '2026-05-06T...',
}
```

> 단일 프로바이더 단일 키 정책. 향후 OpenAI 추가 시 `provider`별 행 추가로 확장.

### 4.2 Zustand 스토어 설계

신규 파일: `src/store/aiCredentialStore.js`

```js
// 상태
{
  apiKey: string | null,         // 메모리 캐시 (IDB hydration 후 채워짐)
  isValid: boolean | null,
  validatedAt: string | null,
  isLoading: boolean,
  isHydrated: boolean,           // IDB 로드 완료 여부

  // 액션
  hydrate: () => Promise<void>,           // 앱 시작 시 IDB → 메모리
  setApiKey: (key) => Promise<void>,      // 형식 검증 + IDB 저장
  validateKey: () => Promise<{ok, msg}>,  // 프록시 /validate 호출
  clearKey: () => Promise<void>,          // IDB 삭제 + 상태 리셋
  hasKey: () => boolean,                  // 셀렉터
}
```

> Zustand `persist` 미들웨어 대신 **수동 hydrate** — IDB는 비동기이므로.
> `App.jsx` 마운트 시 `useAiCredentialStore.getState().hydrate()` 1회 호출.

### 4.3 컴포넌트 구조

**신규 컴포넌트:**

```
src/components/settings/
└── AiKeyPanel.jsx              ← Settings 페이지 신규 섹션 본체
    ├─ 입력/표시 토글
    ├─ 저장/검증/삭제 버튼
    └─ 위험 고지 + 도움말 링크

src/components/common/
└── ApiKeyRequiredDialog.jsx    ← 글로벌 안내 모달
    ├─ "API 키가 필요합니다" 안내
    └─ Settings로 이동 버튼

src/hooks/
└── useApiKeyGuard.js           ← AI 호출 전 가드 훅
    ├─ ensureKey(): Promise<boolean>
    └─ 키 없으면 모달 띄우고 false 반환
```

**기존 수정:**

- `src/pages/Settings.jsx` → `<AiKeyPanel />` 섹션 삽입
- `src/api/claudeApi.js` → 모든 axios 호출에 `X-User-Api-Key` 헤더 자동 첨부 (interceptor)
- AI 호출 진입점들 (`ChatPanel`, `Reports`, `Research`, journal coach 트리거) → `useApiKeyGuard` 적용
- `src/App.jsx` → mount 시 `aiCredentialStore.hydrate()` + `<ApiKeyRequiredDialog />` 글로벌 마운트
- 프록시 서버 (`/api/claude`, `/api/claude/agentic`) → 요청 헤더의 사용자 키 우선 사용, fallback으로 서버 환경변수 키 (선택)

### 4.4 API Key 체크 흐름도

```
[사용자: AI 기능 버튼 클릭]
           │
           ▼
[useApiKeyGuard.ensureKey()]
           │
   ┌───────┴────────┐
   │ isHydrated?     │── 아니오 → await hydrate() → 재진입
   └───────┬────────┘
           │ 예
           ▼
   ┌────────────────┐
   │ apiKey 존재?    │── 아니오 ──▶ [ApiKeyRequiredDialog 표시]
   └───────┬────────┘                     │
           │ 예                            ▼
           ▼                       [설정 페이지로 이동]
   ┌────────────────┐                     │
   │ isValid !== false│── false ──▶ [경고 토스트 "키 검증 실패"]
   └───────┬────────┘                     │
           │ true/null                    └─→ AI 호출 중단
           ▼
   [claudeApi.post(... headers: X-User-Api-Key)]
           │
   ┌───────┴────────┐
   │ 응답 401?       │── 예 → [isValid=false 저장 + 재검증 안내]
   └───────┬────────┘
           │ 아니오
           ▼
       [정상 응답 처리]
```

- **기존 사용자**: 키 미설정 상태로 시작 → AI 기능 사용 시 안내 모달.
  운영 정책에 따라 (a) 공용 키 fallback 유지 또는 (b) 모든 사용자 본인 키 강제 중 선택.
- **데이터 마이그레이션**: 신규 테이블이므로 기존 데이터 영향 없음.
- **백업/복원**: `dataExport.js`에 `aiCredentials` 포함 여부 결정 필요 — **기본 제외 권장** (보안).
