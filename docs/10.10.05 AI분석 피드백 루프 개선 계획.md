# AI분석 피드백 루프 개선 계획

_작성일: 2026-05-20_

---

## 1. 현행 피드백 루프의 구체적 문제

### 1-1. AI 응답 품질 평가 기제 없음

사용자가 AI 응답을 받은 후 그 품질을 기록하거나 평가하는 구조가 전혀 없다. 응답이 유용했는지, 틀렸는지, 반복적인지 시스템은 알 수 없다.

```
사용자 메시지 → AI 응답 → 화면 표시 → 끝
                                          ↑
                            품질 정보가 어디에도 기록되지 않음
```

- 사용자가 같은 질문을 3번 반복해도 시스템은 "이 응답이 부족했다"는 신호를 받지 못한다.
- "틀렸어", "다시 해줘" 같은 부정 피드백도 단순 새 메시지로 처리된다. 이전 응답과의 연관성이 없다.

### 1-2. 세션 간 학습 없음

현재 AI는 매 세션마다 동일한 시스템 프롬프트로 시작한다. 이전 세션에서 좋은 응답·나쁜 응답이 있어도 다음 세션 시스템 프롬프트에 반영되지 않는다.

```js
// claudeApi.js — 항상 고정된 시스템 프롬프트
const systemPrompt = getSystemPrompt(agentType)
// getSystemPrompt는 정적 텍스트를 반환 — 사용자별 학습 없음
```

- "포트폴리오 요약은 표 형식으로 해줘"를 100번 요청해도 다음 세션엔 기억하지 못한다.
- 특정 에이전트에서 반복적으로 오답이 나와도 해당 에이전트 프롬프트가 자동으로 개선되지 않는다.

### 1-3. 응답 유용성 지표 수집 없음

IndexedDB에 저장되는 채팅 히스토리에는 메시지 내용만 있고, 응답 품질 관련 메타데이터가 없다.

```js
// storage.js — 저장 구조
{
  id: sessionId,
  messages: [
    { role: 'user', content: '...' },
    { role: 'assistant', content: '...' },  // ← rating, feedback, wasHelpful 없음
  ]
}
```

- 어떤 에이전트가 어떤 유형의 질문에 잘 응답했는지 사후 분석 불가.
- 사용자가 응답 직후 다시 질문한 비율(재질문율)이 높다면 응답 품질 문제일 수 있지만 측정 방법이 없다.

### 1-4. 프롬프트 개선 피드백 루프 없음

에이전트 프롬프트(`src/agents/*.js`)는 개발자가 수동으로 수정해야만 변경된다. 사용자 피드백에서 자동으로 개선 힌트를 도출하는 기제가 없다.

```js
// journalCoachAgent.js — 정적 프롬프트
export const JOURNAL_COACH_PROMPT = `당신은 투자 심리 코치입니다. ...`
// 사용자가 "너무 딱딱해", "더 구체적으로" 피드백을 줘도 이 텍스트는 바뀌지 않음
```

## 3. 개선 방향

### 옵션 A — 사용자 평점 UI + 로컬 저장

각 AI 응답 아래에 👍/👎 버튼을 추가하고, 평점을 IndexedDB에 저장한다.

- 장점: 구현 단순, 사용자 입력 기반의 명시적 피드백
- 단점: 사용자가 평점을 누르지 않으면 데이터 없음, 자동 개선과 연결 어려움

### 옵션 B — 암묵적 행동 신호 수집 (추천)

사용자가 명시적으로 평점을 누르지 않아도, 행동에서 품질을 추론한다.

| 행동 신호 | 품질 해석 |
|---------|----------|
| 응답 직후 60초 이내 재질문 | 부족한 응답 의심 |
| "틀렸어", "다시" 키워드 포함 | 오답 의심 |
| 같은 에이전트에 동일 키워드 재입력 | 반복 실패 |

이 신호를 세션 메타데이터에 기록하고, 에이전트별 품질 지표로 집계한다.

- 장점: 사용자 추가 동작 불필요, 자연스러운 수집
- 단점: 신호 해석의 모호함, 이탈과 만족을 구분하기 어려움

### 옵션 C — 응답 자기 평가 (Self-Critique)

Claude가 응답을 생성한 후, 같은 Claude에게 "이 응답이 질문에 충분히 답했는가?"를 묻는 2차 호출을 추가한다.

- 장점: 자동화, 사용자 개입 불필요
- 단점: 호출 비용 2배, 자기 평가의 신뢰성 한계

**추천: 옵션 B (암묵적 신호) + 옵션 A의 선택적 평점 UI 병행**

암묵적 신호로 기본 데이터를 수집하고, 관심 있는 사용자는 👍/👎로 명시적 피드백을 추가할 수 있다. 옵션 C는 향후 오류 복구(10.10.07)와 연계해 구현한다.

## 4. 항목별 개선 상세

### 4-1. 응답 메타데이터 스키마 확장

IndexedDB 메시지 구조에 품질 관련 필드를 추가한다.

```js
// storage.js — 메시지 구조 확장
{
  role: 'assistant',
  content: '...',
  agentType: 'portfolio',
  timestamp: Date.now(),
  // 추가 필드
  feedback: null,           // 'helpful' | 'unhelpful' | null
  followUpWithin60s: false, // 60초 이내 재질문 여부
  negativeKeyword: false,   // '틀렸어', '다시', '아니야' 포함 여부
  qualityScore: null,       // 0~100, 집계된 암묵적 점수
}
```

### 4-2. 암묵적 신호 감지 — feedbackDetector

```js
// src/utils/feedbackDetector.js 신규
const NEGATIVE_KEYWORDS = ['틀렸어', '아니야', '다시', '잘못됐어', '다시 해줘', '틀림']

export function detectNegativeIntent(message) {
  return NEGATIVE_KEYWORDS.some(kw => message.includes(kw))
}

export function recordImplicitFeedback(nextMessage, timeDelta) {
  const isNegative = detectNegativeIntent(nextMessage)
  const isFollowUp = timeDelta < 60_000
  // 부정 신호가 없으면 70, 재질문 시 50, 부정 키워드 시 20
  const qualityScore = isNegative ? 20 : isFollowUp ? 50 : 70
  return { negativeKeyword: isNegative, followUpWithin60s: isFollowUp, qualityScore }
}
```

### 4-4. 에이전트별 품질 집계 — generateQualityReport

세션 종료 시(개발 모드) 에이전트별 품질 점수를 집계해 콘솔에 출력한다.

```js
// src/utils/feedbackDetector.js 추가
export function generateQualityReport(messages) {
  const byAgent = {}
  for (const msg of messages) {
    if (msg.role !== 'assistant' || !msg.agentType) continue
    const agent = msg.agentType
    if (!byAgent[agent]) byAgent[agent] = { count: 0, totalScore: 0, unhelpful: 0 }
    byAgent[agent].count++
    byAgent[agent].totalScore += msg.qualityScore ?? 70
    if (msg.feedback === 'unhelpful') byAgent[agent].unhelpful++
  }
  for (const [agent, data] of Object.entries(byAgent)) {
    console.info(
      `[QualityReport] ${agent}: avg=${(data.totalScore / data.count).toFixed(1)}, unhelpful=${data.unhelpful}/${data.count}`
    )
  }
}
```

## 8. 고려 사항

- **프라이버시**: 피드백 데이터는 IndexedDB에만 저장되며 외부 서버로 전송되지 않는다. CLAUDE.md 금지사항 준수.
- **신호 모호성**: "60초 이내 재질문"은 만족(추가 질문)일 수도 불만족(재시도)일 수도 있다. 부정 키워드와 결합했을 때만 강한 신호로 해석한다.
- **스키마 마이그레이션**: 기존 IndexedDB 메시지에는 새 필드가 없다. 읽을 때 `?? 기본값`으로 처리해 하위 호환성을 유지한다.
- **세션 간 학습 확장**: Phase 1~3 수집 데이터를 바탕으로, 향후 품질 점수가 낮은 에이전트 시스템 프롬프트에 "개선 힌트" 텍스트를 동적으로 삽입하는 Phase 4를 별도 기획할 수 있다.
- **개발자 가시성**: `generateQualityReport()`를 개발 모드에서만 실행해 프로덕션 콘솔 오염을 방지한다.
