## 1. 현행 구조의 근본 문제

### 1.1 이중 사용자 ID 체계 (데이터 카오스의 근원)

**현재 상황:**
```
로컬 생성 ID:    user-a1b2c3d4    (authStore.register()에서 생성)
Supabase UUID:   550e8400-e29b-41d3-a4c5-316...  (auth.users.id)
```

**문제점:**
- `migrateLocalUser.js`가 ID 재매핑을 시도했으나 **Race Condition** 발생
- `syncService.migrateLocalToServer()`가 로컬 userId로 조회 → 서버에 Supabase userId로 저장 → **이중 저장**
- `upload.js`가 `data` 컬럼에 전체 레코드를 JSON 래핑 → 메타 필드와 실제 필드 혼재
- `download.js`가 `record.data ?? record`로 unwrap 시도 → **필드명 불일치** (e.g., `synced_at` vs `syncedAt`)

**결과:**
```
Supabase                    IndexedDB (로컬)
─────────────────────────   ──────────────────
id=uuid1, user_id=uuid1     id=uuid1, userId=user-XXX
id=uuid2, user_id=uuid1     id=uuid2, userId=user-XXX
                             (같은 사용자가 두 ID로 기록됨)
```

### 1.2 API 데이터 래핑 구조 불일치

**현재 upload.js (L59-66):**
```javascript
await supabase.from(pgTable).upsert({
  id:           String(record.id),
  user_id:      user.id,
  data:         record,                    // ← 원본 레코드 전체를 JSON으로 저장
  sync_version: (record.syncVersion ?? 0) + 1,
  synced_at:    new Date().toISOString(),
  deleted_at:   record.deletedAt ?? null,
})
```

**현재 download.js (L46-47):**
```javascript
const { data, error } = await query  // ← 서버가 반환한 행 전체
res.status(200).json({
  records: data ?? [],
  version: meta?.global_version ?? 0,
})
// 클라이언트가 받는 각 record: { id, user_id, data: {...}, sync_version, synced_at, deleted_at }
```

**현재 syncService.js (L111-115):**
```javascript
const payload = record.data ?? record  // ← unwrap 시도
await db[table].put({
  ...payload,
  syncedAt: record.synced_at ?? new Date().toISOString(),
})
```

**문제:**
- 서버의 `synced_at` vs 클라이언트의 `syncedAt` (camelCase/snake_case 불일치)
- `record.data` 안에 `syncedAt` 없음 → 클라이언트가 항상 새로운 타임스탐프로 덮어쓰기
- 메타 필드(`id`, `user_id`, `sync_version`)가 `data` 컬럼 밖에 있음 → 이중 저장

### 1.3 테이블 커버리지 불완전

## 2. 새 아키텍처 원칙

### 2.1 Auth — Supabase UUID 단일 체계

**변경:**
| 항목 | 기존 | 신규 |
|------|------|------|
| 가입 | `register()` → 로컬 user-XXXX 생성 후 별도로 Supabase signUp | `signUp(email, password)` → 즉시 Supabase Auth 생성 |
| 로컬 저장 | `users[]` 배열에 모든 사용자 저장 | **제거** — 현재 세션만 `currentUser` |
| 세션 캐시 | 없음 | 브라우저 localStorage에 Supabase session 저장 → `restoreSession()` 호출 시 자동 복원 |
| userId | user-XXXX 또는 UUID (혼재) | **UUID만** (`currentUser.id = auth.users.id`) |
| 로그아웃 | 세션만 정리 | **인증 해제** (`supabase.auth.signOut()`) |

**구현 상세:**

`src/store/authStore.js` (전면 재작성):
```typescript
import { create } from 'zustand'
import { persist } from 'zustand/middleware'
import { authService } from '@/services/authService'

export const useAuthStore = create(
  persist(
    (set, get) => ({
      // ── Supabase 세션 ──
      currentUser: null,  // { id (UUID), email, user_metadata }
      isLoggedIn: false,
      supabaseSession: null,
      isAdmin: false,

      // ── Supabase 가입 ──
      signUp: async (email: string, password: string, displayName?: string) => {
        const { data, error } = await authService.signUp(email, password, displayName)
        if (error) return { ok: false, error: error.message }

        // 가입 직후 자동 세션 설정 (Supabase가 반환한 session 사용)
        if (data.session) {
          set({
            currentUser: {
              id: data.user.id,  // UUID
              email: data.user.email,
              displayName: data.user.user_metadata?.full_name || email,
            },
            supabaseSession: data.session,
            isLoggedIn: true,
          })
        }
        return { ok: true, user: data.user }
      },

      // ── Supabase 로그인 ──
      signIn: async (email: string, password: string) => {
        const { data, error } = await authService.signIn(email, password)
        if (error) return { ok: false, error: error.message }

        set({
          currentUser: {
            id: data.session.user.id,  // UUID
            email: data.session.user.email,
            displayName: data.session.user.user_metadata?.full_name || email,
          },
          supabaseSession: data.session,
          isLoggedIn: true,
        })
        return { ok: true, session: data.session }
      },

      // ── 세션 복원 (앱 시작 시) ──
      restoreSession: async () => {
        const session = await authService.getSession()
        if (session?.user) {
          set({
            currentUser: {
              id: session.user.id,  // UUID
              email: session.user.email,
              displayName: session.user.user_metadata?.full_name || session.user.email,
            },
            supabaseSession: session,
            isLoggedIn: true,
          })
          return true
        }
        set({ currentUser: null, isLoggedIn: false, supabaseSession: null })
        return false
      },

      // ── 로그아웃 ──
      signOut: async () => {
        await authService.signOut()  // Supabase auth 세션 제거
        set({ currentUser: null, isLoggedIn: false, supabaseSession: null })
      },

      setIsAdmin: (v: boolean) => set({ isAdmin: v }),

      // ── 하위 호환성 (기존 코드 호출 처리) ──
      setSupabaseSession: (session) => {
        if (session?.user) {
          set({
            currentUser: {
              id: session.user.id,
              email: session.user.email,
              displayName: session.user.user_metadata?.full_name || session.user.email,
            },
            supabaseSession: session,
            isLoggedIn: true,
          })
        }
      },
    }),
    {
      name: 'auth-storage',
      version: 4,  // ← 버전 올리기 (기존 데이터 무시)
      migrate: (persisted) => ({
        // users[] 제거 — 로컬 user-XXXX 시스템 폐기
        currentUser: null,
        isLoggedIn: false,
        supabaseSession: null,
        isAdmin: false,
      }),
    }
  )
)
```

**변경 요점:**
- `users[]` 배열 → **제거**
- `register()` → **제거** (Supabase signUp만 사용)
- `login()` → **제거** (Supabase signIn만 사용)
- `restoreSession()` **신규** — 브라우저 새로고침 시 캐시된 세션 복원
- persist version ↑ (v3 → v4), migrate 핸들러로 기존 `users[]` 폐기

### 2.2 Sync — 단순 명시적 단방향 흐름

**원칙:**
- 충돌 감지는 **이번 단계에서 제거** (향후 단계)
- **Upload만** — syncedAt=null 레코드 수집 → 서버 upsert
- **Download만** — 서버 전체 레코드 반환 → 로컬 덮어쓰기

**Upload 흐름:**
```
syncService.uploadTable('transactions')
  ├─ IndexedDB에서 syncedAt=null 레코드 조회
  ├─ POST /api/sync/upload { table: 'transactions', records: [...] }
  │   (JWT 검증 → user_id, email 추출 후 강제 덮어쓰기)
  ├─ 서버: 각 레코드 upsert(id) → syncedAt=NOW(), sync_version += 1
  ├─ 응답: { uploaded: [...원본 필드 포함...], failed: [...] }
  └─ 클라이언트: uploaded 레코드의 syncedAt = NOW() 표시
```

**Download 흐름:**
```
syncService.downloadTable('transactions')
  ├─ GET /api/sync/download?table=transactions
  │   (JWT 검증 → user_id 추출)
  ├─ 서버: SELECT * FROM transactions WHERE user_id=? AND deleted_at IS NULL
  ├─ 응답: { records: [...컬럼 그대로...], count: N }
  └─ 클라이언트: IndexedDB에 PUT (최초 설치이므로 충돌 없음)
```

### 2.3 API 데이터 구조 — `data` 컬럼 래핑 제거

**기존 (문제):**
```json
// Supabase에 저장된 행
{
  "id": "uuid-123",
  "user_id": "user-id-456",
  "data": {
    "id": "uuid-123",
    "ticker": "005930",
    "quantity": 10,
    "syncVersion": 0,
    "syncedAt": null
  },
  "sync_version": 1,
  "synced_at": "2026-05-30T10:00:00Z"
}
```

**신규 (명확함):**
```json
// Supabase에 저장된 행
{
  "id": "uuid-123",
  "user_id": "uuid-user-id",
  "user_email": "user@example.com",
  "ticker": "005930",
  "quantity": 10,
  "price": 72000,
  "action": "buy",
  "date": "2026-05-30",
  "sync_version": 1,
  "synced_at": "2026-05-30T10:00:00Z",
  "deleted_at": null
}
```

**이점:**
- 컬럼이 직접 보존 → 서버 쿼리 간단
- `data` 컬럼 불필요 → 저장소 효율
- 클라이언트와 서버의 필드명 일치 (camelCase ↔ snake_case 변환 최소)

## 4. 데이터베이스 스키마 상세

### 4.1 Supabase 신규/수정 테이블

#### `profiles` (신규 — users 정보)

```sql
CREATE TABLE profiles (
  id              UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  email           TEXT NOT NULL UNIQUE,
  display_name    TEXT DEFAULT '',
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- RLS Policy
CREATE POLICY "사용자는 자신의 프로필만 조회" ON profiles
  FOR SELECT USING (auth.uid() = id);

CREATE POLICY "사용자는 자신의 프로필만 수정" ON profiles
  FOR UPDATE USING (auth.uid() = id);

CREATE INDEX idx_profiles_email ON profiles(email);
```

#### `user_accounts` (신규 — 투자 계좌)

```sql
CREATE TABLE user_accounts (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id         UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  user_email      TEXT NOT NULL,
  name            TEXT NOT NULL,
  broker          TEXT DEFAULT '',
  type            TEXT DEFAULT 'GENERAL',  -- 'GENERAL', 'MARGIN', 'OPTIONS'
  currency        TEXT DEFAULT 'KRW',
  initial_balance NUMERIC DEFAULT 0,
  memo            TEXT DEFAULT '',
  sync_version    INT DEFAULT 0,
  synced_at       TIMESTAMPTZ,
  deleted_at      TIMESTAMPTZ,
  created_at      TIMESTAMPTZ DEFAULT NOW(),
  updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- RLS Policy
CREATE POLICY "사용자는 자신의 계좌만 조회" ON user_accounts
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "사용자는 자신의 계좌만 수정" ON user_accounts
  FOR UPDATE USING (auth.uid() = user_id);

CREATE INDEX idx_user_accounts_user_id ON user_accounts(user_id);
CREATE INDEX idx_user_accounts_user_email ON user_accounts(user_email);
```

#### `transactions` (수정 — 기존 테이블 마이그레이션)

> ⚠️ **순환 FK 금지**: `transactions.linked_cash_flow_id` ↔ `cash_flows.linked_journal_id` 는
> 서로를 참조하므로 DB FK 제약을 걸 수 없다. UUID 타입만 선언하고 참조 무결성은 앱 레이어에서 관리.

```sql
-- 기존 테이블 삭제 (P-1 단계에서 이미 완료됐으면 생략 가능)
DROP TABLE IF EXISTS transactions CASCADE;

CREATE TABLE transactions (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id             UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  user_email          TEXT NOT NULL,
  account_id          UUID REFERENCES user_accounts(id) ON DELETE SET NULL,
  account_name        TEXT,
  ticker              TEXT NOT NULL,
  name                TEXT,
  action              TEXT NOT NULL,  -- 'buy', 'sell'
  date                DATE NOT NULL,
  price               NUMERIC NOT NULL,
  quantity            NUMERIC NOT NULL,
  fee                 NUMERIC DEFAULT 0,
  pnl                 NUMERIC,
  psychology          TEXT,
  memo                TEXT DEFAULT '',
  market              TEXT DEFAULT 'KRX',
  sector              TEXT,
  source              TEXT,
  linked_cash_flow_id UUID,           -- ⚠️ FK 제약 없음 (순환 참조 방지)
  external_id         TEXT,
  sync_version        INT DEFAULT 0,
  synced_at           TIMESTAMPTZ,
  deleted_at          TIMESTAMPTZ,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  imported_at         TIMESTAMPTZ
);

ALTER TABLE transactions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "사용자는 자신의 거래만 접근" ON transactions
  FOR ALL USING (auth.uid() = user_id);

CREATE INDEX idx_transactions_user_id    ON transactions(user_id);
CREATE INDEX idx_transactions_user_email ON transactions(user_email);
CREATE INDEX idx_transactions_date       ON transactions(date DESC);
CREATE INDEX idx_transactions_ticker     ON transactions(ticker);
CREATE INDEX idx_transactions_account_id ON transactions(account_id);
CREATE INDEX idx_transactions_sync       ON transactions(user_id, synced_at);
```

```javascript
export default async function handler(req, res) {
  // 1️⃣ CORS + Method 검증
  if (handlePreflight(req, res)) return
  setCors(req, res)
  if (req.method !== 'POST') return res.status(405).end()

  // 2️⃣ JWT 검증 → user_id, email 추출
  const token = req.headers.authorization?.replace('Bearer ', '')
  if (!token) return res.status(401).json({ error: 'Unauthorized' })

  const { data: { user }, error: authError } = await supabase.auth.getUser(token)
  if (authError || !user) return res.status(401).json({ error: 'Unauthorized' })

  // 3️⃣ 요청 파싱 및 검증
  const { table, records } = req.body
  const pgTable = getServerTableName(table)  // syncConfig.js 사용
  if (!pgTable) return res.status(400).json({ error: `Unknown table: ${table}` })
  if (!Array.isArray(records) || records.length === 0) {
    return res.status(400).json({ error: 'records must be a non-empty array' })
  }

  // 4️⃣ 각 레코드 처리
  const uploaded = []
  const failed = []

  for (const record of records) {
    try {
      // ⚠️ 클라이언트 userId 무시 — 서버가 강제 덮어쓰기
      const serverRecord = {
        ...record,
        id: String(record.id),
        user_id: user.id,           // ← JWT에서 추출한 userId 강제 적용
        user_email: user.email,     // ← JWT에서 추출한 email 강제 적용
        sync_version: (record.syncVersion ?? 0) + 1,
        synced_at: new Date().toISOString(),
        deleted_at: record.deletedAt ?? null,
      }

      // camelCase → snake_case 변환 (필요 시)
      const dbRecord = convertToSnakeCase(serverRecord)

      // 5️⃣ Upsert (ON CONFLICT DO UPDATE)
      const { error: upsertError } = await supabase
        .from(pgTable)
        .upsert(dbRecord, { onConflict: 'id' })

      if (upsertError) {
        failed.push({ id: record.id, error: upsertError.message })
        continue
      }

      // 6️⃣ 성공 레코드 원본 필드로 반환
      uploaded.push({
        ...record,
        syncVersion: dbRecord.sync_version,
        syncedAt: dbRecord.synced_at,
      })
    } catch (error) {
      failed.push({ id: record.id, error: error.message })
    }
  }

  // 7️⃣ 응답
  res.status(200).json({ uploaded, failed })
}

// camelCase → snake_case 변환 헬퍼
function convertToSnakeCase(obj) {
  const result = {}
  for (const [key, value] of Object.entries(obj)) {
    const snakeKey = key.replace(/[A-Z]/g, m => '_' + m.toLowerCase())
    result[snakeKey] = value
  }
  return result
}
```

### 7.1 ID 교정 유틸 (`src/utils/migrateLocalIds.js`)

**목표:** 로컬 IndexedDB의 `user-XXXX` userId를 현재 Supabase UUID로 교체

```javascript
// 로컬 ID (user-XXXX) → Supabase UUID 교정
import { db } from '@/utils/db'

export async function migrateLocalIdsIfNeeded(supabaseUserId, supabaseEmail) {
  // 1️⃣ 이미 완료된 경우 스킵
  const migrationKey = `id_migrated_${supabaseUserId}`
  const alreadyMigrated = localStorage.getItem(migrationKey)
  if (alreadyMigrated) {
    console.log('[migrateLocalIds] 이미 완료됨')
    return
  }

  console.log('[migrateLocalIds] 시작...')

  // 2️⃣ 로컬 user-XXXX userId 레코드 조회
  const tableNames = ['transactions', 'cashFlows', 'calendarEvents']
  let totalMigrated = 0

  for (const tableName of tableNames) {
    // Dexie: where().toArray() → 필터 적용
    const records = await db[tableName].toArray()
    const localUserRecords = records.filter(r => 
      r.userId && String(r.userId).startsWith('user-')
    )

    if (localUserRecords.length === 0) continue

    console.log(`[migrateLocalIds] ${tableName}: ${localUserRecords.length}건 교정`)

    // 3️⃣ userId → UUID 교체, userEmail 추가, syncedAt null
    const updated = localUserRecords.map(r => ({
      ...r,
      userId: supabaseUserId,           // ← Supabase UUID로 교체
      userEmail: supabaseEmail,         // ← 추가
      syncedAt: null,                   // ← 미동기화 상태로 표시
      syncVersion: r.syncVersion ?? 0,
    }))

    // 4️⃣ bulkPut (덮어쓰기)
    await db[tableName].bulkPut(updated)
    totalMigrated += updated.length
  }

  // 5️⃣ 완료 플래그 저장
  localStorage.setItem(migrationKey, new Date().toISOString())
  console.log(`[migrateLocalIds] 완료: ${totalMigrated}건`)
}
```
