## 1. 구현 범위 및 목표

### 목표
사용자가 "왜 이 종목이 폭락했나?", "오늘 시장이 왜 출렁이나?" 같은 질문을
채팅창에 타이핑하지 않아도, 종목 상세 화면과 대시보드에서 즉시 AI 해석을 볼 수 있도록 한다.

### 이번 스프린트 범위 (Sprint 10.9)

| 피처 | 설명 |
|------|------|
| F1. Price Movement Explainer | 종목 상세 페이지: 오늘 등락률이 있을 때 "오늘의 이유" 섹션 자동 표시 |

## 2. 아키텍처 설계

### 2.1 신규 에이전트: analysisAgent.js

```
src/agents/analysisAgent.js  (신규)
  - ANALYSIS_PROMPT           ← 급등락 원인 분석 전용 시스템 프롬프트
  - MARKET_BRIEF_PROMPT        ← 시장 전반 브리핑 전용 시스템 프롬프트
  - buildMovementContext()     ← 종목명+등락률+뉴스+공시 → 컨텍스트 문자열
  - buildMarketBriefContext()  ← 지수 목록+글로벌 뉴스 → 컨텍스트 문자열
```

**ANALYSIS_PROMPT 핵심 지시사항:**
```
당신은 주가 급등락 원인 분석 전문 에이전트입니다.
주어진 데이터(현재가, 등락률, 최근 뉴스, 공시)를 기반으로
오늘 이 종목의 주가가 움직이는 주요 이유를 3가지 이내로 명확하게 설명하세요.

출력 형식:
1. 핵심 요인: [가장 큰 원인 — 뉴스/공시/업종 이슈 구분]
2. 세부 분석: 각 요인별 2~3문장 설명
3. 투자자 유의점: 단기/중기 관점에서 주의할 사항
- 면책 문구 필수 포함
- 추측이 아닌 수집된 데이터 기반으로만 분석
```

**MARKET_BRIEF_PROMPT 핵심 지시사항:**
```
당신은 주식 시장 브리핑 전문 에이전트입니다.
오늘 주요 지수(KOSPI, KOSDAQ, NASDAQ, S&P500)의 등락 현황과
관련 뉴스를 바탕으로 시장 전반의 흐름을 간결하게 설명하세요.

출력 형식:
- 오늘의 시장 한줄 요약 (강세/약세/혼조)
- 주요 움직임 원인 2~3가지
- 국내/해외 구분하여 설명
- 면책 문구 필수 포함
```

### 2.2 데이터 흐름 — Price Movement Explainer

```
종목 상세 페이지 (ResearchDetail)
  ↓ 등락률 ±3% 이상 감지 또는 "오늘의 이유" 버튼 클릭
  ↓
buildMovementContext(ticker, changePercent, news, disclosures)
  ↓ 뉴스 최대 8건 + 공시 최대 5건 포함
  ↓
Claude API (ANALYSIS_PROMPT + context)
  ↓
MovementExplainerCard 컴포넌트에 결과 렌더링
  - 로딩: 스켈레톤
  - 결과: 마크다운 렌더링
  - 캐시: sessionStorage (동일 종목 당일 1회)
```

### 2.3 데이터 흐름 — Market Daily Brief

```
종목탐색 페이지 (Research.jsx)
  ↓ 기존 MarketIndexCard 섹션 아래
  ↓ "AI 시장 브리핑" 버튼 클릭 또는 자동 로드
  ↓
Promise.all([
  fetchQuote('^KS11'), fetchQuote('^KQ11'),
  fetchQuote('^IXIC'), fetchQuote('^GSPC'),
  fetchGlobalNews()  ← 글로벌 마켓 뉴스 신규
])
  ↓
buildMarketBriefContext(indices, news)
  ↓
Claude API (MARKET_BRIEF_PROMPT + context)
  ↓
MarketBriefCard 컴포넌트에 결과 렌더링
  - 캐시: sessionStorage (당일 1회, 수동 갱신 가능)
```

### 2.4 Orchestrator 라우팅 개선

기존 routing_rules에 `analysis` 에이전트 추가:

```js
// orchestrator.js 추가
{
  agent: 'analysis',
  keywords: [
    '왜', '이유', '원인', '어떻게 된', '무슨 일',
    '급락', '급등', '폭락', '폭등', '하락 이유', '상승 이유',
    '오늘 시장', '시장 왜', '코스피 왜', '나스닥 왜',
  ],
}
```

채팅에서 `analysis` 에이전트로 라우팅되면:
- 종목 티커가 포함된 경우 → `ANALYSIS_PROMPT` + 종목 데이터 수집 후 분석
- 시장 전반 질문의 경우 → `MARKET_BRIEF_PROMPT` + 지수 데이터 수집 후 분석

## 5. 기술 결정 사항

### 5.1 캐싱 전략

| 데이터 | 캐시 위치 | TTL |
|--------|---------|-----|
| 시장 브리핑 | sessionStorage | 당일 1회 (수동 갱신 가능) |
| 종목 급등락 분석 | sessionStorage | 동일 티커+날짜 1회 |

이유: 뉴스는 하루 중 바뀔 수 있으므로 수동 갱신 버튼 제공.

### 5.2 오류 처리

- AI API 오류 시: 에러 메시지 표시 + 재시도 버튼
- 뉴스 수집 실패 시: 가용 데이터만으로 제한적 분석 (fallback)
- API 키 미설정 시: 기존 ApiKeyRequiredDialog 재사용

### 5.3 토큰 최적화

- 뉴스 본문 제외, 제목+날짜만 전달 (토큰 절감)
- 뉴스 최대 8건, 공시 최대 5건으로 제한
- 응답 maxTokens: 1024
