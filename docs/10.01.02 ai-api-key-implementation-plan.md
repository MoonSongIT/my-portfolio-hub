## Phase B — 상태 & 유틸

> 목표: 키 저장/검증 로직 및 전역 상태 관리 구현

### 신규 파일
- `src/utils/apiKeyValidator.js`
- `src/store/aiCredentialStore.js`

### 수정 파일
- `src/api/claudeApi.js`

### 체크리스트

- [x] **B1** — `src/utils/apiKeyValidator.js` 구현
  - `isValidFormat(key)`: `sk-ant-` prefix + 60자 이상 검사 (경고만, 차단 없음)
  - `maskKey(key)`: `sk-ant-•••••••••••XXXX` 형태 (앞 7자 + 마지막 4자 노출)
  - 순수 함수로 작성 (의존성 없음)

- [x] **B2** — `src/store/aiCredentialStore.js` 구현 (Zustand)
  - 상태: `apiKey, isValid, validatedAt, isLoading, isHydrated`
  - `hydrate()`: 앱 시작 시 IDB → 메모리 로드
  - `setApiKey(key)`: 형식 검증 + IDB 저장 + 상태 업데이트
  - `validateKey()`: `POST /api/claude/validate` 호출 → `isValid`, `validatedAt` 갱신
  - `clearKey()`: IDB 삭제 + 상태 전체 리셋
  - `hasKey()`: `apiKey !== null` 셀렉터
  - Zustand `persist` 미사용 — 수동 hydrate (IDB 비동기 특성)

- [x] **B3** — `src/api/claudeApi.js` interceptor 추가
  - request interceptor: `aiCredentialStore`에서 `apiKey` 읽어 `X-User-Api-Key` 헤더 자동 첨부
  - response interceptor: 401 응답 시 `aiCredentialStore.setState({ isValid: false })` 동기화
  - 기존 API 호출 코드 변경 없이 interceptor 레이어에서만 처리
