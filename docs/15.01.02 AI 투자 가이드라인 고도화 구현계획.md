# 15.01.02 AI 투자 가이드라인 고도화 구현계획

## 작성일
2026-06-23

## 근거 문서
[15.01.01 AI를 활용한 투자 가이드라인 고도화 방법 조사](./15.01.01%20AI를%20활용한%20투자%20가이드라인%20고도화%20방법%20조사.md) — 본 계획은 조사 문서의 격차(G1~G5)와 적용 로드맵(데이터·계산·AI·UI 레이어)을 구현 단위로 구체화한다. 직전 [14.04 AI 분석 기능 고도화](./14.04.02%20AI%20분석%20기능고도화%20구현계획.md) 시리즈(web_search·모델 파라미터화·뉴스 감성)가 완료된 상태를 전제로, 그 위에 "거시·선행지표 기반 시장 국면 판단"을 얹는다.

## 사용 모델
구현·검토는 최고 사양 모델(`claude-opus-4-8`)을 사용한다. 신설 시장 국면 분석도 분석 계열과 동일하게 Opus를 적용한다.

## 1. 목표

1. 미국 **선행지표(SOX·VIX·미국채·달러·원달러)를 수집**하고 시장 브리핑에 결합한다 (G1·G3).
2. **변동성 레짐(VIX 백분위)** 과 **변동성 지표(ATR·볼린저밴드 폭)** 를 순수 함수로 계산한다 (G2).
3. 선행지표를 종합하는 **규칙 스코어(`overnightBias`)** 와 이를 해석하는 **시장 국면 분석**으로 "오늘의 시장 국면"을 산출한다 (G4).
4. 예측을 **과학적 절차**(look-ahead 회피·확률 표현·사후 적중률 트래킹)로 운영한다 (G5).
5. 비용·정책을 통제한다 (설정 토글, 매수/매도 권유 금지·면책 유지).

## 2. 범위 (Phase 구분)

| Phase | 항목 | 조사 문서 매핑 | 성격 |
|-------|------|---------------|------|
| **Phase 1** | 선행지표 수집(데이터) + VIX 레짐·ATR·볼린저(계산) + `overnightBias` | 데이터·계산 레이어 P1·P2·P3 | **권장 1차** — 본 계획 주 대상 |
| **Phase 2** | 브리핑 컨텍스트 확장 + 시장 국면 프롬프트·라우팅 + "시장 국면" UI 카드 | AI·UI 레이어 P3·P4·P5 | 본 계획 상세 |
| **Phase 3** | 사후 검증 트래킹(적중률) + 레짐 추이 차트 | P6 | 방향만 기술 |

본 문서는 **Phase 1·2를 상세 설계**하고, Phase 3는 방향만 기술한다.

## 3. Phase 1 상세 설계 — 데이터·계산 기반

### 3-1. P1 — 선행지표 시세 수집

**현재 상태**
- `src/api/claudeApi.js:181~205` — `BRIEF_INDICES` 4종(KOSPI·KOSDAQ·NASDAQ·S&P500)만 정의, `getMarketIndices()`가 `fetchQuote`로 조회 후 60초 캐시.
- `fetchQuote(ticker, market)`는 `stockApi.js`에서 S&P500(`^GSPC`)·NASDAQ(`^IXIC`)을 이미 Yahoo로 조회 → **지수 티커 조회 경로가 검증되어 있다**.

**변경안**
1. `src/api/claudeApi.js`
   - 표시용 핵심 지수(`BRIEF_INDICES`)와 신호용 선행지표를 구분하기 위해 별도 상수 `LEADING_INDICATORS`를 신설한다(혼선 방지).
     ```
     const LEADING_INDICATORS = [
       { key: 'sox',   label: 'SOX(반도체)', ticker: '^SOX',     market: 'NASDAQ', invert: false },
       { key: 'vix',   label: 'VIX(공포)',   ticker: '^VIX',     market: 'NYSE',   invert: true  },
       { key: 'us10y', label: '美10Y',       ticker: '^TNX',     market: 'NYSE',   invert: true  },
       { key: 'dxy',   label: 'DXY(달러)',   ticker: 'DX-Y.NYB', market: 'NYSE',   invert: true  },
       { key: 'usdkrw',label: '원/달러',     ticker: 'KRW=X',    market: 'NYSE',   invert: true  },
       { key: 'wti',   label: 'WTI(유가)',   ticker: 'CL=F',     market: 'NYSE',   invert: true  },
     ]
     ```
     - `invert: true` = 값 상승이 한국 증시에 음(-)의 신호(VIX·금리·달러·환율).
     - **WTI 주의**: 유가는 부호가 양면적이다(수입국 인플레 부담=음 / 경기확장 신호=양). 표시는 6종으로 하되 `BIAS_WEIGHTS.wti`는 **보수적으로 낮게**(0.5) 두어 bias 왜곡을 최소화한다. `invert: true`는 인플레·무역수지 관점의 기본값일 뿐, 사후 검증(Phase 3)에서 재평가한다.
   - 신규 `getLeadingIndicators()` — `LEADING_INDICATORS`를 `fetchQuote`로 병렬 조회, 실패 티커는 `null`로 스킵, 60초 캐시(키 `indicators:leading`).
2. `src/api/stockApi.js`
   - `fetchQuote`가 선행지표 티커(`^SOX`/`^VIX`/`^TNX`/`DX-Y.NYB`/`KRW=X`)를 정상 반환하는지 점검. 한국 지수처럼 특수 분기(`^KS11`→Naver)가 필요한 경우만 최소 분기 추가. **원칙은 기존 Yahoo 경로 재사용**.

> ✅ 착수 전 확인 완료(2026-06-23): `/api/yahoo` 프록시는 **화이트리스트가 없는 순수 passthrough**다 — dev=`vite.config.js:402`(query1로 전체 통과), prod=`vercel.json:16`(`/api/yahoo/:path*` → `https://query1.finance.yahoo.com/:path*`). 따라서 6개 티커는 **프록시 수정 없이** 그대로 전달된다. 기존 `^GSPC`·`^IXIC` 조회로 `^` 경로는 검증됨. 구현 시 `KRW=X`·`CL=F`의 `=` 문자 경로 인코딩만 라이브 1회 실측한다(필요 시 `encodeURIComponent`).

**검증**: 브라우저 콘솔/네트워크에서 5개 티커 시세가 `changePercent`와 함께 조회됨. 일부 실패해도 나머지로 동작(부분 실패 내성).

### 3-2. P2 — 변동성 레짐 & 변동성 지표 (순수 함수, TDD)

**현재 상태**
- `src/api/technicalApi.js` — MA/RSI/MACD/지지·저항 순수 함수. **변동성 지표(ATR·볼린저)와 레짐 분류는 없음**.

**변경안 — 신규 모듈 `src/api/regimeApi.js`** (technicalApi와 역할 분리)
1. `computeAtr(history, period = 14)` — True Range의 Wilder 평활. 반환 `{ atr, atrPercent }`(atrPercent = atr/현재가).
2. `computeBollinger(closes, period = 20, mult = 2)` — `{ upper, lower, middle, bandwidth, percentB }`. bandwidth로 스퀴즈/확장 감지.
3. `computeVixRegime(vixHistory, currentVix)` — 252일 trailing 분포에서 33/67 백분위 산출.
   - 반환 `{ regime: 'low'|'normal'|'high'|'crisis', percentile, p33, p67 }`.
   - `crisis` 조건: 절대 임계(예 VIX≥35) **또는** 1일 급변(예 +20%).
   - **look-ahead 회피**: 입력은 항상 "현재 시점까지의 vixHistory"만. 함수는 미래를 모름(순수).
4. `computeOvernightBias(snapshot)` — 선행지표 등락 스냅샷 → 가중 스코어.
   - 입력: `{ sox, sp500, nasdaq, vix, us10y, dxy, usdkrw, wti }`(각 changePercent).
   - `sign()` × 가중치 합산 → `{ score, label: '강한하락|약세|중립|강세|강한상승', contributions }`.
   - 가중치는 **명명 상수 `BIAS_WEIGHTS`** — 현 장세(고환율·외국인 매도 진앙) 반영해 **거시 자금 채널(금리·달러·환율)=2 최우선**, SOX·S&P=1.5, 나스닥·VIX=1, **WTI=0.5 최소**. 사후 보정 대상(Phase 3).

> 모두 순수 함수 → **단위 테스트 우선 작성(TDD)**. AAA 패턴. 합성 입력으로 경계값(백분위 33/67 경계, ATR 데이터 부족, bias 중립=0) 검증.

**검증**: `regimeApi.test.js` — ATR·볼린저·VIX 레짐·overnightBias 각 정상/경계/데이터부족 케이스 통과.

### 3-3. Phase 1 작업 순서

```
1. (착수 전) /api/yahoo 프록시 5개 티커 허용 확인 → 미허용 시 화이트리스트 확장
2. regimeApi 단위 테스트 작성 (ATR·볼린저·VIX레짐·overnightBias)   → 검증: vitest RED
3. regimeApi.js 구현                                              → 검증: vitest GREEN
4. claudeApi: LEADING_INDICATORS + getLeadingIndicators()         → 검증: 콘솔 시세 조회
5. stockApi: 선행지표 티커 fetchQuote 점검(필요 시 분기)          → 검증: 5종 시세
6. 빌드 + 테스트                                                  → 체크리스트 15.01.03
```

## 4. Phase 2 상세 설계 — AI 종합 & UI

### 4-1. P3 — 브리핑 컨텍스트 확장 (`buildMarketBriefContext`)

**현재 상태**
- `analysisAgent.buildMarketBriefContext({ indices, news })` — 지수 4종 + 뉴스만 직렬화(조사 문서 4-2).
- 시장 브리핑 경로는 `claudeApi.js`에서 `getMarketIndices()` + `fetchNews('^GSPC')` 후 이 함수로 컨텍스트 생성.

**변경안**
1. `src/api/claudeApi.js` 시장 브리핑 경로
   - `getMarketIndices()`와 `getLeadingIndicators()`를 **병렬** 조회.
   - 선행지표 스냅샷으로 `computeOvernightBias()` 계산.
   - (선택) `^VIX` 히스토리로 `computeVixRegime()` 계산 — 히스토리 조회 비용 고려해 캐시(일 단위).
   - 위 결과를 `buildMarketBriefContext`에 추가 인자로 전달.
2. `src/agents/analysisAgent.js`
   - `buildMarketBriefContext({ indices, leading, bias, regime, news })`로 시그니처 확장(기존 인자 하위호환 — 신규 인자 미전달 시 기존 동작).
   - 조사 문서 4-2의 `[선행지표 스냅샷]` 블록을 렌더(수치·등락·레짐·bias 점수).

> 설계 원칙: 수치는 **코드가 미리 계산**해 텍스트로 주입(프리패치형 RAG). 모델은 산술이 아니라 해석·시나리오화에 집중 → 환각 억제. 14.04 그라운딩 철학의 거시 확장.

### 4-2. P4 — 시장 국면 분석 강화 + 라우팅

**현재 상태**
- 6개 에이전트(`analysis`·`journal`·`research`·`portfolio`·`alert`·`report`). 시장 브리핑은 `analysis` 경로의 한 분기(`MARKET_BRIEF_PROMPT`).
- 라우팅: `orchestrator.ROUTING_RULES`(정적) + `routeToAgentSmart`(14.04 P4, Haiku 보정).

**변경안 — "확장" 우선(신규 에이전트 vs 기존 분기 확장 결정 필요)**

조사 문서는 7번째 에이전트(`MarketRegimeAgent`) 신설을 제안하나, **구현 비용·라우팅 복잡도**를 고려해 두 안을 비교한다.

- **안 A (권장): 기존 analysis의 market-brief 분기를 "시장 국면" 모드로 승격**
  - 신규 에이전트·라우팅 키 추가 없이 `MARKET_BRIEF_PROMPT`를 **레짐 인식 프롬프트**로 강화.
  - 프롬프트에 "방향 5단계 × 변동성 레짐 4단계 / 핵심 동인 3 / 레짐별 행동 원칙 / 확률 시나리오 / 면책" 출력 형식 반영.
  - 라우팅은 기존 analysis 키워드("오늘 시장"·"코스피 왜"·"브리핑") 재사용 + "장 전망"·"선행지표"·"변동성" 키워드 보강.
  - 장점: 변경 최소·회귀 위험 낮음. 단점: "에이전트 분리"라는 조사 의도와 다름.
- **안 B: 독립 `marketRegimeAgent.js` 신설**
  - `src/agents/marketRegimeAgent.js` + `VALID_AGENTS`에 `regime` 추가 + `ROUTING_RULES` 신규 + `AGENT_MODELS`/`AGENT_TOOLS`/`AGENT_MAX_TOKENS`/`AGENT_THINKING` 맵에 `regime` 등록.
  - 장점: 도메인 명확 분리. 단점: 6→7 에이전트 전반 배선, 회귀 표면 증가.

> **결정 필요(④)**: 안 A vs 안 B. 권장은 **안 A로 시작**하고, 사용 빈도·요구가 커지면 안 B로 승격. 본 계획 체크리스트는 안 A 기준으로 작성하고 안 B 항목은 분기 표기.

3. 프롬프트(공통)
   - 확률·조건부 표현 강제("단정 금지, 트리거 조건과 함께 가능성으로 서술").
   - 레짐별 행동 원칙은 **검토 포인트**로만(매수/매도 지시 금지 — PortfolioAgent 사양 정합).
   - 면책 문구 필수.
   - (선택) analysis-brief에 확장적 사고(adaptive) — 14.04 P5 패턴 재사용(`AGENT_THINKING`).

### 4-3. P4(UI) — "오늘의 시장 국면" 카드

**현재 상태**
- `src/components/research/MarketBriefCard.jsx` — 시장 브리핑 표시.

**변경안**
- 카드 상단에 **방향 배지(5단계) × 변동성 레짐 배지(4단계)** 와 선행지표 미니 라인(SOX·VIX·원달러 등락)을 추가.
- 한국 색상 컨벤션 준수(상승=빨강, 하락=파랑). VIX·레짐은 위험도 색(정상=중립, 고변동=주황, 위기=빨강 경고)로 의미 구분.
- 데이터 없음/조회 실패 시 기존 텍스트 브리핑만 표시(graceful degradation).

## 5. Phase 3 방향 (P6 — 사후 검증 트래킹)

**목적**: 예측을 "과학적"으로 닫는 루프(조사 문서 4-3-3).

1. 신규 스토어/IDB 테이블 `regimeForecastLog`
   - 매 브리핑 시 `{ date, overnightBias, regime, predictedDirection }` 저장.
   - 익일(또는 장 마감 후) 실제 KOSPI 등락과 대조해 `actualDirection`·`hit` 갱신.
2. 적중률 집계(`hitRate`, 최근 N일) → "AI 신뢰도" 배지로 표시, `BIAS_WEIGHTS` 보정 근거.
3. (선택) 변동성 레짐 추이 미니 차트(Dashboard/Reports).

> 트레이드오프: 저장·대조 로직은 단순하나 "실제 방향" 판정 기준(시가 대비/종가 대비)을 먼저 정의해야 함. Phase 1·2 안정화 후 착수.
