# 09.01 유진투자증권 HTS 거래내역 연동 리서치

> 작성일: 2026-04-27
> 작성자: Claude (사용자 요청 기반 리서치)
> 대상: My Portfolio Hub 프로젝트
> 목적: 유진투자증권 챔피언(Champion) HTS 데스크탑 앱의 거래내역을 my-portfolio-hub의 매매 일지/포트폴리오에 자동 또는 반자동으로 가져오는 방안 검토

---

## 1. 배경 및 요구사항

### 1.1 사용자 시나리오
- 사용자는 **유진투자증권 챔피언 HTS** (Windows 데스크탑)로 매매를 진행한다.
- 누적된 매매내역을 **my-portfolio-hub**의 다음 두 영역에 반영해야 한다:
  - `journalStore.entries[]` — 매매 일지 (심리 카테고리는 사용자가 추후 보완)
  - `portfolioStore.holdings[]` — 현재 보유 종목/평균단가
- **수작업 입력은 비현실적** (수십~수백 건의 과거 거래 누적).

### 1.2 핵심 요구사항
| 항목 | 요구 수준 |
|------|-----------|
| 거래내역 일괄 가져오기 | 필수 (MVP) |
| 자동 동기화 (실시간) | 선택 (Phase 2) |
| 중복 방지 (재import 안전) | 필수 |
| 심리 카테고리 보강 UX | 필수 (가져온 후 일괄 편집) |
| 보유 종목 자동 재계산 | 권장 |
| Windows 외 환경 지원 | 불필요 (사용자 PC가 Windows 11) |

---

## 2. 데이터 채널 비교

유진투자증권에서 거래내역을 외부로 빼낼 수 있는 채널은 크게 3가지가 확인된다.

### 2.1 HTS 화면 → Excel 다운로드 (수동 export)
- 챔피언 HTS의 **계좌별 거래내역 / 매매일지 / 실현손익** 화면에서 우클릭 → "엑셀 저장" 또는 상단 툴바의 엑셀 아이콘으로 `.xlsx` / `.xls` 추출.
- **장점**: 별도 신청 불필요, 즉시 사용 가능, 보안 위험 최소.
- **단점**: 수동 클릭 필요. 화면별로 컬럼 구성이 다름.

### 2.2 챔피언 Open API (OCX/DLL)
- 유진투자증권은 **Champion Open API**를 제공하나 형태가 **OCX/DLL 컴포넌트 기반**.
- 키움증권 OpenAPI+, 한국투자증권 KIS Developers와 달리 **REST/WebSocket 미지원**으로 확인됨.
- 신청 절차: 홈페이지 → Open API 사용 신청 → 별도 설치 프로그램 + 인증서 로그인.
- TR 코드 중 **체결조회/잔고조회**는 존재하나 과거 1년 이상 거래내역 일괄 조회는 화면별 제한 가능성.
- **장점**: 자동화 가능, 실시간 시세까지 활용 가능.
- **단점**: Windows 32-bit 환경 강제, COM 기반, JS/브라우저에서 직접 호출 불가, 별도 데몬 필요.

### 2.3 모바일 앱(MTS) / 홈페이지 거래내역
- 홈페이지(웹)에서 거래내역을 PDF/엑셀로 다운로드 가능 (인증서/공동인증서 로그인 필요).
- API 형태로는 미공개. 스크래핑은 약관/보안 위반 소지.

### 2.4 채널 비교표

| 채널 | 자동화 | 구축 난이도 | 보안/약관 | MVP 적합 |
|------|--------|-------------|-----------|----------|
| HTS Excel 다운로드 | 수동(반복) | ★☆☆ | 안전 | ✅ 권장 |
| Champion Open API (OCX) | 완전자동 | ★★★ | 안전 (공식) | △ Phase 2 |
| 홈페이지 스크래핑 | 자동 | ★★ | ❌ 약관 위반 위험 | ❌ |
| MTS 캡처/OCR | 수동 | ★★ | 안전하나 비효율 | ❌ |

## 3. 권장 단계별 접근 (Pilot)

### Stage 1 — Excel 업로드 기반 일괄 import (MVP, 1~2 스프린트)
1. 사용자가 HTS에서 거래내역을 `.xlsx`로 저장.
2. my-portfolio-hub 내 `/import/hts` 페이지에서 파일 드래그앤드롭.
3. 브라우저에서 **SheetJS(`xlsx`)**로 파싱 → 컬럼 자동 매핑 → 미리보기 → 확정 시 `journalStore`에 적재.
4. 보유 종목은 매매내역으로부터 재계산 (또는 잔고 엑셀 별도 import).

### Stage 2 — Champion Open API 데몬 (선택, Phase 2 이상)
1. 별도 Node/Python 데몬을 Windows에서 띄워 OCX와 통신.
2. 데몬이 로컬 REST(`localhost:xxxx`)로 거래내역을 노출.
3. my-portfolio-hub가 정기 polling으로 신규 거래만 sync.
4. 사용자 인증서 로그인이 필요하므로 **백그라운드 자동화 한계** 존재.

> **결론**: Stage 1만으로도 사용자의 즉각적인 니즈(과거 데이터 일괄 적재)를 해결할 수 있다. Stage 2는 누적 사용 후 효용이 분명해질 때 도입.

## 6. 중복 방지 전략

- 모든 import 행에 대해 `externalId = sha256(date|ticker|action|quantity|price|orderNo)` 산출.
- import 시 기존 `journalStore.entries`에서 동일 `externalId` 존재 여부 확인 후 skip.
- 주문번호가 누락된 구버전 엑셀은 `date|ticker|action|quantity|price` 조합으로 fallback.
- 미리보기 단계에서 "신규/중복" 행을 색상으로 구분 표시.

---

## 7. UX 플로우

1. **/import/hts** 진입 → 안내 모달 (HTS에서 엑셀 저장하는 방법 스크린샷).
2. 파일 드롭 → 시트 자동 감지 (체결/잔고/실현손익 등 다중 시트 지원).
3. 컬럼 자동 매핑 결과 표시 + 사용자 수동 보정 가능.
4. 미리보기 테이블에서 행 단위 제외 가능, 중복 행은 기본 제외.
5. "심리 카테고리 일괄 설정" 옵션 (예: 전부 "기타"로 채운 뒤 추후 편집).
6. 적용 → `journalStore` 추가 + `portfolioStore` 보유 종목 재계산.
7. 결과 요약 (추가 N건 / 중복 M건 / 오류 K건) + 일지 페이지로 이동.

## 8. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| HTS 버전별 컬럼명 차이 | 매핑 실패 | 한글 컬럼 사전 + 사용자 수동 매핑 fallback |
| 대용량 엑셀(수천 행) | 브라우저 freeze | Web Worker로 파싱 분리 (Phase 2) |
| 매도 평균단가 계산 오류 | 손익 왜곡 | 보유 재계산 시 FIFO 가정 명시, 수동 조정 UI |
| 외화 거래 (해외주식) | 통화 혼재 | `currency` 필드 분리, 환율 미적용은 명시 |
| Excel 내 합계/공백 행 | 파싱 오류 | 정수형 검증 후 skip 로깅 |
| 종목코드 zero-pad 손실 | 매칭 실패 | 문자열로 강제 변환 후 `padStart(6,'0')` |

## 9. 법적/약관 고려

- HTS Excel 다운로드는 **본인 계좌의 본인 데이터를 본인 PC로 export**하는 행위로 약관 위반 소지 없음.
- 데이터는 **사용자 PC 로컬에서만 처리** (LocalStorage/IndexedDB), 외부 서버 전송 없음.
- 향후 Claude AI 분석에 사용할 경우 **개별 거래 식별정보(주문번호, 계좌번호)는 마스킹** 후 전송.
