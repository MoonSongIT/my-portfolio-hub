# 14.04.04 뉴스 매칭 정확도 개선 수정안

## 작성일
2026-06-16

## 배경
Phase 2·3 라이브 검증 중, AI 분석이 종목과 **무관한 뉴스**를 받는 현상이 반복 확인되었다.

- 사례: "SFA반도체(036540, KOSDAQ) 왜 움직였어?" 질의 시, 프리패치된 뉴스 5건이 모두
  **EU-우크라이나 협상 / 미군 폭격기 추락 / 미국 투자사 인사 / GM-록히드마틴 계약 / 우크라이나 모병** —
  반도체·SFA반도체와 전혀 무관한 글로벌 기사였다.
- 결과: ① 감성 점수가 전부 중립(0)으로 산출되고, ② 원인 분석이 종목을 직접 설명하지 못하고 시장 전반으로 우회했다.
- 즉 감성 엔진(P3)·분석(P5)은 정상이며, **병목은 입력 뉴스의 종목 매칭 정확도**다.

## 진단 (코드 추적)

`src/api/newsApi.js`의 `fetchNews(ticker, market)`:

```js
// L106~118 (현재)
const isKorean = market === 'KRX' || market === 'KOSDAQ'
const pureTicker = ticker.replace(/\.(KS|KQ)$/, '')
if (isKorean) {
  const [naverNews, yahooNews] = await Promise.all([
    fetchNewsNaver(pureTicker),
    fetchNewsYahoo(`${pureTicker}.KS`),   // ← 항상 .KS (KOSPI 접미사)
  ])
  result = sortByDate(dedupeByTitle([...naverNews, ...yahooNews])).slice(0, 5)
}
```

### 근본 원인

| # | 원인 | 설명 |
|---|------|------|
| RC1 | **KOSDAQ에 `.KS` 접미사 하드코딩** | KOSDAQ 종목(036540)인데 Yahoo에 `036540.KS`(KOSPI 형식)로 질의. Yahoo는 해당 심볼을 찾지 못함. 올바른 접미사는 `.KQ`. |
| RC2 | **Yahoo 무매칭 시 글로벌 뉴스 폴백** | Yahoo `/v1/finance/search`는 심볼이 매칭되지 않아도 일반/글로벌 top 뉴스를 반환. 이 무관 뉴스가 결과에 섞임. |
| RC3 | **Naver·Yahoo 무조건 병합** | Naver(종목 전용)가 좋은 뉴스를 줘도, Yahoo 폴백 junk가 항상 합쳐져 상위 5건을 오염시킴. 관련성 가드 없음. |

> RC1이 1차 트리거, RC2·RC3이 증폭. KOSDAQ뿐 아니라 Yahoo 커버리지가 약한 한국 중소형주 전반에서 재현 가능.

## 수정안

### Fix 1 — 시장별 올바른 Yahoo 접미사
- KOSPI/KRX → `.KS`, KOSDAQ → `.KQ`.

### Fix 2 — 한국 종목은 Naver 우선, Yahoo는 폴백 (핵심)
- Naver(종목 전용 엔드포인트)가 충분한 뉴스를 주면 **Yahoo를 병합하지 않는다**(글로벌 junk 차단).
- Naver가 부족할 때만(예: 3건 미만) Yahoo로 보강하되 **올바른 접미사** 사용.

```js
// 수정안 (newsApi.js fetchNews 한국 분기)
const isKorean = market === 'KRX' || market === 'KOSDAQ'
const pureTicker = ticker.replace(/\.(KS|KQ)$/, '')

if (isKorean) {
  const naverNews = await fetchNewsNaver(pureTicker)        // 1순위: 종목 전용
  if (naverNews.length >= 3) {
    result = sortByDate(dedupeByTitle(naverNews)).slice(0, 5)
  } else {
    // Naver 부족 시에만 Yahoo 보강 — 시장별 접미사 적용
    const suffix = market === 'KOSDAQ' ? '.KQ' : '.KS'
    const yahooNews = await fetchNewsYahoo(`${pureTicker}${suffix}`)
    result = sortByDate(dedupeByTitle([...naverNews, ...yahooNews])).slice(0, 5)
  }
} else {
  result = (await fetchNewsYahoo(ticker)).slice(0, 5)
}
```

장점.
- RC1 해소(접미사 정정), RC2·RC3 해소(Naver 충분 시 Yahoo 미병합).
- Naver가 충분하면 Yahoo 호출 자체를 생략 → 지연·비용도 소폭 개선.

### Fix 3 (옵션) — 약한 관련성 필터
- 한국 종목인데 제목이 전부 영문/글로벌 키워드면 1차 필터링. 다만 오탐 위험이 있어 **Fix 1·2로 충분하면 보류**.
- 더 근본적으로는 종목명(예: "SFA반도체")으로 Naver 검색을 보강하는 방안도 검토 가능(별도 작업).

## 검증 방법

| 검증 | 방법 | 기대 결과 |
|------|------|----------|
| 재현 | 수정 전 "SFA반도체 왜 움직였어?" | 무관 글로벌 뉴스 5건 |
| Fix 효과 | 수정 후 동일 질의 | SFA반도체/반도체 관련 뉴스 위주, 무관 글로벌 뉴스 제거 |

## 영향 범위 / 리스크
- 변경 파일: `src/api/newsApi.js` 단일(`fetchNews`).
- 하위 호환: 반환 형태 불변. 감성(P3)·분석(P5)·리서치 등 뉴스 소비처는 그대로.
- 리스크: Naver 종목 전용 엔드포인트가 일부 종목에서 비어 있을 수 있음 → Fix 2의 폴백이 방어. 임계값(3건)은 튜닝 가능.

  - 만약 Naver도 부실하면 → 종목명 기반 검색 보강(Fix 3 확장)을 별도 과제로 승격.
