# AI분석 오류 복구 개선 계획

_작성일: 2026-05-20_

---

## 1. 현행 오류 복구의 구체적 문제

### 1-1. 500/529 상태코드에서만 재시도 — 다른 실패 유형 무대응

`sendToAgent`의 재시도 로직은 HTTP 500과 529(과부하)에만 반응한다. 타임아웃, 네트워크 단절, 빈 응답 등 다른 실패 유형은 한 번 실패하면 바로 오류 메시지를 반환한다.

```js
// claudeApi.js L107-254 — 재시도 조건
for (let attempt = 0; attempt < 3; attempt++) {
  try {
    const response = await claudeApi.post('/claude', { systemPrompt, messages, maxTokens })
    const text = response.data?.content?.[0]?.text || '응답을 받지 못했습니다.'
    return { text, agentType, agentInfo }
  } catch (error) {
    const status = error.response?.status
    if (status === 429 || status === 401) break          // 즉시 포기
    if ((status === 500 || status === 529) && attempt < 2) {
      await new Promise((r) => setTimeout(r, 1500 * (attempt + 1)))
      continue
    }
    break  // 그 외 모든 상태코드 — 재시도 없음
  }
}
```

- 네트워크 일시 단절(`ECONNRESET`, `ETIMEDOUT`) → 재시도 없음
- API 게이트웨이 503 → 재시도 없음
- 응답은 200이지만 `content[0].text`가 빈 문자열 → "응답을 받지 못했습니다." 반환, 재시도 없음

### 1-2. sendWithHistory는 재시도 로직 자체가 없음

멀티턴 대화(`sendWithHistory`)에는 재시도가 전혀 없다. 단일 try/catch로 오류를 잡아 텍스트로 반환할 뿐이다.

```js
// claudeApi.js L263-277 — 재시도 없음
export async function sendWithHistory(messages, systemPrompt, agentType = 'journal') {
  const maxTokens = AGENT_MAX_TOKENS[agentType] || 4096
  try {
    const response = await claudeApi.post('/claude', { systemPrompt, messages, maxTokens })
    const text = response.data?.content?.[0]?.text || '응답을 받지 못했습니다.'
    return { text }
  } catch (error) {
    return { text: getErrorMessage(error) }  // 재시도 없이 오류 텍스트 반환
  }
}
```

journal coach 세션이 일시적 네트워크 문제로 실패해도 사용자는 오류 메시지를 보고 수동으로 다시 전송해야 한다.

### 1-3. 불완전 응답 감지 없음

Claude가 토큰 한도에 걸려 응답을 중간에 잘라내도 시스템이 이를 감지하지 못한다.

```js
// claudeApi.js — stop_reason 확인 없음
const text = response.data?.content?.[0]?.text || '응답을 받지 못했습니다.'
// response.data.stop_reason이 'max_tokens'여도 확인하지 않음
// → 중간에 잘린 응답이 그대로 사용자에게 전달됨
```

- "...를 기반으로 분석하면" 에서 잘린 응답이 정상 응답처럼 표시된다.
- 마크다운 테이블이 절반만 그려져 렌더링이 깨질 수 있다.

### 1-4. 환각(Hallucination) 감지 없음

AI가 존재하지 않는 종목 코드, 잘못된 수치, 허구의 공시를 응답해도 시스템이 탐지하거나 경고하지 않는다.

```js
// 현재: 응답 텍스트를 검증 없이 그대로 반환
return { text, agentType, agentInfo }
// "삼성전자 2분기 영업이익 15조원" 같은 수치를 AI가 만들어내도 탐지 불가
```

- research 에이전트가 잘못된 PER 수치를 자신 있게 제시한다.
- alert 에이전트가 실제 발생하지 않은 공시를 언급한다.

### 1-5. 오류 메시지가 기술적 용어 그대로 노출

```js
// claudeApi.js — getErrorMessage
function getErrorMessage(error) {
  const status = error.response?.status
  if (status === 429) return '요청이 너무 많습니다. 잠시 후 다시 시도해주세요.'
  if (status === 401) return 'API 키가 유효하지 않습니다.'
  // 그 외: error.message 그대로 반환 — "Network Error", "timeout of 10000ms exceeded" 등
  return error.message || 'AI 응답 중 오류가 발생했습니다.'
}
```

사용자에게 "Network Error" 또는 "ECONNRESET" 같은 기술적 메시지가 노출된다.

## 3. 개선 방향

### 옵션 A — 재시도 범위 확장 (최소 변경)

재시도 조건을 503, 타임아웃, 빈 응답까지 확장하고, `sendWithHistory`에도 동일 재시도 로직을 적용한다.

- 장점: 구현 단순, 즉시 효과
- 단점: 환각 감지·불완전 응답 문제는 해결 안 됨

### 옵션 B — 통합 재시도 + 응답 유효성 검증 (추천)

재시도 로직을 공통 함수로 추출하고, 응답 후 유효성 검증 레이어를 추가한다.

```
Claude API 호출
    │
    ▼
응답 수신
    │
    ├─ HTTP 오류 (503, 네트워크) → 재시도 (최대 3회, 지수 백오프)
    │
    ├─ stop_reason === 'max_tokens' → incomplete 플래그 설정
    │
    ├─ 빈 응답 → 재시도
    │
    └─ 정상 응답 → 환각 의심 패턴 감지 → 반환
```

- 장점: 재시도 일관성, 불완전 응답 처리, 환각 부분 감지 가능
- 단점: 구현 복잡도 증가, 환각 감지의 완전성 한계

### 옵션 C — 자기 검증 (Self-Verification) 2차 호출

응답 후 "이 응답에 근거 없는 수치나 존재하지 않는 종목이 포함되어 있는가?"를 Claude에게 재질문한다.

- 장점: 가장 정확한 환각 감지 가능
- 단점: 비용 2배, 응답 시간 증가

**추천: 옵션 B — 통합 재시도 + 응답 유효성 검증**

비용 효율과 복구 커버리지의 균형이 가장 좋다. 환각 감지는 완전한 해결이 어려우므로 의심 패턴에 경고 배지를 표시하는 수준으로 제한한다.

## 4. 항목별 개선 상세

### 4-1. 공통 재시도 함수 — callClaudeWithRetry

```js
// src/api/claudeApi.js 수정
function isRetryable(error) {
  const status = error.response?.status
  if (!status) return true             // 네트워크 오류 (ECONNRESET, ETIMEDOUT 등)
  return [500, 503, 529].includes(status)
}

async function callClaudeWithRetry(payload, maxAttempts = 3) {
  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    try {
      const response = await claudeApi.post('/claude', payload)
      const content = response.data?.content?.[0]
      const text = content?.text?.trim() || ''

      // 빈 응답 재시도
      if (!text && attempt < maxAttempts - 1) {
        await delay(1000 * (attempt + 1))
        continue
      }

      const incomplete = response.data?.stop_reason === 'max_tokens'
      return { text, incomplete }
    } catch (error) {
      const status = error.response?.status
      if (status === 429 || status === 401) break  // 재시도 불가
      if (isRetryable(error) && attempt < maxAttempts - 1) {
        await delay(1500 * (attempt + 1))
        continue
      }
      break
    }
  }
  return { text: '', incomplete: false, failed: true }
}

const delay = (ms) => new Promise(r => setTimeout(r, ms))
```

### 4-2. sendWithHistory에 재시도 적용

```js
// claudeApi.js — sendWithHistory 수정
export async function sendWithHistory(messages, systemPrompt, agentType = 'journal') {
  const maxTokens = AGENT_MAX_TOKENS[agentType] || 4096
  const result = await callClaudeWithRetry({ systemPrompt, messages, maxTokens })
  if (result.failed || !result.text) {
    return { text: getErrorMessage({ response: { status: 0 } }) }
  }
  return { text: result.text }
}
```

### 4-4. 환각 의심 패턴 감지 — hallucinationGuard

완전한 환각 감지는 불가능하지만, 자주 발생하는 의심 패턴을 정규식으로 탐지해 경고 배지를 표시한다.

```js
// src/utils/hallucinationGuard.js 신규
const SUSPICIOUS_PATTERNS = [
  /\d{4}년 \d{1,2}월 \d{1,2}일 공시/,       // 날짜 + 공시 (허구 공시 위험)
  /영업이익\s[\d,]+조\s?원/,                 // 대규모 수치 (잘못된 단위 위험)
  /목표주가\s[\d,]+원.*(\d+)%\s?상승/,       // 목표주가 + 상승률 (환각 위험)
]

export function checkHallucinationRisk(text) {
  return SUSPICIOUS_PATTERNS.some(p => p.test(text))
}
```

```jsx
// MessageBubble.jsx — 환각 경고 배지
import { checkHallucinationRisk } from '../../utils/hallucinationGuard'

function MessageBubble({ message }) {
  const isRisky = message.agentType !== 'journal' && checkHallucinationRisk(message.content)
  return (
    <div>
      {isRisky && (
        <p className="text-xs text-red-400 mb-1">
          ⚠️ 수치·날짜를 원본 출처에서 직접 확인하세요.
        </p>
      )}
      <MarkdownRenderer content={message.content} />
    </div>
  )
}
```

## 8. 고려 사항

- **재시도 지수 백오프**: 1.5초 → 3초 → 4.5초. 총 대기 시간 최대 9초. 429(Rate Limit)는 재시도하지 않는다. Anthropic이 재시도 간격을 클라이언트가 임의로 결정하지 말 것을 권고하기 때문이다.
- **환각 감지 한계**: 정규식 패턴은 알려진 유형만 탐지한다. 각 에이전트 프롬프트에 이미 면책 문구가 포함되어 있으므로, 경고 배지는 추가적인 안내 역할을 한다.
- **sendWithHistory와 세션 압축**: `summarizeAndCompressHistory()`가 20메시지 초과 시 실행된다. 압축 요청 자체도 Claude 호출이므로 동일한 `callClaudeWithRetry` 로직을 적용한다.
- **완전한 환각 방지**: 실시간 가격·공시 데이터를 Claude 응답과 교차 검증하는 팩트체킹 레이어는 10.10.03(데이터 신선도)과 연계해 별도 기획한다.
- **불완전 응답 자동 연속**: 현재는 사용자에게 수동 요청을 안내한다. 향후 `incomplete: true` 시 자동으로 "계속해주세요"를 전송하는 자동 연속 호출을 추가할 수 있다.
